## 项目目标

Auto Collection 用于小范围 Android 手机运行农业内容采集脚本，并把设备运行状态、采集记录、心跳、日志和控制指令集中到后台监控。当前阶段目标不是完整内容生产平台，而是先解决手机脚本运行不可见、异常难排查、日志难归档的问题。

## 业务价值

1. 让负责人能通过公网后台查看测试手机是否在线、是否暂停、是否持续上报心跳。
2. 让脚本采集到的候选农业内容、热门评论和运行日志可追踪。
3. 让 APK 试运行过程中的权限、版本、设备认证和异常退出问题有可复查证据。
4. 降低反复连接手机、人工翻日志和手动判断脚本状态的成本。

## 当前成果

1. 手机端 AutoX.js 脚本可打包为 APK，提供启动、停止、守护、权限检查等入口。
2. 后台 API 接收设备注册、心跳、运行日志、完整日志文件和采集记录。
3. 后台 Web 提供设备、采集记录、日志和任务配置页面。
4. 生产环境已通过 Docker Compose 部署到 `106.54.41.106:18080`。
5. 设备认证逻辑已改为令牌注册模式，普通上报接口不再自动创建设备。

## 当前不做

1. 不接入平台官方 API。
2. 不绕过验证码、登录校验或平台风控。
3. 不做自动点赞、评论、关注、私信等互动功能。
4. 不采集非公开内容。
5. 不承诺平台标签、推荐或账号权重结果，只记录脚本实际运行证据。

## 技术结构

| 模块 | 技术 | 说明 |
|---|---|---|
| 手机端 | AutoX.js / JavaScript | Android 自动化脚本与 APK 包装 |
| 后台 API | Bun + Hono | 接收移动端上报和后台管理请求 |
| 后台 Web | React 19 + Vite + Ant Design | 管理后台页面 |
| 数据库 | PostgreSQL + Drizzle ORM | 设备、任务、日志、心跳、采集记录 |
| 缓存 | Redis | 预留后台运行依赖 |
| 部署 | Docker Compose | 生产环境 API、Web、Postgres、Redis |

## 成功指标

1. 负责人能打开线上后台查看设备、日志和采集记录。
2. 新版 APK 能使用唯一设备 ID 注册，不再共用 `android_001`。
3. 未注册设备访问移动端普通接口时返回 401，不写入脏数据。
4. 默认 `android_001` 旧脚本注册返回 `DEVICE_ID_NOT_UNIQUE`，不写入设备表。
5. 清理生产库后，设备、日志、心跳、采集记录等运行数据表可复查为 0。
