# 群控脚本需求合规改写与 Demo 方案

## 1. 文档目标

本文把外部《群控脚本系统需求文档》改写成一个可落地的内部 Demo 方案。

原文中的“刷视频养号、自动评论、自动关注、自动私信、直播间批量互动、反检测策略”等内容不进入 Demo。Demo 只做运营辅助、设备管理、任务配置、公开内容采集、日志监控和人工确认工作流。

目标不是复制一套自动营销脚本，而是先做出一个可演示、可扩展、可审计的“手机 Agent + 后台控制台”系统。

## 2. 核心结论

1. 可以做的部分：
   - 设备接入、心跳、在线状态。
   - 手机端任务启动、暂停、停止。
   - 后台下发任务配置。
   - 手机端采集公开页面上的可见文本、截图、评论摘要。
   - 后台展示采集记录、运行日志、异常原因。
   - 素材/线索/候选内容的人工审核。
   - 需要互动时生成“待办动作”，由用户人工确认后处理。

2. 不进入 Demo 的部分：
   - 自动点赞、自动评论、自动关注、自动私信。
   - 自动养号、模拟真人行为、规避平台检测。
   - 多账号错峰执行策略、风控绕过策略。
   - 直播间自动刷屏、自动响应主播或目标账号消息。
   - 自动添加微信好友、微信群批量加人。

3. Demo 的正确定位：
   - 后台是任务、设备、内容、日志的管理端。
   - 手机 App 是一个轻量 Agent，有几个按钮：检查权限、启动任务、停止任务、上传日志、查看状态。
   - 手机 Agent 可以辅助采集和展示建议，但不能替用户自动执行平台互动行为。

## 3. 产品名称建议

建议 Demo 暂定名：

```text
Agri Ops Assistant
农业新媒体运营辅助系统
```

名称上避免使用“群控、养号、自动获客、反检测”等词，后续对外演示和代码命名都更稳。

## 4. Demo 范围

### 4.1 第一阶段必须做

| 模块 | Demo 能力 | 说明 |
|---|---|---|
| 设备管理 | 手机注册、心跳、在线状态 | 后台能看到每台手机是否在线 |
| 任务配置 | 创建采集任务、下发关键词 | 手机启动时拉取当前任务 |
| 手机 Agent | 权限检查、启动、停止、上传日志 | App 首页就是几个按钮 |
| 内容采集 | 采集公开页面可见文本和截图 | 只采集用户能看见的公开信息 |
| 记录中心 | 展示采集内容、关键词命中、截图 | 供人工筛选 |
| 日志中心 | 展示运行日志、异常、停止原因 | 方便排查手机端问题 |
| 人工待办 | 生成建议动作，不自动执行 | 比如“建议查看此作者主页” |

### 4.2 第一阶段不做

| 原需求 | Demo 替代方案 |
|---|---|
| 刷视频养号 | 改成“公开内容浏览采集任务” |
| 自动点赞/评论/关注/私信 | 改成“生成待办，人工确认” |
| 直播间自动互动 | 改成“直播间公开评论观察记录” |
| 微信附近的人自动加人 | 不做 |
| 微信群自动加人 | 不做 |
| 反检测/行为随机化 | 不做 |

## 5. 页面设计

### 5.1 后台页面结构

```text
控制台
├── 总览看板
├── 设备管理
├── 任务配置
├── 采集记录
├── 人工待办
├── 运行日志
└── 系统设置
```

### 5.2 总览看板

用途：让你一眼知道系统有没有跑起来。

字段：

| 区域 | 内容 |
|---|---|
| 指标卡 | 在线设备数、运行中设备数、今日采集数、异常数 |
| 设备状态表 | 设备编号、设备名称、状态、当前任务、最后心跳 |
| 最近日志 | 时间、设备、级别、消息、停止原因 |
| 最近采集 | 平台、关键词、标题文本、命中词、采集时间 |

### 5.3 设备管理

用途：管理每台手机。

字段：

| 字段 | 说明 |
|---|---|
| 设备编号 | 手机端配置的唯一 ID |
| 设备名称 | 后台可编辑名称 |
| 平台 | douyin、xhs、kuaishou 等，Demo 先只做 douyin |
| 状态 | offline、online、running、paused、error |
| App 版本 | 手机 Agent 版本 |
| 最后心跳 | 最近一次上报时间 |
| 当前任务 | 正在执行的任务 |

按钮：

| 按钮 | 行为 |
|---|---|
| 查看详情 | 查看该设备日志、心跳、采集记录 |
| 标记停用 | 后台不再给这台设备下发任务 |
| 复制设备 Token | 给手机端配置使用 |

### 5.4 任务配置

用途：配置手机端要采集什么。

字段：

| 字段 | 示例 | 说明 |
|---|---|---|
| 任务名称 | 农业病虫害内容观察 | 后台展示用 |
| 平台 | douyin | Demo 先固定 douyin |
| 入口模式 | search/feed | 搜索流或推荐流 |
| 搜索关键词 | 水稻病虫害、玉米高产 | 用于找到相关公开内容 |
| 命中关键词 | 水稻、玉米、农药、病虫害 | 用于判断是否保存 |
| 最大浏览数 | 100 | Demo 限制采集规模 |
| 最大采集数 | 30 | 达到后停止 |
| 是否采集评论摘要 | true/false | 只采集可见热门评论 |
| 状态 | draft/enabled/disabled | 是否下发给手机 |

### 5.5 采集记录

用途：查看手机端采集到的候选内容。

列表字段：

| 字段 | 说明 |
|---|---|
| 采集时间 | 手机端上报时间 |
| 设备 | 来源设备 |
| 平台 | 来源平台 |
| 关键词 | 当前搜索词 |
| 命中词 | 命中的业务关键词 |
| 标题文本 | OCR 或控件提取的标题 |
| 指标文本 | 可见点赞、评论、收藏等文本 |
| 评论摘要 | 可见热门评论摘要 |
| 状态 | pending、reviewed、ignored、converted |

详情内容：

| 区域 | 内容 |
|---|---|
| 原始截图 | 手机端采集截图 |
| 屏幕文本 | OCR 或控件文本 |
| 评论摘要 | 可见评论列表 |
| 原始 payload | 手机端完整 JSON |
| 人工备注 | 运营人员填写 |

### 5.6 人工待办

用途：把“自动互动”改成“人工确认动作”。

待办类型：

| 类型 | 来源 | 处理方式 |
|---|---|---|
| 查看作者主页 | 采集记录命中高价值关键词 | 人工点击处理 |
| 标记潜在线索 | 评论中出现需求词 | 人工判断 |
| 加入素材库 | 内容适合作为选题参考 | 人工确认 |
| 忽略 | 低价值内容 | 人工关闭 |

注意：待办只记录建议，不自动去平台执行点赞、评论、关注、私信。

### 5.7 运行日志

用途：排查手机端是否卡住、权限是否缺失、任务是否正常结束。

字段：

| 字段 | 说明 |
|---|---|
| 时间 | 日志时间 |
| 设备 | 来源设备 |
| 任务 | 关联任务 |
| 级别 | INFO、WARN、ERROR |
| 消息 | 简短描述 |
| 上下文 | JSON |
| 停止原因 | manual_stop、task_finished、permission_missing、risk_control、app_not_found |

## 6. 手机 App 设计

### 6.1 首页布局

手机 App 不需要复杂页面，第一版只做一个控制面板。

```text
农业运营助手

设备：MI8-03
状态：未运行 / 运行中 / 已暂停 / 异常
当前任务：农业病虫害内容观察
最后心跳：2026-06-11 18:30

[检查权限]
[打开无障碍设置]
[打开悬浮窗设置]

[启动任务]
[停止任务]
[上传日志]
[刷新状态]

最近日志：
- 18:30 拉取任务成功
- 18:31 任务启动
- 18:33 命中关键词：水稻
```

### 6.2 按钮行为

| 按钮 | 行为 |
|---|---|
| 检查权限 | 检查无障碍、悬浮窗、截图、网络 |
| 打开无障碍设置 | 跳转系统无障碍页面 |
| 打开悬浮窗设置 | 跳转系统悬浮窗权限页面 |
| 启动任务 | 拉取任务配置并进入采集状态机 |
| 停止任务 | 停止当前任务并上报状态 |
| 上传日志 | 手动补传本地日志 |
| 刷新状态 | 重新读取本地状态和后台任务 |

### 6.3 手机端状态机

```text
INIT
  -> CHECK_PERMISSION
  -> FETCH_TASK
  -> OPEN_PLATFORM
  -> ENTER_FLOW
  -> READ_SCREEN
  -> EVALUATE_CONTENT
  -> CAPTURE_RECORD
  -> UPLOAD_RECORD
  -> NEXT_ITEM
  -> STOPPED
```

异常状态：

| 状态 | 处理 |
|---|---|
| PERMISSION_MISSING | 停止任务，提示用户打开权限 |
| APP_NOT_FOUND | 停止任务，提示安装目标 App |
| LOGIN_REQUIRED | 停止任务，等待人工登录 |
| RISK_CONTROL | 停止任务，只上报异常，不尝试绕过 |
| NETWORK_ERROR | 本地缓存，稍后补传 |

## 8. 接口设计

### 8.1 手机端接口

```http
GET /api/v1/mobile/tasks/current?deviceCode=MI8-03&platform=douyin
```

返回当前启用任务。

```http
POST /api/v1/mobile/heartbeats
```

上报设备心跳。

```http
POST /api/v1/mobile/collection-records
```

上报采集记录。

```http
POST /api/v1/mobile/runtime-logs
```

上报运行日志。

### 8.2 后台管理接口

```http
GET /api/v1/admin/dashboard/summary
GET /api/v1/admin/devices
GET /api/v1/admin/devices/:id
GET /api/v1/admin/tasks
POST /api/v1/admin/tasks
PATCH /api/v1/admin/tasks/:id
GET /api/v1/admin/collection-records
PATCH /api/v1/admin/collection-records/:id/review
GET /api/v1/admin/review-todos
PATCH /api/v1/admin/review-todos/:id
GET /api/v1/admin/runtime-logs
```

## 9. Demo 开发顺序

### 9.1 后台优先

1. 建表：设备、任务、采集记录、心跳、日志、人工待办。
2. 写手机端接口：当前任务、心跳、采集记录、日志。
3. 写后台页面：总览、设备、任务、采集记录、日志。
4. 用 Postman 或脚本模拟手机上报，先把后台跑通。

### 9.2 手机 Agent 第二步

1. 做手机 App 首页。
2. 做权限检查按钮。
3. 做启动、停止、刷新状态。
4. 做拉取任务配置。
5. 做本地日志和心跳上报。
6. 再接入公开页面文本采集。

### 9.3 最后做人工待办

1. 后台根据命中关键词生成待办。
2. 用户在后台人工标记处理结果。
3. 采集记录和待办结果关联。

## 10. Demo 验收标准

1. 后台能新增一个启用状态的采集任务。
2. 手机 App 能显示设备编号、当前状态、当前任务。
3. 手机 App 点击启动后能拉取任务配置。
4. 手机 App 每隔固定时间上报心跳。
5. 手机 App 能上报一条模拟采集记录。
6. 后台采集记录列表能看到这条记录。
7. 后台日志中心能看到手机端日志。
8. 后台能把一条采集记录标记为“待处理、已处理、忽略”。
9. 手机端遇到权限缺失时停止任务并上报异常。
10. 整个 Demo 不包含自动点赞、评论、关注、私信、加好友、反检测逻辑。

## 11. 你自己写 Demo 时的文件拆分建议

如果沿用当前项目结构，建议按下面拆：

```text
apps/
  admin-web/              后台 React 页面
  api-server/             Hono 后端接口
mobile-agent/
  autojs/
    launcher.js           手机 App 首页按钮
    main.js               任务状态机入口
    config.js             本地兜底配置
    api.js                后台接口封装
    logger.js             日志封装
    permissions.js        权限检查
    collector.js          公开页面采集逻辑
    storage.js            本地缓存
docs/
  requirements/           当前有效需求和设计
  project-records/        外部资料分析和阶段记录
```

第一版最小闭环只需要写：

```text
api-server:
  devices
  tasks
  heartbeats
  collection-records
  runtime-logs

admin-web:
  dashboard
  devices
  tasks
  collection-records
  runtime-logs

mobile-agent:
  launcher.js
  api.js
  logger.js
  main.js
```

## 12. 和原需求的映射关系

| 原需求模块 | Demo 中保留什么 | Demo 中删除什么 |
|---|---|---|
| M1 刷视频养号 | 公开内容采集、关键词命中、运行日志 | 养号目标、模拟真人、互动概率 |
| M2 养号发布 | 素材/采集记录可进入人工审核 | 自动发布、多账号差异化发布 |
| M3 直播间互动 | 直播间公开评论观察记录 | 自动发言、自动响应、批量互动 |
| 风控约束 | 异常停止、人工处理、日志审计 | 规避检测、行为随机化、反风控 |

## 13. 一句话开发原则

后台负责管理和审计，手机端负责采集和上报，所有平台互动动作都变成人工确认，不写自动执行。
