# Agent 心跳任务分离与设备令牌方案

## 1. 本次调整目标

手机脚本启动后不应直接等用户点击悬浮窗开始，也不应把“脚本是否运行”和“采集任务是否执行”混在一起。

调整后的模型：

1. Agent 常驻模块：负责启动心跳、拉后台参数、拉控制命令、注册设备 token。
2. 任务执行模块：只在后台启动命令或 `autoStart=true` 时执行视频/直播采集。
3. 停止任务只停止采集，不退出 Agent。Agent 继续发送心跳和拉取命令。

## 2. 启动流程

1. AutoX.js 定时任务启动 `main.js`。
2. `main.js` 创建悬浮窗。
3. 立即注册或校验设备 token。
4. 立即上报 Agent 启动日志。
5. 拉取 `/mobile/tasks/current` 后台配置。
6. 立即上报 idle 心跳。
7. 如果后台配置 `autoStart=true`，自动进入任务执行。
8. 如果 `autoStart=false`，显示“未执行任务”，等待后台启动命令。

## 3. 后台字段语义

设备页字段调整：

| 字段 | 语义 |
|---|---|
| 当前状态 | Agent 当前状态，如 idle/running/offline |
| 当前任务 | 只有 `视频`、`直播`、`未执行任务` 三种展示 |
| 最后心跳 | 只显示心跳时间，不再显示“多少分钟前” |
| 最近 IP | 最近一次请求来源 IP，只做辅助排查 |

## 4. token 方案

不采用“IP + 设备码 + 运行时间加密”作为身份 token。

原因：

1. IP 会变化，全国分布手机更不稳定。
2. 设备码可以被伪造。
3. 运行时间不是密钥，不能证明设备身份。
4. 这种 hash 只能当指纹，不能当鉴权凭据。

当前采用：

1. 手机首次启动时生成 64 位随机 hex token。
2. token 保存在 AutoX.js 本地 storage。
3. 手机调用 `/mobile/device-token/register` 申请绑定。
4. 后台如果设备未绑定 token，则写入该 token。
5. 后台如果已有 token，必须与手机上报 token 一致，否则返回冲突或鉴权失败。
6. 后台不再提供“生成 token / 清除 token”作为常规控制按钮。

后续安全升级方向：

1. 后台增加设备注册审核状态。
2. token 只保存 hash，不保存明文。
3. 请求增加 timestamp、nonce、HMAC 签名，防重放。
4. 公网入口增加 HTTPS、限流、IP 风控和失败次数封禁。
