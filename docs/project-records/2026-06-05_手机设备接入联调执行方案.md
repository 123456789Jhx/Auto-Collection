# 手机设备接入联调执行方案

更新时间：2026-06-05

## 1. 背景与来源

当前后台已经具备设备列表、设备级脚本参数、采集记录按设备筛选、运行日志按设备筛选、设备 token 基础鉴权和远程控制命令。

本方案用于指导把新版 `mobile-agent/autojs` 同步到手机后，完成一台或多台手机的正式接入联调。它是执行清单，不替代需求设计文档。

## 2. 核心结论

1. 每台手机必须有唯一 `deviceId`。
2. 每台手机建议配置独立 `deviceToken`。
3. 后台设备页负责设备识别、参数配置、远程控制和状态监测。
4. 手机脚本启动后应保持常驻 Agent，不因任务结束而退出。
5. 视频默认随机执行 `120-180` 分钟，直播默认随机执行 `60-120` 分钟，可在后台按设备单独调整。
6. 采集记录、运行日志和命令状态都必须能按设备过滤查看。

## 3. 变更范围

本次联调涉及：

| 模块 | 路径/页面 | 用途 |
|---|---|---|
| 手机脚本 | `mobile-agent/autojs` | 同步到手机运行 |
| 手机配置 | `mobile-agent/autojs/config.js` | 设置 `deviceId`、`deviceToken`、后台地址 |
| 后台设备页 | `/devices` | 设备信息、token、脚本参数、控制命令 |
| 采集记录页 | `/records` | 按设备查看候选内容 |
| 日志页 | `/logs` | 按设备查看运行日志 |
| API | `http://106.54.41.106:13010/api/v1` | 手机公网访问入口 |

## 4. 不变范围

1. 不改变视频阶段和直播阶段的主流程。
2. 不把停止任务等同于退出 Agent。
3. 不在本阶段实现真正远程脚本替换、备份和回滚。
4. 不依赖 IP 作为设备唯一身份，IP 只用于辅助判断设备大致来源。
5. 不把外部公网端口暴露视为安全方案，token 只是第一层鉴权。

## 5. 前置条件

| 检查项 | 标准 |
|---|---|
| 本机 API | `http://127.0.0.1:3010/health` 返回 `ok` |
| 本机 Web | `http://127.0.0.1:3020` 可打开 |
| frpc | 本机 frpc 运行，转发 `127.0.0.1:3010` 到公网 `106.54.41.106:13010` |
| 公网 API | `http://106.54.41.106:13010/health` 返回 `ok` |
| 数据库 | 已有 `device_task_configs` 表和 `collector_devices` 设备安全字段 |
| 手机权限 | AutoX.js 无障碍、悬浮窗、截图权限可用 |

## 6. 单台手机接入步骤

### 6.1 确认设备编号

为每台手机设置唯一编号：

| 手机 | 建议编号 |
|---|---|
| 第一台测试机 | `android_001` |
| 广东一号机 | `phone_gd_001` |
| 山东一号机 | `phone_sd_001` |

编号写入手机脚本：

```js
device: {
  deviceId: "android_001",
  deviceToken: ""
}
```

### 6.2 后台生成 token

在后台设备页操作：

1. 找到对应设备。
2. 点击 `更多`。
3. 点击 `生成 token`。
4. 保存弹窗里显示的 token。

注意：token 明文只显示一次。若丢失，需要重新生成并重新写入手机脚本。

### 6.3 写入手机配置

在手机脚本 `config.js` 中写入：

```js
device: {
  deviceId: "android_001",
  deviceToken: "后台生成的token"
}
```

确认后台地址：

```js
upload: {
  baseUrl: "http://106.54.41.106:13010/api/v1",
  url: "http://106.54.41.106:13010/api/v1/mobile/collection-records"
}
```

### 6.4 同步脚本到手机

将整个目录同步到手机：

```text
mobile-agent/autojs
```

手机端目录保持：

```text
/storage/emulated/0/安卓群控/autojs
```

必须包含：

| 文件/目录 | 用途 |
|---|---|
| `main.js` | 手机入口 |
| `main.module.js` | 模块装配 |
| `config.js` | 设备与任务配置 |
| `app/` | Agent、阶段、心跳、控制轮询 |
| `core/` | 上传、日志、OCR、存储 |
| `domain/` | 匹配、直播评分、风险判断 |
| `platforms/` | 抖音适配 |
| `utils/` | AutoX.js 工具 |

### 6.5 启动 Agent

在 AutoX.js 中运行 `main.js`。

启动后手机悬浮窗应显示：

```text
等待开始
```

后台设备页应看到：

| 字段 | 预期 |
|---|---|
| 当前状态 | 在线或待命 |
| 最近上报 | idle |
| 鉴权 | 已设 |
| 最近 IP | 手机公网出口 IP |
| 本机版本 | `0.1.0` |

## 7. 配置刷新验证

### 7.1 后台修改设备级参数

在设备页点击 `脚本参数`，配置：

| 参数 | 默认值 | 验证值示例 |
|---|---:|---:|
| 视频随机下限 | 120 | 120 |
| 视频随机上限 | 180 | 125 |
| 直播随机下限 | 60 | 60 |
| 直播随机上限 | 120 | 65 |
| 心跳间隔 | 1 或后台默认值 | 1 |
| 评论采集数量 | 10 | 10 |

保存后点击 `更多 -> 刷新配置`。

### 7.2 手机日志验证

手机本地日志应出现：

```text
拉取当前任务配置完成
后台配置已应用到当前脚本
```

启动新任务时应出现类似：

```text
今日随机采集时长 {"videoMinutes":123,"liveMinutes":62}
```

验收标准：

1. 视频分钟数在设备配置的视频区间内。
2. 直播分钟数在设备配置的直播区间内。
3. 后台命令回执显示完成。

## 8. 采集与日志验证

### 8.1 视频阶段验证

点击后台 `启动` 或手机悬浮窗开始。

预期日志：

```text
启动流程：打开抖音
启动流程：已进入搜索视频
开始采集阶段 {"sceneType":"video"}
快速文本识别完成
候选记录上传完成
采集心跳
```

后台采集记录页验证：

1. 设备下拉选择当前设备。
2. 阶段选择 `视频`。
3. 应能看到该设备上传的采集记录。

### 8.2 直播阶段验证

视频阶段结束后进入直播阶段。

预期日志：

```text
直播阶段启动前恢复页面上下文
进入直播采集阶段
直播候选扫描完成
```

如果没有直播入口，日志应出现：

```text
no_live_entry
```

如果进入直播间，日志应出现：

```text
准备进入直播间
已进入直播间，开始停留
直播间采集完成，准备退出
```

验收标准：

1. 不能把普通农业视频误判为直播间。
2. 有明确直播入口时才尝试进入。
3. 直播阶段结束后任务回到待命。

### 8.3 日志页验证

后台日志页：

1. 选择当前设备。
2. 选择日志级别。
3. 搜索关键字，例如 `后台配置已应用`、`采集阶段结束`、`风险`。

验收标准：

1. 日志按设备过滤准确。
2. 空数据时不误判为页面损坏。

## 9. token 鉴权验证

### 9.1 正常 token

手机写入正确 token 后：

| 接口 | 预期 |
|---|---|
| `/mobile/heartbeats` | 200 |
| `/mobile/commands` | 200 |
| `/mobile/collection-records` | 200 |

### 9.2 错误 token

将手机 token 临时改错，重启脚本。

预期：

| 行为 | 预期 |
|---|---|
| 心跳上报 | 401 |
| 命令拉取 | 401 |
| 后台设备状态 | 不再更新心跳 |

验证完成后必须改回正确 token。

### 9.3 清除 token

后台点击 `清除 token` 后：

1. 设备鉴权列显示 `未设`。
2. 旧手机即使不带 token 也能上报。

该模式只用于临时调试，不建议正式部署长期使用。

## 10. 异常处理

| 现象 | 判断 | 处理 |
|---|---|---|
| 后台设备离线 | 手机没上报心跳或公网 API 不通 | 检查手机网络、API、frpc、公网端口 |
| 手机日志出现 `Failed to connect` | 公网链路不可达 | 检查本机 API、frpc、云服务器端口 |
| 手机日志出现 `DEVICE_UNAUTHORIZED` | token 不匹配 | 后台重新生成 token 并写入手机 |
| 手机频繁回首页 | 抖音上下文恢复触发 | 查看是否仍出现 `重启任务上下文`，必要时继续收窄页面判断 |
| 直播阶段 0 进入 | 没识别到直播入口 | 查看日志是否为 `no_live_entry`，确认当前流里是否有直播入口 |
| 采集记录中文乱码 | 存量编码问题或手机上报编码问题 | 新记录单独验证，必要时修 AutoX.js HTTP 编码 |

## 11. 多手机接入规则

每台手机一组独立配置：

| 手机 | deviceId | deviceToken | 后台设备名称 | 部署区域 |
|---|---|---|---|---|
| 测试机 1 | `android_001` | 后台生成 | 测试一号机 | 本地 |
| 广东机 1 | `phone_gd_001` | 后台生成 | 广东一号机 | 广东 |
| 山东机 1 | `phone_sd_001` | 后台生成 | 山东一号机 | 山东 |

禁止多个手机共用同一个 `deviceId`。如果共用，后台会把多台手机的心跳、采集记录和日志混在一起。

## 12. 当前暂不处理内容

1. 真正远程脚本更新：下载、校验、备份、替换、回滚。
2. HTTPS 域名和反向代理限流。
3. GPS 定位上报。
4. 自动生成手机安装包或一键同步脚本。
5. 命令历史详情页。

## 13. 后续落地顺序

1. 按本方案完成 `android_001` 单机联调。
2. 再接入第二台手机，验证设备隔离。
3. 开启设备 token 强鉴权。
4. 增加部署层安全：HTTPS、反向代理、限流、安全组收敛。
5. 实现远程脚本更新闭环。

## 14. 验收标准

| 验收项 | 标准 |
|---|---|
| 设备识别 | 后台能区分每台手机 |
| token 鉴权 | 正确 token 放行，错误 token 拒绝 |
| 配置刷新 | 后台设备级参数能被手机应用 |
| 视频采集 | 采集记录按设备归类 |
| 日志查看 | 日志按设备过滤 |
| 常驻 Agent | 任务结束后回到待命，后台仍能看到心跳 |
| 异常恢复 | 不再频繁无意义回首页重开抖音 |
