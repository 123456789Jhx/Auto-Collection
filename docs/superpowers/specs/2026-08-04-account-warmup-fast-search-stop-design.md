# 养号快速搜索与停止任务设计

## 目标

本节点解决“目标直播间互动养号”真机测试中的两个问题：

1. 抖音已打开后，进入搜索、输入目标关键词并确认结果耗时约 90 秒。
2. 当前批次缺少语义清晰、可立即操作的“停止任务”控件。

成功标准：搜索阶段在正常抖音首页上于 8～15 秒内完成；停止按钮无需确认即可停止当前批次全部设备，前端立即展示“停止中”，手机在最近动作边界 ACK `STOPPED` 后返回燎原星火。

## 范围

### 包含

- 新增养号专用快速搜索模块，不修改通用抖音 `openSearch()`。
- 搜索入口使用短周期 `findOnce`，坐标点击只作兜底。
- 输入关键词后提交搜索，并校验搜索框或结果页包含目标关键词。
- 记录搜索入口、输入、提交、结果确认四段耗时。
- 将批次级“全部停止”改为“停止任务”。
- 点击后立即把活动设备显示为“停止中”，并阻止重复点击。
- 先完成 STOP ACK，再切回燎原星火。
- 保留单设备停止操作。

### 不包含

- 不修改直播间标题 OCR 判定规则。
- 不修改直播列表滑动距离、速度和候选数量。
- 不增加点赞、评论、观看计时等后续动作。
- 不修改发布、采集等其他业务的搜索流程。

## 手机端设计

新增独立业务脚本 `features/account-warmup/fast-target-search.js`。注册表在 Agent 启动阶段预加载该模块，并将其注入目标直播间任务，避免执行线程首次加载模块。

快速搜索按以下顺序执行：

1. 确认抖音在前台；否则返回明确失败。
2. 在限定时间内用 `findOnce` 查找顶部搜索入口。
3. 未找到节点时，使用按屏幕比例计算的顶部搜索坐标。
4. 找到输入框后清空并输入目标关键词。
5. 优先点击“搜索”提交按钮，找不到时使用回车键提交。
6. 在限定时间内校验搜索结果页和目标关键词。

所有轮询都有固定截止时间，不调用宽泛的整页文本扫描作为前置条件。失败返回阶段化错误码，交由现有候选恢复流程处理。

停止仍复用 `ACCOUNT_WARMUP_STOP`。桥接器收到停止命令后设置当前任务的停止标记；业务脚本在打开抖音、搜索完成、切换直播栏、滑动和 OCR 前后检查该标记。任务返回 `STOPPED` 后，桥接器先 ACK 运行命令，再启动燎原星火界面。

## 前端设计

表单操作区保留“开始查找”，将批次按钮改为危险样式的“停止任务”。按钮只在当前批次存在非终态任务时可用。

点击后立即记录本批次活动命令为停止中，状态表显示“停止中”；STOP 下发成功后继续轮询服务端结果，下发失败则恢复原状态并显示错误。单设备停止按钮沿用相同状态逻辑。

## 错误处理

- 搜索入口、输入框、提交按钮或结果页超时均返回具体阶段错误。
- STOP 部分设备下发失败时保留成功设备的停止中状态，并提示成功/失败数量。
- ACK 失败继续沿用现有终态重试机制，不重复执行养号动作。
- 返回燎原星火失败只记录警告，不改变已经成功的 STOP ACK。

## 验证

- 单元测试覆盖快速搜索节点路径、坐标兜底、提交兜底、结果超时和停止检查。
- 前端测试覆盖“停止任务”文案、立即停止中状态、重复点击禁用和单设备停止。
- AutoJS 回归确认执行线程不加载养号模块。
- 真机日志必须包含四段搜索耗时，并验证搜索总耗时达到 8～15 秒目标。
- 真机停止验证必须显示 STOP ACK 先于返回燎原星火。
