# 养号共享词库与离线 OCR 修复设计

## 目标

1. 直播间相关名词和评论词库支持后端共享的历史选项。
2. 历史词永久保留，只有管理员主动删除时才移除。
3. 表单仍允许手动输入新词；至少一个养号任务命令发布成功后，自动收录本次使用的新词。
4. 修复 APK 已内置中文离线 OCR、但业务适配器调用了错误方法名而无法识别的问题。
5. 最终 APK 由用户执行打包和覆盖安装。

## 非目标

- 不引入云端 OCR 服务、API Key 或外部 OCR 网络依赖。
- 不改变养号搜索、点赞、评论、单直播时长和总时长规则。
- 不从历史任务反向推导或自动导入旧词。
- 不因词库保存失败撤销已经成功发布的手机命令。

## 当前问题

前端的 `relatedTerms` 和 `commentLibrary` 已使用 Ant Design `Select mode="tags"`，可以临时输入标签，但没有选项源，也不会保存历史值。

手机 OCR 适配器依次探测 `ocr.recognize()`、`paddle.ocr()` 和 `$ocr.recognize()`。当前 AutoJs6 实际提供 `ocr.recognizeText()`，并已经依赖中文 ML Kit 文本识别模型。因此 APK 日志错误地报告“当前运行环境未发现可用 OCR API”，直播间稳定区域始终得到空文本，任务无法进入点赞和评论阶段。

## 共享词库数据模型

新增 `account_warmup_vocabulary_entries` 表：

| 字段 | 说明 |
| --- | --- |
| `id` | UUID 主键 |
| `tenant_id` | 租户隔离键 |
| `kind` | `RELATED_TERM` 或 `COMMENT` |
| `value` | 展示和下发使用的原始文本，最长 100 字符 |
| `normalized_value` | 去除首尾空白后的唯一比较值 |
| `last_used_at` | 最近一次成功发布任务时使用的时间 |
| 审计字段 | `created_at`、`updated_at`、`created_by`、`updated_by`、`deleted_at` |

同一租户、类型和标准化文本在包含软删除数据的范围内只能有一条记录，唯一约束不附加 `deleted_at is null` 条件。重复保存只刷新 `last_used_at`；已经软删除的记录再次被成功任务使用时清空 `deleted_at` 并恢复为有效记录。

## 后端接口

### 查询

`GET /api/v1/admin/account-warmup/vocabulary`

支持 `kind`、`query` 和 `limit`。默认按 `last_used_at` 倒序返回，保证近期常用词优先。查询只返回当前租户且未删除的数据。

### 合并保存

`POST /api/v1/admin/account-warmup/vocabulary`

请求同时接收 `relatedTerms` 和 `comments`。服务端沿用养号契约的去空白、去重、数量和长度限制，并执行幂等 upsert。

前端只有在至少一个 `ACCOUNT_WARMUP_RUN` 命令创建成功后才调用该接口一次。多设备任务不会按成功设备数量重复保存。若词库保存失败，已创建的任务保持成功，页面单独提示“任务已发布，但共享词库保存失败”，并允许后续重试。

### 删除

`DELETE /api/v1/admin/account-warmup/vocabulary/:id`

删除前由前端显示确认框。后端执行软删除；运行中和历史命令中的 payload 不受影响。被删除文本以后再次用于成功任务时可以自动恢复。

## 前端交互

1. 页面加载时分别查询相关名词和评论历史。
2. 两个字段继续使用标签多选，历史记录作为可搜索选项显示。
3. 点击历史选项立即加入当前表单；键入新文本并确认后生成临时标签。
4. 下拉选项提供删除图标。删除操作阻止选项点击，并在确认成功后刷新共享数据。
5. 已选标签只从当前表单移除，不等同于删除共享词库。
6. 评论文本允许完整搜索；较长选项在下拉中截断显示，并通过提示展示完整内容。
7. 任务发布成功后合并保存本次最终标准化的相关词和评论，再刷新两个查询缓存。

## 离线 OCR 适配

`mobile-agent/autojs/core/ocr.js` 调整识别顺序：

1. AutoJs6 `ocr.recognizeText(image, { mode: "mlkit" })`。
2. 兼容旧运行时的 `ocr.recognize(image)`。
3. 兼容可用的 Paddle OCR 和 `$ocr` 实现。

返回值继续通过统一的 `normalizeResult()` 转换为文本。日志需记录选中的 OCR 引擎；引擎存在但调用失败时记录具体错误和重试次数，只有所有候选 API 都不存在时才报告能力缺失。

AutoJs6 工程已经包含 `com.google.mlkit:text-recognition-chinese`，APK 构建脚本也没有移除中文 OCR 模型，因此不需要 API Key、云服务或手机端单独安装插件。`core/ocr.js` 属于 APK 基础层，不在现有 `features/`、`domain/` 业务热更新范围内，修复后必须重新打 APK。

## 用户打包与安装边界

实现和自动化验证完成后，由用户执行仓库现有 `scripts/package-autojs-apk.ps1`。新 APK 必须提升 `versionName` 和 `versionCode`，使用与当前安装包一致的签名进行覆盖安装。安装后首次启动需要确认无障碍、悬浮窗和截图权限；OCR 本身无需额外配置。

## 错误处理

- 词库查询失败：表单仍允许手动输入，页面显示历史选项加载失败。
- 词库保存失败：不回滚已发布任务，显示独立警告并保留当前输入。
- 删除失败：选项保持不变并显示失败原因。
- OCR 不可用：记录探测过的 API 和错误，不伪造命中；养号任务沿用当前未命中/切换逻辑。
- OCR 返回空文本：记录引擎、区域和空结果，不把搜索关键词当作直播间相关词证据。

## 验证

### 后端

- 同租户同类型去重、不同类型可保存相同文本。
- 不同租户数据隔离。
- 重复保存刷新最近使用时间。
- 删除后不再查询到，再次保存可以恢复。
- 长度、数量和空值校验。

### 前端

- 加载、搜索、点击选择、手动新增和当前表单移除。
- 共享删除需要确认，且不会误触发选择。
- 全部任务发布失败时不保存词库。
- 部分或全部任务发布成功时只合并保存一次。
- 词库保存失败与任务发布结果分别提示。

### 手机端

- AutoJs6 `ocr.recognizeText()` 被正确选择并标准化结果。
- 旧 OCR API 兼容分支和失败重试。
- 真机稳定区域能识别中文直播间文字，并在命中 `relatedTerms` 后进入点赞和评论链路。
- 重新打包 APK 后核对版本、模型资产、截图权限和 OCR 引擎日志。
