# 目标直播间互动养号第一节点设计

## 目标

在左侧主菜单中新增独立“养号”功能入口，位置紧跟“视频发布”。“目标直播间互动养号”是养号主模块的一个子功能；第一节点只完成：管理员输入一个目标直播间关键词和 1～30 个相关名词，多选在线设备并立即下发；每台手机独立打开抖音、搜索关键词、切换顶部“直播”分类、纵向检查候选直播间，并在确认目标直播间后停留在该页面。

本节点不做点赞、评论、关注、观看计时、定时任务或周期任务。

## 用户流程

1. 进入“养号 → 目标直播间互动养号”。
2. 输入一个目标直播间关键词。该值同时用于抖音搜索和直播间主关键词匹配。
3. 输入相关名词标签，至少 1 个、最多 30 个；支持回车、中英文逗号，自动去重和清理空格。
4. 多选在线且启用的设备，点击“开始查找”。
5. 系统为每台设备创建独立命令，设备并行执行，失败互不影响。
6. 页面按设备显示等待下发、搜索中、验证中、已进入、未找到、停止中、已停止或执行失败。
7. 用户可停止整个批次或单台设备。

## 手机流程

每台设备最多执行 3 轮，每轮最多检查 4 个候选直播间：

1. 复用现有抖音适配器的包名启动逻辑打开 `com.ss.android.ugc.aweme`。
2. 抖音可用后随机等待 5～10 秒。
3. 点击右上角搜索入口，输入前端下发的目标关键词并搜索。
4. 搜索结果稳定后随机等待 2～5 秒，点击顶部“直播”分类。
5. 直播结果使用纵向滚动。按候选序号滚动后进入当前第一个直播间。
6. 进入后先确认页面仍是直播间，再读取主播名、直播标题和直播简介等稳定区域。
7. 无障碍文本优先；信息不足时对屏幕上部稳定区域执行 OCR。评论区和商品卡文字不参与匹配。
8. 直播间名称或标题包含目标关键词，或稳定区域包含任一相关名词，即判定成功并停留在直播间。
9. 不匹配、已下播或页面异常时执行固定恢复链：最近任务 → 识别并左滑移除抖音卡片 → 系统主页 → 按包名重新打开抖音。
10. 12 个候选均未命中时返回 `TARGET_LIVE_NOT_FOUND`。

所有普通动作之后使用 1～3 秒随机等待。等待范围是脚本内部规则，不在前端暴露配置。

## 架构

- 共享契约：新增通用养号运行和停止 payload schema，扩展通用手机命令类型。
- 后台：沿用 `mobile_commands`，不新增表或 migration。批次 ID 和目标信息保存在命令 payload，设备结果保存在 result JSON。
- 前端：新增独立 API client、表单页和批次状态表；在左侧主菜单中将“养号”放在“视频发布”之后，并在养号模块内挂载“目标直播间互动养号”子页签。
- 扩展边界：后续观看、点赞、评论等能力继续增加在“目标直播间互动养号”内部，不拆成养号主模块的同级子页签。
- 手机：新增小于 400 行的命令桥接器、热更新白名单注册表和目标直播间脚本。桥接器包装命令轮询，在独立线程运行任务并允许 STOP 命令继续被轮询。
- 热更新：APK 基线只安装一次通用桥接器；`features/account-warmup/registry.js` 按固定 `featureKey` 白名单加载业务脚本，后台不能传入任意文件路径。后续养号业务扩展通过 biz-scripts 发布注册表和 feature 脚本。
- 接线：只修改低于 400 行的 `main.module.js` 安装桥接器，不修改 1493 行的存量 `control-loop.js`。

## 命令契约

### `ACCOUNT_WARMUP_RUN`

```json
{
  "featureKey": "target_live_interaction",
  "batchId": "uuid",
  "config": {
    "targetKeyword": "药材种植",
    "relatedTerms": ["当归", "淫羊藿", "三七", "何首乌"],
    "maxRounds": 3,
    "candidatesPerRound": 4
  }
}
```

成功 ACK 为 `DONE`，result.status 为 `TARGET_LIVE_ENTERED`。未找到和执行异常 ACK 为 `FAILED`。

### `ACCOUNT_WARMUP_STOP`

```json
{
  "batchId": "uuid",
  "targetCommandId": "uuid"
}
```

停止命令只影响同设备中匹配的活动任务。活动任务收到停止信号后在动作边界结束，并以 `DONE`、result.status=`STOPPED` 收口。

## 验收

- 前端正确校验关键词、相关名词和设备多选，并为每台设备创建独立命令。
- 同批设备并行，结果逐设备展示；单设备失败不覆盖其他设备。
- 重复轮询同一个 FETCHED 命令不会启动第二个执行线程。
- 停止命令可以让运行脚本在动作边界结束。
- 目标关键词或任一相关名词命中稳定区域即可成功；评论和商品文字不参与判断。
- 每轮 4 个候选、最多 3 轮，失败上报 `TARGET_LIVE_NOT_FOUND`。
- 新增和修改的相关源文件不超过 400 行；存量超限文件不修改。
