# 抓取评论词：直播间入口设计

## 目标

在“视频养号”之后增加独立的“抓取评论词”功能页。第一阶段只完成按关键词进入第一个直播结果，并把执行过程实时反馈给用户。该功能不修改现有目标直播间互动养号和视频养号链路。

## 范围

### 本阶段包含

- 前端新增“抓取评论词”功能页。
- 任务批次可选择多台在线设备同时执行。
- 同一批次共用一套目标直播间关键词和人数下限。
- 人数下限默认为 `300`，允许输入非负整数；`0` 表示不限制；当前阶段只保存并下发参数，不执行人数判断。
- 手机端按人工路径执行：打开抖音、点击右上角搜索、输入关键词、点击“直播”页签、点击第一个直播结果。
- 前端显示批次汇总和每台设备的实时阶段、时间及错误信息。
- 进度事件写入后台任务记录，页面刷新后仍能查看最近一次执行记录。
- 无直播结果时自动重试一次；仍无结果则结束该设备任务并显示失败阶段。

### 本阶段明确不包含

- 评论区识别、上滑、评论文本提取或评论数据库写入。
- 直播间人数读取或 `300` 门槛校验。
- 目标房间身份校验、主播匹配或房间切换判断。
- 与共享评论词库、直播养号评论词库的连接。
- 修改既有 `target_live_interaction`、`video_warmup` 的执行逻辑。
- 修改包名、隐藏自动化特征或规避平台风控。

## 用户界面

“抓取评论词”作为独立页签，沿用现有设备选择上下文，不新增设备型号输入。页面包含：

1. 目标直播间关键词输入框。
2. 直播间人数下限输入框（默认 300，无上限，0 表示不限制）。
3. 启动批次按钮和停止批次按钮。
4. 批次汇总：设备总数、执行中、已进入、失败。
5. 设备明细：每台设备当前阶段、最后更新时间、结果或错误原因。
6. 阶段日志：下发任务、打开抖音、打开搜索、输入关键词、切换直播页签、点击首个结果、完成或失败。

设备选择沿用现有设备列表能力；页面不显示额外的设备型号字段，但进度明细必须标识设备，便于排查多设备差异。

## 任务与数据流

1. 前端生成 `batchId`，校验关键词和人数下限。
2. 后端为每个选中设备创建一条独立入口命令，命令共享 `batchId` 和参数快照。
3. 手机 Agent 领取命令，按阶段执行并上报阶段事件。
4. 后端保存命令终态和阶段事件；前端通过现有轮询/查询机制刷新进度。
5. 单台设备失败只结束该设备命令，不影响同批其他设备。
6. 批次在所有设备进入终态后汇总为完成、部分失败或全部失败。

新功能使用独立的 feature key 和命令处理分支，不复用旧养号的业务执行分支；共享评论词库留给后续阶段设计。

## 手机端入口状态机

- `PENDING`: 等待 Agent 领取。
- `OPENING_DOUYIN`: 打开抖音。
- `OPENING_SEARCH`: 定位并点击搜索入口。
- `INPUT_KEYWORD`: 输入并提交关键词。
- `OPENING_LIVE_TAB`: 点击“直播”页签。
- `OPENING_FIRST_RESULT`: 点击第一个直播结果。
- `RETRYING_SEARCH`: 首次没有结果时重新搜索一次。
- `ENTERED`: 入口动作完成，暂停等待后续评论采集阶段。
- `FAILED`: 记录失败阶段和可读原因，停止继续点击。

进入阶段的成功条件只代表“首个直播结果点击动作完成”；不代表已经通过人数或目标房间校验。

## 错误处理

- 设备离线或 Agent 未就绪：该设备命令失败，前端显示领取/连接阶段错误。
- 抖音无法打开、搜索入口找不到、直播页签找不到、首个结果无法点击：记录对应阶段并停止该设备。
- 首次未找到直播结果：自动重试一次；第二次仍为空则失败。
- 检测到验证码、风控提示或非预期页面：立即停止并上报，不尝试绕过。

## 验证

- 前端测试覆盖参数校验、批次构造、阶段和汇总展示。
- API 测试覆盖多设备命令拆分、参数快照、阶段事件和部分失败汇总。
- 手机端 mock 测试覆盖入口动作顺序、一次重试和终态上报。
- 真机验证由用户手动执行；本阶段不自动读取评论，也不验证人数。
