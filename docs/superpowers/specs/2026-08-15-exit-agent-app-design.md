# 退出燎原星火功能设计

## 目标

在现有远程唤醒模块中增加一个独立的“退出燎原星火”动作。该动作只管理内层 Agent 和燎原星火的应用界面任务，不停止外层底座服务、不停止外层心跳，也不影响已有业务脚本、开机自启、`START_AGENT` 或 `OPEN_AGENT_APP` 流程。

## 术语与边界

- **外层底座**：原生 Android BASE 层及 `BaseConnectivityService`，负责设备接入和外层心跳。用户不能从此功能停止它。
- **内层 Agent**：由 `main.js` 和 `watchdog.js` 组成的 AutoJS 业务运行层，可被本功能停止。
- **应用界面任务**：燎原星火 Activity 在前台或最近任务中的 UI 任务。这里的“后台”只指这个任务，不指 APK 进程和外层服务。
- **锁屏**：通过现有系统无障碍全局动作执行的屏幕锁定。锁屏开关默认关闭。

本功能的源码只能位于项目目录 `D:\new demo\Auto-Collection-main\Auto-Collection-main` 内；不修改或依赖 `D:\DevTools\Sources\AutoJs6` 的源码。

## 命令与数据契约

新增一个复合命令：`EXIT_AGENT_APP`。

请求体只有一个可选行为字段，默认值为 `false`：

```json
{ "lockScreen": false }
```

命令沿用现有设备命令通道和命令生命周期：

```text
PENDING -> FETCHED -> ACK
```

ACK 的业务结果单独放在结果体中，取值为：

- `DONE`：所有需要执行的步骤成功或幂等跳过。
- `PARTIAL`：前序步骤完成，但后续步骤失败，例如清理成功、锁屏失败。
- `FAILED`：没有完成必要步骤，或执行前置检查失败。

每个步骤返回 `SUCCESS`、`SKIPPED` 或 `FAILED`，并附带稳定的错误码和可读原因。建议结构如下：

```json
{
  "commandId": "...",
  "commandType": "EXIT_AGENT_APP",
  "result": "DONE",
  "stages": [
    { "name": "STOP_AGENT", "status": "SUCCESS" },
    { "name": "REMOVE_APP_TASK", "status": "SKIPPED", "reason": "NO_UI_TASK" },
    { "name": "LOCK_SCREEN", "status": "SKIPPED", "reason": "NOT_REQUESTED" }
  ]
}
```

传输层仍以现有 `ACK` 表示命令已处理；不得把 `PARTIAL` 或 `FAILED` 伪装成成功 ACK。

## 前置状态与用户提示

前端点击退出按钮后，先读取当前设备快照并在提交前再次校验。在线设备使用以下四种提示：

| 内层 Agent | 应用界面任务 | 提示与确认后的动作 |
| --- | --- | --- |
| 关闭 | 无 | “当前 Agent 已关闭，无后台程序。”点击“我知道了”仅关闭对话框，不下发命令。 |
| 关闭 | 有 | 告知 Agent 已关闭但仍有应用界面任务；确认后只清除该 UI 任务。 |
| 开启 | 无 | 告知 Agent 正在运行但没有应用界面任务；确认后只停止内层 Agent。 |
| 开启 | 有 | 告知 Agent 和应用界面任务均存在；确认后执行完整退出顺序。 |

前台任务和最近任务都视为“应用界面任务存在”。外层设备接入状态只用于判断命令是否可达，不作为内层 Agent 状态的替代品。设备离线或没有可用快照时，前端只提示当前无法连接并不下发命令，不猜测手机一定关机。

对话框提供“同时锁屏”开关，默认关闭。用户确认后才提交 `EXIT_AGENT_APP`；取消或关闭对话框不产生命令。

## 外层执行流程

命令只通过原生 BASE 层执行，步骤严格串行：

1. **前置检查**：解析 `lockScreen`，确认外层服务仍在运行；若请求锁屏，先确认系统锁屏能力和所需权限。前置检查失败时不改变 Agent 或 UI 任务，返回 `FAILED`。
2. **停止内层 Agent**：由新的原生 stopper 按规范化脚本路径定位 `main.js`、`watchdog.js` 的执行实例并调用 `engine.forceStop()`。两个脚本都已停止时返回 `SKIPPED/ALREADY_STOPPED`。
3. **清除应用界面任务**：通过 `AppUiForegroundController` 的任务清理能力移除燎原星火 Activity 的前台/最近任务。没有任务时返回 `SKIPPED/NO_UI_TASK`。不得调用 `force-stop package`，以免杀掉外层服务。
4. **可选锁屏**：仅当 `lockScreen=true` 且前两步均未失败时执行现有无障碍 `GLOBAL_ACTION_LOCK_SCREEN`。屏幕已锁定时返回 `SKIPPED/ALREADY_LOCKED`；调用失败时返回 `PARTIAL`，不得回报完整成功。
5. **提交 ACK**：写入逐步结果并回传最终业务结果。外层心跳在整个过程中持续运行。

任何步骤失败都停止后续步骤，避免继续占用通道。已完成的步骤保持真实记录，下一条命令不能复用上一条命令的临时执行状态。

## 并发、重试与幂等

- 同一设备同一时刻只允许一个退出命令执行；已有执行中的命令返回正在处理状态，不再启动第二个执行器。
- 以服务端 `commandId` 作为幂等键。重复投递已完成命令时直接返回缓存的 ACK，不重复停止脚本、移除任务或锁屏。
- 各步骤本身也必须幂等：Agent 已停止、UI 任务不存在、屏幕已锁定均视为成功跳过。
- 命令完成或失败后清理手机端临时上下文和执行锁；保留服务端审计结果，避免把历史步骤带入下一次任务。
- 网络重试只能重发同一 `commandId`，不能生成新的复合命令。

## 后端与前端职责

### API 与路由

- 在现有远程唤醒命令类型和校验器中加入 `EXIT_AGENT_APP`，只接受布尔 `lockScreen`。
- 复用现有鉴权、设备在线检查、命令入队和状态查询接口，不新增旁路通道。
- BASE 路由接受该命令；`STOP_AGENT` 是否可单独调用保持现状，不因本功能扩大其权限。

### 前端

- 在设备操作区增加独立的“退出燎原星火”按钮，和已有打开/启动动作分开。
- 对话框展示快照、执行阶段和最终 `DONE/PARTIAL/FAILED`；阶段失败时展示具体原因。
- 提交期间禁用重复确认，支持刷新后继续查看同一 `commandId` 的结果。
- 不提供停止外层底座或外层心跳的控件，也不修改现有打开流程的提示。

## 测试与验收

### 后端

- 命令类型和 payload 校验：缺失、非布尔和未知字段按既有校验规则处理。
- 路由测试：`EXIT_AGENT_APP` 只能进入 BASE 执行器，旧命令行为不变。
- 幂等和并发测试：重复 `commandId` 不产生第二次执行，同设备并发请求被串行化。
- ACK 合同测试：逐步状态、错误码和 `DONE/PARTIAL/FAILED` 映射正确。

### 原生 BASE

- Agent 开启/关闭、UI 任务存在/不存在四种组合均得到预期步骤。
- 锁屏未请求、已锁屏、权限缺失和执行失败分别验证；前序失败时不执行后续步骤。
- 断言不会调用 `force-stop package`，`BaseConnectivityService` 和外层心跳始终保持运行。
- 重复执行、脚本不存在、任务已被用户清除等场景验证为幂等结果。

### 前端

- 四种状态提示文案和确认动作逐一覆盖。
- 锁屏开关默认关闭，开启后正确传递布尔值。
- 阶段进度、部分完成和失败状态在刷新后仍能显示；旧的打开/启动回归测试通过。

### 真机验收

1. Agent 关闭且无 UI 任务：只显示信息，不下发命令。
2. Agent 关闭且有 UI 任务：确认后 UI 任务消失，外层心跳不中断。
3. Agent 开启且无 UI 任务：确认后内层停止，外层仍在线。
4. Agent 开启且有 UI 任务：确认后按顺序停止、清任务；勾选锁屏时最后锁屏。
5. 对每种组合重复点击和中途断网，确认不会出现重复后台、黑屏或旧任务串入。

## 非目标与兼容性

- 不改动外层心跳、开机自启、设备接入状态判定、已有业务脚本和更新中心。
- 不恢复已删除的旧远程唤醒旁路接口。
- 不在本设计阶段构建或安装 APK；构建和真机测试在实现计划完成后单独执行。
- 不自动修改 MIUI 自启动、电池策略或用户权限。
