# 农业采集监控产品流程与功能介绍

版本日期：2026-06-04

适用对象：产品、运营、项目负责人

## 1. 项目定位

这个项目当前要解决的问题是：手机脚本在抖音里持续浏览农业相关视频和直播，并把运行状态、采集记录、异常日志同步到后台，让产品和运营知道脚本有没有在跑、跑到了什么阶段、有没有采到农业内容、有没有出现风险或异常。

当前阶段不是完整素材库平台，也不是自动互动平台。核心闭环是：

| 模块 | 产品含义 | 当前作用 |
|---|---|---|
| 手机脚本 | 放在手机上的自动化执行端 | 浏览农业视频/直播，采集候选信息，上报状态 |
| 账号数据管理平台 | 给产品和运营看的后台 | 监控设备、查看记录、查看日志、下发控制命令 |
| 远程通信 | 手机和后台之间的数据通道 | 支持手机分散在不同地区后继续上报和受控 |
| 风险处理 | 异常识别和停止机制 | 遇到验证码、登录异常、页面跑偏时停止或恢复 |

## 3. 远程控制流程图

![远程通信与控制流程](../project-records/generated-assets/remote_control_flow.png)

会议里确认的核心点是：手机分散到全国各地后，不能再依赖插线群控，也不能让手机访问本机的 `192.168.x.x` 私网地址。后台必须有一个手机能访问到的公网地址。

远程控制不是后台直接钻进手机执行动作，而是后台先记录命令，手机脚本自己定时访问后台，把属于自己的命令拉下来执行。

| 环节 | 产品解释 |
|---|---|
| 后台下发命令 | 产品或运营在后台点击启动、暂停、恢复、停止、检查版本等按钮 |
| 命令进入后台 | 后台记录这条命令，等待手机来拉取 |
| 手机主动拉取 | 手机脚本定时访问后台，检查有没有新命令 |
| 手机执行命令 | 脚本根据命令改变任务状态 |
| 回传执行结果 | 手机把命令是否执行成功回写到后台 |
| 心跳持续上报 | 手机每分钟上报一次状态，后台据此判断在线、离线、运行、暂停 |

## 4. 会议形成的方案边界

06-03 会议讨论的重点不是继续调某一个脚本动作，而是确认“不插线、分散运行”后怎么继续管手机。结论如下：

| 场景 | 结论 | 说明 |
|---|---|---|
| 集中插线群控 | 可以做，但不是当前分散运行主方案 | 手机都在现场并接线时可以直控；手机分散后无法依赖这种方式 |
| 分散远程脚本 Agent | 当前主方案 | 手机主动访问公网后台，上报状态并拉取命令 |
| 第三方群控工具 | 可调研，不作为当前交付依赖 | 后续如发现成熟工具，再单独评估稳定性、成本和权限边界 |
| 公网直接暴露 ADB | 不建议作为主方案 | 安全风险高，不适合长期暴露给全国分散手机 |
| 多手机共用同一 Wi-Fi | 不建议作为长期运行方式 | 大量手机共用同一出口 IP 容易带来账号侧风险 |

## 5. 手机端功能介绍

手机脚本目录是 `mobile-agent/autojs`，复制到手机后通过 AutoX.js / Auto.js 运行 `main.js`。

| 功能 | 产品说明 | 当前状态 |
|---|---|---|
| 权限检查 | 检查无障碍、悬浮窗、截图等权限 | 已实现 |
| 极简控制按钮 | 手机上保留开始/暂停和停止按钮，减少遮挡 | 已实现 |
| 农业关键词搜索 | 通过水稻病虫害、大棚蔬菜、果树修剪等词进入农业内容流 | 已实现 |
| 视频浏览 | 随机运行 2-3 小时，尽量减少无关内容停留 | 已实现 |
| 直播浏览 | 随机运行 1-2 小时，进入少量直播间并控制停留 | 已实现基础逻辑 |
| 内容采集 | 采集标题、作者、点赞/评论等指标、评论和屏幕文本 | 已实现 |
| 本地输出 | 采集结果保存到脚本目录下 `datasource` | 已实现 |
| 后台上报 | 上报采集记录、运行日志和心跳 | 已实现 |
| 常驻待命 | 一轮任务结束后不退出脚本，回到待命状态 | 已实现 |
| 版本检查 | 上报当前脚本版本，检查后台目标版本 | 已实现第一阶段 |

## 6. 后台功能介绍

后台模块是 `account-data-platform`，产品名称可以理解为“账号数据管理平台”。当前定位是监控和排障，不是完整运营平台。

| 页面 | 产品作用 | 当前状态 |
|---|---|---|
| 监控看板 | 查看设备数、运行数、今日采集、今日异常、最近心跳、最近日志 | 已实现基础版 |
| 设备 | 查看每台手机是否在线、当前状态、最后心跳、版本、最后命令 | 已实现基础版 |
| 采集记录 | 查看手机采集到的视频和直播候选记录 | 已实现基础版 |
| 日志 | 查看脚本运行日志，排查卡住、异常、上传失败等问题 | 已实现基础版 |
| 任务配置 | 管理关键词、视频时长、直播时长、基础策略 | 已实现基础版 |
| 远程控制 | 对设备下发启动、暂停、恢复、停止、刷新配置、检查版本等命令 | 已实现基础版 |

## 7. 当前采集与监控的数据

这些数据主要用于判断账号浏览内容是否偏向农业领域，以及脚本是否稳定运行。

| 数据类型 | 内容 | 用途 |
|---|---|---|
| 采集记录 | 平台、类型、关键词、标题、作者、互动指标、评论、屏幕文本 | 判断是否采到农业相关内容 |
| 心跳 | 当前状态、运行阶段、已浏览数量、采集数量、剩余时间、版本 | 判断手机是否在线和任务是否正常 |
| 运行日志 | 启动、暂停、停止、异常、上传结果、风险停止原因 | 排查脚本问题 |
| 命令记录 | 后台下发了什么命令、手机是否拉取、是否执行成功 | 判断远程控制是否生效 |
| 版本事件 | 当前版本、目标版本、检查结果、更新事件 | 后续远程更新使用 |

## 8. 部署与通信说明

如果手机和后台在同一个局域网，手机可以访问本机后台地址。只要手机使用流量，或者手机分散到不同地区，就不能继续使用 `192.168.x.x` 这种本机私网地址。

要让分散手机能正常上报，需要下面任一种方式：

| 方式 | 说明 | 适用阶段 |
|---|---|---|
| 内网穿透 | 本机后台还在本地运行，通过 frp 映射出公网地址 | 本地演示、短期验证 |
| 云服务器部署 | 后台 API 和前端部署到服务器，手机直接访问域名 | 正式运行 |
| HTTPS 域名 | 给正式后台配置域名和证书 | 长期运行 |

短期建议先用 frp 打通公网访问，验证手机使用流量时后台能收到心跳、日志和采集记录。验证通过后，再迁移到正式云服务器。

## 9. 风险识别与安全边界

这里的“风控规避”应理解为减少不必要的异常触发，并在风险出现时及时停止自动操作，不是绕过验证码或绕过平台限制。

| 风险场景 | 当前处理方式 |
|---|---|
| 验证码、安全验证、滑块 | 停止自动操作，记录日志，等待人工处理 |
| 登录异常、账号异常 | 停止任务并上报后台 |
| 页面跑到发布页、商品页、评论页等非采集场景 | 尝试恢复到视频流，超过次数后停止 |
| 网络不可用 | 本地继续保存关键记录，网络恢复后补传 |
| 后台不可达 | 脚本继续本地运行，不被后台请求卡死 |
| 动作轨迹或批量行为风险 | 通过随机停留、随机滑动、分散网络降低风险，实际效果需要持续观察 |

明确不做的内容：

| 不做内容 | 原因 |
|---|---|
| 不绕过验证码 | 平台风险高，且不符合当前项目边界 |
| 不自动点赞、评论、关注、私信 | 当前目标是采集和监控，不是互动执行 |
| 不直接公网暴露 ADB | 安全和维护风险高，不适合作为远程控制主方案 |
| 不承诺平台账号标签结果 | 后台只能展示浏览和采集证据，不能证明平台最终如何识别账号 |

## 10. 产品验收关注点

产品验收时建议重点看下面几件事：

| 验收点 | 判断方式 |
|---|---|
| 手机是否在线 | 设备页最后心跳是否持续更新 |
| 脚本是否在跑 | 看板是否显示运行阶段、浏览数量和采集数量 |
| 是否采到农业内容 | 采集记录是否出现农业关键词、标题和屏幕文本 |
| 视频阶段是否完成 | 心跳和日志是否显示视频阶段持续运行并结束 |
| 直播阶段是否完成 | 日志是否显示进入直播阶段，并限制直播间数量 |
| 远程控制是否生效 | 命令状态是否从待拉取变为已执行或失败 |
| 异常是否可排查 | 日志里是否能看到停止原因、风险词、页面恢复记录 |
| 流量手机是否能上报 | 手机不在本机局域网时，后台仍能收到心跳和日志 |
