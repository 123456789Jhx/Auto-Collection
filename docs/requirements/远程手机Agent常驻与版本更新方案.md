# 远程手机 Agent 常驻与版本更新方案

## 1. 文档目标

本文定义手机脚本从“本地一次性采集脚本”升级为“远程手机 Agent”的方案。目标是让分布在不同地区的手机在不物理连接电脑的情况下长期运行，后台可以实时监控脚本状态、下发控制指令、调整任务配置，并在后续支持脚本版本更新。

本文只描述方案，不落代码。后续每一阶段改手机脚本、后台接口、数据库或前端页面前，必须先确认本阶段范围。

## 2. 背景结论

当前脚本已经具备抖音视频/直播采集、心跳、运行日志、后台控制和本地缓存能力，但它仍偏向“人工启动一次任务”。如果手机分布在全国各地运行，现有模式存在三个问题：

1. 任务结束后脚本容易进入停止态，不适合作为长期在线执行端。
2. 心跳间隔和在线判断不够实时，后台不能快速识别掉线、卡死、风控或版本落后。
3. 脚本更新依赖人工复制文件夹，无法支撑远程维护。

因此后续应把手机端定义为常驻 Agent：脚本长期运行，采集任务只是 Agent 的一个工作阶段。

## 3. 当前范围与不变范围

| 范围 | 说明 |
|---|---|
| 当前要升级 | 手机脚本常驻、实时心跳、远程控制、远程配置、版本检查、更新流程 |
| 当前保留 | AutoX.js / Auto.js 运行方式、`mobile-agent/autojs` 源码目录、后台账号数据管理平台 |
| 暂不处理 | 官方 API、AI 分析审核、素材库、知识库、自动点赞评论关注私信、验证码绕过 |
| 必须遵守 | 遇到验证码、登录异常、风控提示时停止自动操作并上报，等待人工处理 |

## 4. 目标架构

```text
远程手机 AutoX.js Agent
  -> 常驻主循环
  -> 定时心跳
  -> 拉取后台命令
  -> 拉取任务配置
  -> 执行视频/直播采集
  -> 上传采集记录、运行日志、状态摘要
  -> 检查脚本版本
  -> 下载更新包、校验、备份、替换、重启

公网账号数据管理平台
  -> 设备在线状态
  -> 任务配置
  -> 控制命令
  -> 版本发布
  -> 日志与采集数据
  -> 异常告警
```

后台必须部署到公网服务器，并使用域名和 HTTPS。手机脚本不能再使用局域网地址，例如 `192.168.x.x`。

## 5. 手机 Agent 状态机

| 状态 | 说明 | 进入条件 | 退出条件 |
|---|---|---|---|
| `booting` | 脚本启动和权限检查 | AutoX.js 启动脚本 | 权限通过后进入 `idle` |
| `idle` | 在线待命，等待任务或后台指令 | 启动完成、任务结束、恢复待命 | 收到启动命令或到达本地计划 |
| `running` | 正在执行视频或直播采集 | 手动开始、后台启动、计划启动 | 任务完成、暂停、停止、异常 |
| `paused` | 暂停自动操作，脚本仍在线 | 后台暂停或悬浮窗暂停 | 后台恢复或悬浮窗恢复 |
| `updating` | 下载和替换脚本版本 | 后台发布强制更新或可选更新 | 更新成功重启，失败回滚 |
| `error` | 脚本仍活着但当前任务异常 | OCR、页面、网络、权限等异常 | 自动恢复成功或进入人工处理 |
| `risk_control` | 检测到验证码、账号异常或风控 | 页面文本命中风险词 | 停止采集并等待人工处理 |
| `stopped` | 人工停止当前任务 | 后台停止或悬浮窗停止 | 回到 `idle` 或退出脚本 |
| `offline` | 后台推导状态，不由手机上报 | 心跳超时 | 收到新心跳 |

`offline` 只能由后台根据最后心跳时间计算，手机端不主动上报 `offline`。

## 6. 常驻主循环

手机 Agent 启动后不应直接退出。推荐主循环如下：

1. 初始化配置、日志、存储目录、设备编号和本机版本。
2. 检查无障碍、悬浮窗、截图权限。
3. 立即上报启动心跳，状态为 `idle`。
4. 进入常驻循环：
   - 按心跳间隔上传状态。
   - 按控制间隔拉取后台命令。
   - 按配置间隔拉取任务配置。
   - 按版本间隔检查是否需要更新。
   - 如果状态为 `running`，执行视频或直播阶段。
   - 如果任务结束，回到 `idle`，不退出脚本。
5. 遇到异常时先写本地日志，再上报后台；上报失败时保留本地缓存。

主循环要求：后台网络不可用时，脚本仍保持本地可运行；后台请求必须短超时、异步或非阻塞，不能卡住采集主流程。

## 7. 心跳策略

当前 15 分钟心跳不适合远程实时监控。后续建议改为：

| 场景 | 推荐间隔 | 说明 |
|---|---:|---|
| 常驻待命 `idle` | 60 秒 | 确认手机脚本仍在线 |
| 采集运行 `running` | 60 秒 | 上报浏览数、采集数、当前阶段 |
| 暂停 `paused` | 60 秒 | 证明脚本未退出 |
| 更新 `updating` | 15-30 秒 | 让后台看到更新进度 |
| 后台命令拉取 | 10-30 秒 | 控制暂停、停止、恢复的响应速度 |
| 在线超时判断 | 3-5 分钟 | 超过阈值后台显示离线 |

心跳只传状态摘要，不上传大文本和截图。采集记录、运行日志和截图证据走独立接口。

## 8. 远程控制

后台控制采用手机主动拉取命令的方式，不要求后台主动连接手机。

| 命令 | 作用 | 手机端处理 |
|---|---|---|
| `START` | 开始当前任务 | `idle` 或 `paused` 切换为 `running` |
| `PAUSE` | 暂停采集 | 停止滑动和 OCR，保持心跳 |
| `RESUME` | 恢复采集 | 从暂停处继续 |
| `STOP` | 停止当前任务 | 当前阶段结束，回到 `idle` |
| `STATUS` | 查询状态 | 立即上报心跳和状态摘要 |
| `REFRESH_CONFIG` | 刷新配置 | 拉取最新任务配置，不强制中断当前任务 |
| `RESTART_APP` | 重启目标平台 App | 回到手机首页并重新打开抖音 |
| `RESTART_AGENT` | 重启脚本 | 需要 AutoX.js 支持脚本自重启或由守护机制实现 |
| `CHECK_UPDATE` | 检查版本 | 立即请求版本清单 |
| `UPDATE_AGENT` | 更新脚本 | 进入 `updating`，执行下载、校验、替换 |

每条命令必须有回执：`FETCHED`、`DONE`、`FAILED`、`IGNORED`。后台页面不能只显示“已下发”，还要显示手机是否已拉取、是否执行成功。

## 9. 远程配置

手机端本地 `config.js` 只保留兜底配置。正式运行时优先使用后台任务配置。

| 配置项 | 后台维护 | 手机端用途 |
|---|---|---|
| 设备编号 | 是 | 区分手机 |
| 平台 | 是 | 当前为抖音 |
| 搜索关键词 | 是 | 进入农业相关视频流 |
| 农业匹配词 | 是 | 判断内容是否相关 |
| 视频运行时长 | 是 | 生成每日随机时长 |
| 直播运行时长 | 是 | 生成每日随机时长 |
| 直播间数量上限 | 是 | 控制直播阶段进入房间数量 |
| 心跳间隔 | 是 | 控制监控实时性 |
| 命令拉取间隔 | 是 | 控制后台指令响应速度 |
| 脚本最低版本 | 是 | 判断是否强制更新 |
| 风险词库 | 是 | 检测验证码、风控和异常页面 |

配置刷新不能直接覆盖正在执行中的关键参数。推荐策略是：当前阶段继续使用运行时快照，下一阶段或下一轮任务使用新配置。

## 10. 版本更新方案

### 10.1 版本模型

后台维护手机 Agent 版本清单。

| 字段 | 说明 |
|---|---|
| `version` | 版本号，例如 `0.2.0` |
| `channel` | 发布通道：`stable`、`gray`、`dev` |
| `minSupportedVersion` | 低于该版本必须更新 |
| `packageUrl` | 更新包下载地址 |
| `sha256` | 文件校验值 |
| `entryFile` | 入口文件，默认 `main.js` |
| `releaseNote` | 本次更新说明 |
| `forceUpdate` | 是否强制更新 |
| `publishedAt` | 发布时间 |

### 10.2 手机端更新流程

1. Agent 定时请求版本清单。
2. 比较本机 `config.app.version` 和后台版本。
3. 如果需要更新，先上报 `updating` 心跳。
4. 下载更新包到本地临时目录。
5. 校验 `sha256`。
6. 备份当前脚本目录。
7. 替换脚本文件。
8. 写入新版本标记。
9. 重启脚本或提示人工重启。
10. 更新失败时回滚备份目录，并上报失败原因。

更新必须支持失败回滚。不能直接覆盖后删除旧版本，否则远程手机一旦更新失败就可能失联。

### 10.3 更新包建议

用户当前希望直接复制整个 `mobile-agent/autojs` 文件夹，因此远程更新阶段推荐仍保持“目录结构包”的概念，不依赖 bundle。

```text
autojs-agent-0.2.0/
  main.js
  main.module.js
  config.js
  app/
  core/
  domain/
  platforms/
  utils/
  manifest.json
```

`manifest.json` 记录文件列表、版本、入口文件和校验值。手机端按 manifest 替换文件。

## 11. 后台页面调整

| 页面 | 新增能力 |
|---|---|
| 设备列表 | 当前状态、最后心跳、本机版本、目标版本、更新状态、最近命令回执 |
| 设备详情 | 心跳时间线、命令时间线、版本更新时间线、最近错误 |
| 任务配置 | 下发搜索词、匹配词、时长、心跳间隔、控制间隔 |
| 命令中心 | 对单台或多台设备下发控制指令 |
| 版本管理 | 发布 Agent 版本、灰度范围、强制更新、回滚版本 |
| 日志中心 | 按设备、状态、版本、命令 ID 查询日志 |

后台页面的在线状态只按 `lastHeartbeatAt` 计算。最近上报状态只作为历史状态展示，不能覆盖在线判断。

## 13. 数据库扩展

| 表 | 用途 |
|---|---|
| `collector_devices` | 增加当前版本、目标版本、最后命令时间、最后错误 |
| `device_heartbeats` | 保留状态快照和运行计数 |
| `mobile_commands` | 记录后台下发命令和执行回执 |
| `agent_versions` | 记录手机脚本版本发布信息 |
| `agent_update_events` | 记录下载、校验、替换、重启、失败、回滚 |
| `device_config_snapshots` | 记录设备拉取到的配置快照，便于排查 |

数据库表必须写字段注释或备注；新增迁移必须可重复验证，不能直接手工改库。

## 14. 安全与部署

1. 后台必须部署公网 HTTPS。
2. 每台设备必须有设备密钥或 token，不能只靠 `deviceId`。
3. 版本更新包必须校验 `sha256`。
4. 后台命令必须记录操作人、时间、目标设备和执行结果。
5. 手机端请求必须短超时，失败后本地缓存，不阻塞主流程。
6. 设备失联后后台只能显示离线，不能假定脚本仍在运行。
7. 风控、验证码和登录异常只允许上报和停止，不实现绕过。

## 15. 分阶段落地

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| 第一阶段 | 常驻 Agent 和实时心跳 | 脚本启动后不退出；任务结束回到 `idle`；后台 3-5 分钟内能判断离线 |
| 第二阶段 | 稳定远程控制 | 后台启动、暂停、恢复、停止均有拉取和执行回执 |
| 第三阶段 | 后台任务配置下发 | 手机端优先使用后台配置，本地配置只兜底 |
| 第四阶段 | 版本检查与版本展示 | 后台能看到每台手机当前版本、目标版本和是否落后 |
| 第五阶段 | 远程更新和回滚 | 手机可下载、校验、替换脚本；失败能回滚旧版本 |
| 第六阶段 | 告警与批量管理 | 支持离线、异常、版本落后、风控状态告警 |

## 16. 验收标准

1. 手机脚本启动后 60 秒内后台出现最新心跳。
2. 任务结束后脚本不退出，后台显示 `idle`。
3. 断网后脚本继续本地运行，恢复网络后补传关键日志和采集记录。
4. 后台下发暂停或停止后，手机在命令拉取间隔内执行并回执。
5. 后台能区分 `当前状态`、`最近上报`、`最后心跳`、`本机版本`。
6. 手机版本落后时后台能识别并提示。
7. 远程更新失败时手机能回滚，后台能看到失败原因。
8. 所有异常状态都有日志和最近阶段信息，方便远程排查。
