# 后台监控工程实施方案

## 1. 文档目标

本文定义账号数据管理平台的工程落地方案。当前阶段目标是让手机 AutoX.js 脚本可以上传采集记录、心跳和运行日志，平台页面可以查看设备状态、采集数据、日志和任务配置。

本文只描述方案，不代表已经落地代码。后续创建、修改前后端代码或工程配置前，必须先向项目负责人确认。

## 2. 工程结构

```text
Auto-Collection/
  account-data-platform/
    apps/
      web/           # React 平台管理端
      api/           # Hono API 服务
    packages/
      db/            # Drizzle schema、migration、db client
      types/         # 前后端共享类型和 Zod schema
  mobile-agent/       # AutoX.js 手机脚本
  docs/               # 需求与设计文档
```

`account-data-platform` 是“账号数据管理平台”的英文目录名。目录名不使用中文，避免跨系统路径兼容问题。

平台模块内部结构：

```text
account-data-platform/
  apps/
    web/           # React 后台管理端
    api/           # Hono 后端 API 服务
  packages/
    db/            # Drizzle schema、migration、db client
    types/         # 前后端共享类型和 Zod schema
```

第一阶段不创建 `apps/worker`、`packages/ai`、`packages/storage`、`packages/auth`。这些目录在后续出现 AI、异步任务、文件存储或完整权限体系时再补齐。

## 3. 技术栈

| 模块 | 技术 |
|---|---|
| 包管理 | Bun workspaces |
| 后端 | Bun runtime + Hono |
| 入参校验 | Zod |
| ORM | Drizzle ORM |
| 数据库 | PostgreSQL |
| 在线状态 | Redis |
| 前端 | React 19 + TypeScript + Vite |
| 路由 | TanStack Router 文件路由 |
| 服务端状态 | TanStack Query |
| UI | Ant Design |
| 接口文档 | OpenAPI 文档或接口 Markdown |
| 本地环境 | Docker Compose |

技术栈来源：`docs/部门统一技术架构规范_V1.0.md`。

## 4. 后端模块

| 模块 | 说明 |
|---|---|
| `routes/health` | `/health`、`/ready` 健康检查 |
| `routes/mobile` | 手机脚本上报接口 |
| `routes/admin` | 后台管理端查询接口 |
| `services/task` | 任务配置业务逻辑 |
| `services/device` | 设备状态和心跳业务逻辑 |
| `services/record` | 采集记录业务逻辑 |
| `services/log` | 运行日志业务逻辑 |
| `repositories/*` | Drizzle 数据访问 |

第一版可以先按 `mobile`、`admin` 两组路由组织接口，但路由层只负责校验和响应，业务逻辑必须下沉到 service，数据库访问必须下沉到 repository。

后端推荐目录：

```text
apps/api/
  src/
    routes/
      health.ts
      mobile.ts
      admin.ts
    services/
      task.service.ts
      device.service.ts
      record.service.ts
      log.service.ts
      overview.service.ts
    repositories/
      task.repository.ts
      device.repository.ts
      record.repository.ts
      heartbeat.repository.ts
      log.repository.ts
    validators/
      mobile.schema.ts
      admin.schema.ts
    middleware/
      error-handler.ts
      request-log.ts
    app.ts
    index.ts
```

## 5. 手机端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/mobile/tasks/current` | 手机获取当前任务配置 |
| `POST` | `/api/v1/mobile/collection-records` | 上传采集记录 |
| `POST` | `/api/v1/mobile/heartbeats` | 上传心跳 |
| `POST` | `/api/v1/mobile/runtime-logs` | 上传运行日志 |

## 6. 后台管理接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/admin/overview` | 监控看板 |
| `GET` | `/api/v1/admin/devices` | 设备列表 |
| `GET` | `/api/v1/admin/devices/:id` | 设备详情 |
| `GET` | `/api/v1/admin/devices/:id/heartbeats` | 设备心跳时间线 |
| `GET` | `/api/v1/admin/collection-records` | 采集记录列表 |
| `GET` | `/api/v1/admin/runtime-logs` | 日志列表 |
| `GET` | `/api/v1/admin/tasks` | 任务配置列表 |
| `POST` | `/api/v1/admin/tasks` | 创建任务配置 |
| `PATCH` | `/api/v1/admin/tasks/:id` | 更新任务配置 |
| `POST` | `/api/v1/admin/tasks/:id/actions/enable` | 启用任务 |
| `POST` | `/api/v1/admin/tasks/:id/actions/disable` | 停用任务 |

## 7. 数据库表

第一版只建监控闭环必需表：

1. `collector_device`
2. `collection_task`
3. `collection_record`
4. `device_heartbeat`
5. `runtime_log`

未来素材库、知识库、AI 分析和审核表继续保留在 `docs/方案设计/后续方案/`，不进入当前第一版。

## 8. 前端页面

| 页面 | 路由 | 说明 |
|---|---|---|
| 看板 | `/` | 今日运行、命中率、异常概览 |
| 设备 | `/devices` | 设备在线状态、最后心跳 |
| 采集记录 | `/records` | 农业候选内容列表 |
| 日志 | `/logs` | 运行日志和停止原因 |
| 任务配置 | `/tasks` | 关键词、时长、评论开关 |

前端推荐目录：

```text
apps/web/
  src/
    routes/
      index.tsx
      devices.tsx
      records.tsx
      logs.tsx
      tasks.tsx
    features/
      overview/
      devices/
      records/
      logs/
      tasks/
    components/
    lib/
      api-client.ts
    styles/
    main.tsx
```

前端页面只负责展示、筛选、表单和调用 API，不直接写业务判断。设备状态、停止原因、命中率等计算优先由 API 返回。

页面实现要求：

1. 列表页统一使用 Ant Design `Table`。
2. 筛选区统一使用 Ant Design `Form`。
3. 状态枚举统一使用 `Tag`。
4. 删除、停用、启用等危险或状态变更操作必须有确认。
5. 每个页面必须实现 loading、empty、error 状态。
6. 任务编辑使用抽屉或独立页面，不能用复杂弹窗承载。

## 9. 本地启动

```bash
bun install
bun run docker:up
bun run db:generate
bun run db:migrate
bun run dev
```

默认地址：

| 服务 | 地址 |
|---|---|
| 后端 API | `http://localhost:3010/api` |
| 健康检查 | `http://localhost:3010/health` |
| 后台前端 | `http://localhost:3020` |
| PostgreSQL | `localhost:5432` |
| Redis | `localhost:6379` |

根目录标准脚本应符合部门规范：

```json
{
  "scripts": {
    "dev": "bun run --filter '*' dev",
    "dev:web": "bun --filter @app/web dev",
    "dev:api": "bun --filter @app/api dev",
    "build": "bun run build:web && bun run build:api",
    "build:web": "bun --filter @app/web build",
    "build:api": "bun --filter @app/api build",
    "lint": "eslint .",
    "typecheck": "tsc -b",
    "test": "bun test",
    "db:generate": "drizzle-kit generate",
    "db:migrate": "drizzle-kit migrate",
    "db:studio": "drizzle-kit studio"
  }
}
```

## 10. 验收标准

1. Hono API 服务可以启动并返回 `/health`。
2. `/ready` 可以检查 PostgreSQL 和 Redis 是否可用。
3. Drizzle 能连接 PostgreSQL 并通过 migration 创建五张核心表。
4. React 后台可以打开看板、设备、采集记录、日志和任务配置页面。
5. 手机端接口字段与 `docs/方案设计/架构方案/后台监控架构方案.md` 保持一致。
6. 工程结构、技术栈、端口和脚本与 `部门统一技术架构规范_V1.0.md` 一致。

## 11. 落地约束

1. 本文档只用于方案确认。
2. 未经项目负责人确认，不创建 `apps/`、`packages/`、`package.json`、`docker-compose.yml` 等工程文件。
3. 每次准备落代码前，必须说明本次会创建或修改哪些文件，并等待确认。
4. 不在同一项目中混用 NestJS、Vue、Prisma、MySQL 等非当前规范技术栈。
