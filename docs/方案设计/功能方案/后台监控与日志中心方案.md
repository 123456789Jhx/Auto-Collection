# 后台监控与日志中心方案

本文记录后台 Web 当前实际功能和后续保持方向，合并原后台 UI 页面收敛、日志中心重构和 UI 卡点记录中的有效结论。

## 1. 功能定位

后台 Web 是运营和排查入口，目标是让非技术用户能看懂每台手机的运行状态、任务进度、采集结果、直播评论动作和异常原因。

后台页面不直接操作手机屏幕，只通过后台 API 保存配置、创建命令、展示数据和查看日志。

## 2. 当前页面

| 页面 | 定位 |
|---|---|
| 工作台 | 今日运行概览、设备在线状态、核心功能状态看板、任务进度和常用控制 |
| 任务调度 | 查看后台期望任务、手机实际任务、命令状态，并统一下发视频、直播、直播评论任务 |
| 采集记录 | 查看手机上报的视频、直播采集记录 |
| 日志中心 | 默认查看功能状态和异常汇总，完整日志在独立标签中查看 |
| 配置 | 维护公共任务模板和设备级覆盖配置 |

设备运行能力已收敛到工作台，不再保留重复导航入口。直播评论不再作为独立后台页面出现，任务启动、暂停、停止和切换统一归入任务调度页。

## 3. 工作台

工作台以设备为核心：

1. 顶部展示在线设备、运行中设备、今日采集和今日异常。
2. 顶部增加功能状态看板，只展示“设备在线、配置同步、采集链路、日志同步”四类关键状态是否跑通。
3. 设备卡片展示设备名、设备码、心跳状态、当前任务、今日进度、功能状态条和最近日志。
4. 点击设备卡片打开右侧详情抽屉。
5. 常用操作包括启动、暂停、恢复、停止、刷新配置。
6. 心跳状态必须醒目，离线和异常状态要优先暴露。

工作台不展示大量技术字段，复杂 JSON、命令 payload 和原始日志进入详情或日志中心。

## 4. 任务调度页

任务调度页不能只展示历史分配记录。即使没有任何分配记录，也必须先展示手机任务状态。

第一屏结构：

| 区域 | 作用 |
|---|---|
| 手机任务状态 | 展示每台设备在线状态、后台希望任务、手机实际任务和最近反馈 |
| 快捷操作 | 对指定设备下发视频、直播、直播评论任务、停止 |
| 分配记录 | 作为审计和排查使用 |

展示字段：

1. 设备名称和设备码。
2. 在线状态和最近心跳。
3. 后台期望任务：视频、直播、直播评论任务、未分配。
4. 手机实际任务：由最新心跳或 raw payload 提供。
5. 最近命令状态：待下发、已拉取、已回执、失败、过期。
6. 调度原因和失败原因。

英文状态、技术字段和 JSON 不应直接显示在主表。需要中文映射：

| 原值 | 主表文案 |
|---|---|
| `video` | 视频 |
| `live` | 直播 |
| `live_comment` | 直播评论任务 |
| `PENDING` | 待下发 |
| `FETCHED` | 手机已拉取 |
| `ACKED` | 手机已确认 |
| `FAILED` | 失败 |
| `manual` | 手动调整 |
| `task_orchestrator` | 后台调度 |

## 5. 直播评论能力归属

直播评论能力不再保留独立导航页面，避免和商品卡直播评论、旧目标直播间评论混淆。控制入口统一放到任务调度页，配置和审计继续复用既有配置与记录能力：

1. 启动、暂停、恢复、停止直播评论任务由任务调度页统一下发。
2. 工作台只展示评论任务是否运行、是否有日志、是否有异常，不展示旧直播评论操作台。
3. 评论动作记录和配置能力不删除，继续保留给配置页、设备详情或后续专门抽屉复用。
4. 商品卡直播评论和旧目标直播间评论必须通过任务类型、配置字段和日志阶段区分，不能在 UI 文案里混为一个“直播评论页面”。
5. 执行记录展示计划、已发送、跳过、失败和中文原因。

保存评论相关配置后，应触发配置更新或远程命令下发，确保手机端不会只停留在旧配置。

## 6. 采集记录

采集记录保留三层路径：

```text
手机卡片
-> 采集日期
-> 当天内容列表
```

主表展示标题、作者、来源、关键词、命中原因和采集时间。屏幕文本、热门评论、原始 payload 进入详情抽屉。

该路径是用户已习惯的操作方式，后续 UI 改版不能改成默认下拉直接进入明细。

## 7. 日志中心

日志中心也保留三层路径：

```text
手机卡片
-> 日志日期
-> 功能状态 / 异常汇总 / 完整日志
```

### 7.1 功能状态

功能状态面向运营用户，主表列为：

| 列 | 含义 |
|---|---|
| 时间 | 本地时间 |
| 状态 | 正常、需要关注、异常 |
| 发生了什么 | 人话描述功能状态或事件 |
| 所在环节 | 页面识别、任务切换、搜索、直播间、评论、上传等 |
| 涉及内容 | 关键词、主播、直播间或目标上下文 |
| 是否影响任务 | 不影响、可能影响、已影响 |
| 建议处理 | 无需处理、检查配置、看手机页面、确认权限等 |

主表不直接展示 `douyin_state_detection`、`candidate_upload`、`context_json` 等技术字段。默认视角只关注设备在线、配置同步、采集链路、日志同步等关键能力是否正常，完整日志进入独立标签。

### 7.2 异常汇总

异常汇总聚合 WARN、ERROR 和最近失败原因，重点回答：

1. 哪台手机异常最多。
2. 主要失败原因是什么。
3. 是否影响任务继续运行。
4. 是否需要人工查看手机。

### 7.3 完整日志

完整日志来自 `device_log_files`，展示后台已收到的完整日志内容、上传时间、文件大小、警告数、错误数和最近错误。

手机端心跳会按节流策略自动同步当前日志文件。后台可保留“重新同步”作为次级兜底操作，但完整日志查看不应依赖用户每次手动拉取。

## 8. 友好文案映射

常见原因映射：

| 原因 | 用户文案 | 建议 |
|---|---|---|
| `task_switched` | 后台切换了任务 | 观察新任务是否启动 |
| `target_live_card_not_found` | 搜索结果里没找到目标直播间 | 检查主播名称或等待开播 |
| `target_live_room_not_matched` | 进入的直播间不是目标 | 调整关键词并重试 |
| `search_network_retry_failed` | 搜索页网络异常 | 检查手机网络后重试 |
| `permission_failed` | 手机权限没有通过 | 确认无障碍、悬浮窗、截图权限 |
| `unknown_overlay_blocked` | 未知弹窗阻断脚本 | 人工查看手机当前页面 |
| `risk_control` | 疑似平台风控 | 暂停任务并人工检查账号 |

## 9. 保留原则

1. UI 可以优化，但不能删除已验证的业务路径。
2. 采集记录和日志中心必须保留“手机 -> 日期 -> 明细”三层结构。
3. 任务调度和工作台主界面必须使用中文业务文案，直播评论不再作为独立导航页面。
4. 技术字段不删除，但默认放入详情、折叠区或日志中心。
5. 后台按钮必须能和命令、心跳、日志、执行记录对账。

## 10. 验收口径

1. 工作台能看到设备在线状态、配置同步、采集链路、日志同步、当前任务、最近心跳和常用操作。
2. 任务调度页无分配记录时仍显示手机清单和快捷分配。
3. 任务调度页可统一下发视频、直播和直播评论任务。
4. 采集记录和日志中心保留三层点击路径。
5. 日志中心默认显示功能状态和异常汇总，完整日志标签展示后台收到的完整内容。
6. 日志主表展示人能看懂的状态、环节、影响和建议。
7. 页面不出现主要英文技术字段作为运营主文案。
