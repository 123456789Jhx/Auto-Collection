# 商品卡直播评论方案

本文记录商品卡直播评论任务的第一版实现口径。该任务是独立的新链路，不复用旧的“搜索主播或直播间后评论”的 `live_comment` 执行流程。

> 当前定位：本文仍是线上第一版基线。`商品卡养号与直播评论组合任务方案.md` 和 `商品卡养号与直播评论后台改造方案.md` 只有在确认、开发、无评论灰度、真实评论风控和真机验收完成后，才替代本文的执行口径。

## 1. 功能定位

商品卡直播评论用于模拟从抖音商城商品卡进入相关直播间的浏览路径：

```text
打开抖音
-> 进入商城
-> 搜索商品关键词
-> 刷商品卡
-> 命中商品关键词和直播信号
-> 进入直播间
-> 随机评论数字或表情
-> 观看 15 分钟
-> 返回继续下一轮
```

第一版目标是跑通商品卡路径、字段化匹配、随机评论和观看停留，不做购买、加购、关注、私信或复杂话术生成。

## 2. 任务边界

| 项目 | 说明 |
|---|---|
| 执行入口 | 独立任务类型 `commerce_card_live_comment`，由任务调度页下发 |
| 代码隔离 | 使用 `commerce-card-live-runner.js`，不调用 `live-comment-runner.js` |
| 搜索入口 | 抖音商城/商品卡路径 |
| 匹配对象 | 商品卡、商品详情、直播入口和直播间可见文本 |
| 评论方式 | 随机数字或表情 |
| 真实互动 | 只允许评论，不允许购买、加购、关注或私信 |

## 3. 第一版配置

```js
// 存放在 p3ExtensionsConfig.commerceCardLiveComment 下
commerceCardLiveComment: {
  enabled: false,
  executeEnabled: false,
  manualExecutionApproved: false,
  searchKeywords: ["夏橙"],
  matchKeywords: ["秭归", "夏橙"],
  liveSignals: ["直播中", "讲解中", "主播讲解", "进入直播间", "正在直播"],
  scanMinutesPerRound: 15,
  watchMinutesPerLive: 15,
  maxRounds: 3,
  maxCommentsPerRoom: 1,
  commentPool: ["111", "666", "👍", "🌹", "😊"]
}
```

安全口径：

1. 手机本地默认关闭商品卡任务，避免误触发。
2. 只有后台下发 `commerce_card_live_comment` 且高级配置明确 `enabled=true` 时，才进入商品卡 runner。
3. 只有 `executeEnabled=true` 且 `manualExecutionApproved=true` 时才真实发送评论。
4. 未审批、重复直播间、发送失败都会写入直播评论动作审计记录。
5. 普通 `live` 任务永远只走普通直播采集，不因商品卡配置开启而抢占。

## 4. 字段化匹配

脚本不写死某个商品卡位置，而是把页面可见内容按字段思路处理：

| 字段 | 来源 | 当前作用 |
|---|---|---|
| `productTitle` | 商品卡标题或可见文本 | 匹配 `秭归`、`夏橙` |
| `productSubtitle` | 商品卖点或副标题 | 辅助匹配 |
| `shopName` | 店铺或账号名称 | 当前仅作为文本样本记录 |
| `liveBadgeText` | 直播中、讲解中、主播讲解等 | 判断是否可进入直播 |
| `screenText` | 当前屏幕可见文本 | 兜底匹配 |
| `liveRoomText` | 进入直播间后的可见文本 | 二次校验 |

命中条件：

1. 当前商品卡或详情页文本命中 `秭归` 或 `夏橙`。
2. 当前页面同时出现直播信号。
3. 点击进入后，直播间页面仍能命中 `秭归` 或 `夏橙`。

不满足二次校验时不评论，返回继续扫描或结束。

## 5. 执行流程

每轮流程：

```text
进入商城
-> 搜索“夏橙”
-> 最多刷 15 分钟商品卡
-> 找到命中“秭归/夏橙”且有直播信号的卡片
-> 进入直播间
-> 二次校验关键词
-> 随机发送一条评论
-> 观看 15 分钟
-> 退出直播间
```

循环规则：

1. 最多执行 3 轮。
2. 任意一轮 15 分钟内没刷到匹配直播，则正常结束任务，不继续刷。
3. 收到 STOP、PAUSE、退出请求时，当前轮中断并上报原因。
4. 遇到验证码、账号异常、访问过频等风险文本，立即停止。

## 6. 日志事件

关键日志阶段：

| 阶段 | 含义 |
|---|---|
| `commerce_card_live_start` | 商品卡直播评论任务启动 |
| `commerce_card_scan_start` | 开始一轮商品卡扫描 |
| `commerce_card_live_comment_send` | 准备发送随机评论 |
| `commerce_card_live_comment_result` | 评论发送结果 |
| `commerce_card_live_watch` | 进入 15 分钟观看 |
| `commerce_card_live_finish` | 任务正常结束 |

常见结束原因：

| 原因 | 含义 |
|---|---|
| `commerce_card_live_rounds_finished` | 完成 3 轮 |
| `commerce_live_not_found` | 当前轮 15 分钟内没找到匹配直播 |
| `commerce_search_failed` | 商城商品搜索失败 |
| `commerce_live_room_not_matched` | 进房后二次校验失败 |
| `manual_pause` | 后台或本地暂停 |
| `manual_stop` | 后台或本地停止 |
| `risk_control` | 风控或验证码 |

## 7. 当前不做

1. 不购买、不加购物车。
2. 不关注主播或店铺。
3. 不私信、不跳外部联系方式。
4. 不使用 AI 生成评论。
5. 不复用旧直播评论的目标主播搜索链路。
6. 不复用普通 `live` 任务，不通过普通直播流兜底进入商品卡直播。

## 8. 第二版替代条件

第二版组合任务不得只因为后台能保存 `configVersion=2` 配置就替代第一版。替代前必须同时满足：

1. 后台完成第二版结构化配置、严格校验、阶段化表单和预览。
2. START 创建同一 `assignment`，并冻结 `selectedTargetId`、`targetCode`、`configRevision`、`configHash` 和完整配置快照。
3. PAUSE、RESUME、STOP 不创建新运行，命令回执和业务终态分开记录。
4. 手机端支持 checkpoint v2，恢复时能校验 assignment、阶段、配置哈希和未确认副作用。
5. 设备能力、版本、allowlist 和 `commerceCardWorkflowV2Enabled` 门禁全部通过。
6. 真实评论开启前完成服务端幂等预占、唯一幂等键、动作状态、审批哈希、审批有效期和全局急停。
7. 关闭 V2 或真实评论开关时，在途任务能停止并保留审计，不把 V2 checkpoint 交给第一版 runner。

## 9. 验收口径

1. 后台下发 `commerce_card_live_comment` 时进入 `commerce-card-live-runner.js`。
2. 每轮最多扫描 15 分钟商品卡。
3. 命中 `秭归/夏橙` 且有直播信号后进入直播间。
4. 每个直播间默认只随机评论 1 条数字或表情，按 `maxCommentsPerRoom` 控制。
5. 每个命中直播间观看 15 分钟。
6. 最多循环 3 轮。
7. 首轮或任意一轮没有刷到匹配直播时正常结束。
8. STOP/PAUSE/风控能中断，不继续搜索、点击或评论。
9. 后台未开启或未审批时，不真实发送评论，只记录跳过原因。
10. 普通 `live` 任务不会调用商品卡 runner，旧 `live_comment` 仍只走搜索目标直播间评论。
11. 第二版未满足替代条件前，本文第一版仍是线上执行口径。
