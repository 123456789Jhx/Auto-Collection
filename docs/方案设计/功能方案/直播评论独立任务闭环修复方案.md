# 直播评论独立任务闭环修复方案

## 背景结论

当前问题不是单纯的“直播卡片识别不准”，而是直播评论任务的功能边界没有彻底拆开。

现有代码已经有 `video`、`live`、`live_comment` 三种任务状态，但 `live_comment` 的执行层仍复用普通直播流程。这样会导致三个结果：

- 搜索目标直播间失败后，任务可能继续走普通直播入口或错误兜底。
- 进入的直播间没有被强校验为目标账号，就可能发送评论。
- 风控页、残留搜索词、错误页面没有在搜索阶段被明确中断，日志会把真实失败包装成后续点击失败。

后续修复必须把 `live_comment` 做成独立闭环任务：只找指定直播间，只在目标直播间评论，失败就退出抖音并上报明确原因。

## 已确认问题

### 1. 代码基线不一致

当前主线提交为 `c5c33d4 fix: 稳定直播入口识别链路`。

任务切换修复提交 `3e695db fix: stabilize backend task switching` 没有在当前主线里，存在于 `fix/task-switch-current` 和 `fix/live-entry-comment-current` 分支。

执行修复前必须先确认基线：

- 以包含 `3e695db` 的分支为准继续修复，或
- 将 `3e695db` 合入当前修复分支后再改代码。

不能在缺失任务切换修复的主线上继续叠直播评论修复。

### 2. 状态分离不等于行为分离

`task-scheduler.js` 里有独立的 `live_comment` 状态，但执行入口仍可能通过普通直播阶段运行。

必须禁止 `live_comment` 调用普通直播 runner，例如：

```js
phaseRunner.runPhase("live", ..., { taskType: "live_comment" })
```

`live_comment` 必须有自己的 runner，不能复用普通直播刷流逻辑。

### 3. 目标搜索没有硬校验

实测出现过任务目标是 `少东三农`，但手机搜索框仍停留在 `辣椒未来价格预测` 的情况。

这说明搜索输入、清空、提交、结果页确认之间缺少闭环校验。后续必须确认：

- 搜索框或结果页关键词已经变成当前任务目标。
- 页面没有停留在上一轮关键词。
- 没有进入推荐流、普通搜索残留页或错误账号页。

任何一步不满足，都要以明确失败原因停止。

### 4. 风控检测覆盖不足

实测出现过：

```text
您的访问被拒绝
操作过于频繁，请稍后再试
验证码
立即恢复
```

这类页面必须在搜索、点击、进房、评论前每个阶段识别为 `risk_control`，并立即停止任务。不能继续点击，也不能重试进房。

### 5. 日志验收口径错误

日志里出现 `DONE`、`comment_sent` 或点击成功，不等于直播评论链路成功。

直播评论任务成功必须同时满足：

- 搜索目标与任务目标一致。
- 进入的是目标账号的直播间。
- 评论只在目标直播间发送。
- 任务完成后退出抖音或回到脚本安全态。
- 后台任务状态、手机屏幕、ADB 观察三者一致。

## 修复目标

1. `video`、`live`、`live_comment` 三个功能执行层彻底隔离。
2. `live_comment` 只允许通过搜索目标账号或目标直播卡进入直播间。
3. 没有确认目标直播间前，不允许发评论。
4. 发生风控、目标不存在、搜索失败、进房失败时，停止任务并退出抖音。
5. 任务完成后不允许继续乱点，不允许继续刷普通视频或普通直播。

## 执行边界

### 普通视频任务

- 允许刷视频。
- 允许执行视频任务自己的交互。
- 不允许调用直播评论 runner。

### 普通直播任务

- 允许进入普通直播流。
- 允许按普通直播规则停留、切换、退出。
- 不允许读取直播评论目标账号。
- 不允许发送直播评论任务的评论内容。

### 直播评论任务

- 必须有目标账号或目标直播间关键词。
- 必须独立运行 `live_comment` runner。
- 只允许搜索目标、识别目标直播入口、进入目标直播间、验证目标、发送评论、退出。
- 不允许进入普通直播流兜底。
- 不允许向非目标直播间评论。

## 实施步骤

### 第一步：固定代码基线

1. 确认当前工作分支和提交。
2. 确认 `3e695db fix: stabilize backend task switching` 是否已经在当前修复分支。
3. 如果没有，先合入任务切换修复。
4. 记录最终用于打包的提交号。

验收标准：

- `git branch --contains 3e695db` 能覆盖当前修复分支。
- `live_comment`、`live`、`video` 在调度状态上互不覆盖。

### 第二步：新增直播评论独立 runner

建议新增或整理为：

```text
mobile-agent/autojs/app/live-comment-runner.js
```

核心入口：

```js
runTargetLiveCommentTask(taskContext)
```

这个 runner 只负责直播评论闭环：

1. 打开抖音。
2. 进入搜索。
3. 清空旧关键词。
4. 输入当前任务目标。
5. 提交搜索。
6. 校验搜索结果关键词。
7. 找目标直播入口。
8. 进入直播间。
9. 校验直播间属于目标账号。
10. 发送评论。
11. 上报结果。
12. 退出抖音。

### 第三步：改任务入口路由

`collector-app.js` 或同级任务入口必须改成：

```js
if (taskType === "live_comment") {
  return liveCommentRunner.runTargetLiveCommentTask(context);
}
```

禁止继续使用：

```js
phaseRunner.runPhase("live", ..., { taskType: "live_comment" })
```

普通直播任务继续走普通直播 runner，直播评论任务只能走独立 runner。

### 第四步：补齐搜索关键词硬校验

搜索阶段必须形成闭环：

1. 获取搜索框。
2. 清空搜索框。
3. 输入目标关键词。
4. 点击搜索。
5. 二次读取页面关键词或搜索框文本。
6. 确认当前页面属于本次目标。

失败原因要明确区分：

- `search_input_clear_failed`
- `search_keyword_set_failed`
- `target_search_open_failed`
- `search_keyword_mismatch`
- `search_result_stale`

只要发现页面仍是上一轮关键词，必须停止，不能继续点直播卡片。

### 第五步：直播入口识别规则

综合页里的直播入口优先级：

1. 用户区块里的账号头像或账号卡片带 `直播` 标识。
2. 用户区块下方的大直播卡片，右上角有 `直播中`。
3. 综合结果里的视频卡片，左上或右上角有 `直播中`。
4. 可见文本同时满足目标账号和直播标识的坐标区域。

点击前必须满足至少一个条件：

- 卡片或父区域文本包含目标账号。
- 卡片附近账号名等于目标账号。
- 搜索关键词与目标账号一致，且唯一可见直播卡片属于目标结果区域。

不能只因为看到 `直播中` 就点击。

### 第六步：进房后目标校验

进入直播间后必须采集页面文本或控件信息，确认至少一项：

- 主播名等于目标账号。
- 页面用户名、直播间标题、关注按钮附近文本包含目标账号。
- 直播间来源标记与刚点击的目标卡片绑定一致。

无法确认时：

- 不发评论。
- 截图或保存页面文本摘要。
- 上报 `target_room_verify_failed`。
- 退出抖音。

### 第七步：风控识别前置

以下阶段都必须调用风控检测：

- 打开抖音后。
- 打开搜索页后。
- 搜索提交后。
- 点击直播入口后。
- 评论输入前。
- 评论发送后。

命中以下文本时立即停止：

```text
访问被拒绝
操作过于频繁
验证码
立即恢复
账号异常
登录
安全验证
环境异常
```

统一上报：

```text
risk_control
```

### 第八步：任务结束动作

直播评论任务结束必须调用统一收尾：

1. 停止当前任务。
2. 上报最终状态。
3. 关闭或退出抖音。
4. 回到脚本等待态。

失败也要收尾，不能留在搜索页、直播间、设置页或推荐流继续点击。

## 测试方案

### 单机链路测试

先选一台已安装脚本的手机，后台依次发：

1. 视频任务。
2. 普通直播任务。
3. 直播评论任务。

ADB 只观察，不人工操作手机。

每一步记录：

- 当前任务 ID。
- 当前设备 ID。
- 后台任务类型。
- 手机前台页面。
- ADB 截图或 UI 文本摘要。
- 移动端日志关键事件。

### 三机回归测试

三台已安装 APP 的手机都要跑：

1. `video` 可以启动、执行、停止。
2. `live` 可以启动、执行、停止。
3. `live_comment` 可以搜索目标、进入目标直播间、评论或明确失败。
4. 每个任务结束后都退出抖音。
5. 任一设备出现风控时，只标记该设备风控，不影响其他设备。

### 验收标准

直播评论成功必须满足：

- 手机搜索框关键词等于当前目标。
- 搜索结果页能识别目标直播入口。
- 进入直播间后目标账号校验通过。
- 评论发送发生在目标直播间。
- 任务完成后抖音退出。

直播评论失败也算正确处理的情况：

- 目标没有直播：上报 `target_live_not_found`，退出抖音。
- 搜索词残留：上报 `search_keyword_mismatch` 或 `search_result_stale`，退出抖音。
- 风控：上报 `risk_control`，退出抖音。
- 目标校验失败：上报 `target_room_verify_failed`，退出抖音。

## 日志要求

直播评论 runner 必须输出以下关键事件：

```text
live_comment_start
search_opened
search_keyword_set
search_keyword_verified
target_live_entry_found
target_live_entry_clicked
target_room_verified
comment_input_ready
comment_sent
live_comment_finish
app_exit_done
```

失败日志必须带：

```text
task_id
device_id
target_name
stage
reason
screen_text_sample
```
