\# 远程脚本功能模块 · 分节点实施清单



> 目标项目：`Auto-Collection-main`（Bun + Hono API / React 19 + AntD Web / PostgreSQL + Drizzle / AutoX.js 移动端）

\## 一、模块整体架构



\### 1.1 模块定位



"远程脚本"是一个\*\*底层基座组件\*\*：把未来各类业务（发视频、直播互动、采集策略等）抽象为"脚本类型 + 配置实例"两层模型。新增一种业务 = 注册一个类型定义（含配置 Schema），无需改动表结构和页面骨架，即可获得完整的 CRUD、校验、审计与后续下发能力。

\### 1.3 配置数据结构与存储方案



存储：PostgreSQL（Drizzle ORM），沿用全项目约定（`tenant\_id` 多租户预留 + 审计列 + `deleted\_at` 软删除）。



\*\*表1：脚本类型定义 `remote\_script\_definitions`\*\*（基座注册表，代码维护、启动同步，不走 UI 编辑）



| 字段 | 类型 | 说明 |

|---|---|---|

| id | uuid pk | |

| script\_key | varchar(64) | 类型唯一键，如 `generic\_form`、未来的 `publish\_video` |

| name | varchar(100) | 显示名，如"发视频配置" |

| description | varchar(500) | 用途说明 |

| config\_schema | jsonb | 配置 Schema 子集（见 1.4），驱动 API 校验 + Web 动态表单 |

| status | varchar(32) | `ENABLED` / `DISABLED`，默认 ENABLED |

| + auditColumns | | tenant\_id / created\_at / updated\_at / created\_by / updated\_by / deleted\_at |



唯一约束：`(tenant\_id, script\_key) WHERE deleted\_at IS NULL`



\*\*表2：业务配置实例 `remote\_script\_configs`\*\*（UI CRUD 的核心对象）



| 字段 | 类型 | 说明 |

|---|---|---|

| id | uuid pk | |

| script\_key | varchar(64) | 逻辑关联 definitions.script\_key（同租户） |

| config\_name | varchar(100) | 配置名称，如"6月玉米发视频计划" |

| config\_payload | jsonb | 配置内容，按所属类型的 config\_schema 校验 |

| revision | integer | 每次保存 +1，默认 1（下发与缓存版本依据） |

| config\_hash | varchar(64) | sha256(script\_key + 规范化 payload + revision) |

| status | varchar(32) | `ENABLED` / `DISABLED`，默认 ENABLED |

| remark | varchar(500) | 备注 |

| + auditColumns | | 同上 |



唯一约束：`(tenant\_id, script\_key, config\_name) WHERE deleted\_at IS NULL`

索引：`(tenant\_id, script\_key, status)`、`(tenant\_id, created\_at)`



\*\*表3：设备绑定 `remote\_script\_device\_bindings`\*\*（阶段一下只建表，节点8 启用）



| 字段 | 类型 | 说明 |

|---|---|---|

| id | uuid pk | |

| config\_id | uuid fk → remote\_script\_configs.id | |

| device\_id | uuid fk → collector\_devices.id | |

| priority | integer | 默认 100，冲突时数值小者优先 |

| enabled | boolean | 默认 true |

| + auditColumns | | 同上 |



唯一约束：`(tenant\_id, config\_id, device\_id) WHERE deleted\_at IS NULL`



> 建表模板直接参照现有 `live\_targets` / `live\_target\_device\_bindings`（schema.ts 第 343-419 行），风格完全一致。



\### 1.4 配置 Schema 子集（关键架构决策）



为避免引入 ajv 等重依赖，定义一个 \*\*JSON Schema 子集\*\*，同一份 Schema 三处消费：



```json

{

&#x20; "type": "object",

&#x20; "properties": {

&#x20;   "keywords":   { "type": "array", "items": { "type": "string" }, "maxItems": 20, "description": "关键词" },

&#x20;   "titleTpl":   { "type": "string", "minLength": 1, "maxLength": 100, "description": "标题模板" },

&#x20;   "dailyLimit": { "type": "integer", "minimum": 1, "maximum": 50, "description": "每日上限" },

&#x20;   "mode":       { "type": "string", "enum": \["immediate", "scheduled"], "description": "发布方式" },

&#x20;   "enabled":    { "type": "boolean", "description": "是否启用" }

&#x20; },

&#x20; "required": \["keywords", "titleTpl"]

}

```



\- 支持的能力仅：`type(object/string/integer/number/boolean/array)`、`required`、`enum`、`minLength/maxLength`、`minimum/maximum`、`maxItems`、`description`（作为表单 label/校验提示）

\- API 侧用它做入参校验（节点4 实现约 100 行的校验器）；Web 侧用它渲染动态表单（节点7）；未来移动端可用它做配置生效前自检



\### 1.5 API 契约（Admin 域，全部过现有 admin-auth 中间件）



| 方法 | 路径 | 说明 |

|---|---|---|

| GET | `/api/v1/admin/remote-scripts/definitions` | 类型列表（含 schema） |

| GET | `/api/v1/admin/remote-scripts/configs?scriptKey=\&status=\&keyword=\&page=\&pageSize=` | 配置分页列表 |

| POST | `/api/v1/admin/remote-scripts/configs` | 新建配置 |

| GET | `/api/v1/admin/remote-scripts/configs/:id` | 配置详情 |

| PATCH | `/api/v1/admin/remote-scripts/configs/:id` | 更新（revision+1、重算 hash；支持仅改 status 做启停） |

| DELETE | `/api/v1/admin/remote-scripts/configs/:id` | 软删除 |



错误码沿用现有风格：`VALIDATION\_ERROR` / `NOT\_FOUND` / `CONFIG\_NAME\_CONFLICT` / `SCRIPT\_TYPE\_DISABLED` / `PAYLOAD\_SCHEMA\_MISMATCH`。
