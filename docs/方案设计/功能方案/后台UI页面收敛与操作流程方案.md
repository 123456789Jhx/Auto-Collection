# 后台 UI 页面收敛与操作流程方案

记录日期：2026-06-27

## 1. 文档目标

本文用于指导下一版后台 UI 调整，解决当前页面存在的信息重复、按钮过多、英文状态暴露、详情区域占屏和部分刷新控件干扰的问题。

本方案只定义前端页面结构、交互流程和展示口径。除非实现中发现接口缺失，否则不新增后端业务逻辑，不改变手机 Agent 的任务执行流程。

## 2. 设计原则

1. 保留原有业务路径，不因为 UI 改版改变数据查看和操作逻辑。
2. 页面文案全部面向运营人员，主界面不展示英文状态码。
3. 设备相关页面优先展示“设备是否正常、正在做什么、能操作什么”。
4. 详情信息通过右侧抽屉展示，不再常驻占据主页面宽度。
5. 常用操作按钮要少而明确，危险操作必须视觉上区分。
6. 直播评论页定位为“设备直播评论参数配置 + 直播评论操作”，不再承担日志或全局调度职责。

## 3. 变更范围

| 页面 | 本轮处理 |
|---|---|
| 工作台 | 调整为设备运行总览，展示所有设备信息和关键操作入口 |
| 设备运行 | 与工作台能力合并，不再做重复页面 |
| 任务调度 | 中文化、精简筛选和顶部按钮，重做操作按钮 |
| 直播评论 | 去掉自动刷新下拉，聚焦设备直播评论参数和操作 |

## 4. 不变范围

1. 采集记录继续保留“手机卡片 -> 日期卡片 -> 明细”的查看路径。
2. 日志中心继续保留“手机卡片 -> 日期卡片 -> 明细”的查看路径。
3. 不删除任务调度已有的切视频、切直播、切评论、停止能力。
4. 不把直播评论真实发送能力默认扩大，仍按配置和审计执行。
5. 不提交 `docs/项目开发/error` 和根目录临时截图。

## 5. 工作台与设备运行合并

### 5.1 页面定位

工作台调整为唯一的“设备运行总览页”。设备运行页与工作台功能重复，下一版可采用两种方式之一：

| 方案 | 说明 | 建议 |
|---|---|---|
| 隐藏设备运行导航 | 侧边栏只保留工作台 | 推荐，减少重复入口 |
| 保留设备运行导航 | 点击后进入同一个工作台页面 | 可作为过渡方案 |

推荐采用“隐藏设备运行导航”。如果担心用户习惯变化，可以先保留导航但指向同一组件。

### 5.2 页面结构

```text
顶部统计
设备运行看板
  左侧：设备卡片列表 / 紧凑表格合并视图
  右侧：无常驻详情
点击设备 -> 右侧设备详情抽屉
```

页面不再同时展示“设备卡片 + 右侧固定详情 + 需要处理表 + 大面积空白”。主页面只保留设备运行看板，详情进入抽屉。

### 5.3 顶部统计

| 指标 | 展示口径 |
|---|---|
| 设备总数 | 已接入后台的手机数量 |
| 在线设备 | 最近 3 分钟内有心跳 |
| 离线设备 | 超过心跳阈值或状态为离线 |
| 今日采集 | 视频和直播内容采集总数 |
| 今日异常 | 需要人工关注的设备或日志事件 |

### 5.4 设备运行看板

设备卡片和列表合并为一个视图。推荐使用“卡片式列表”：每个设备是一张横向卡片，在桌面端显示完整信息，在小屏幕下自动变成竖向卡片。

单个设备卡片包含：

| 信息 | 展示方式 |
|---|---|
| 设备名称 | 加粗展示 |
| 设备编号 | 小字展示 |
| 设备状态 | 标签：在线、运行中、待命、暂停、离线、异常 |
| 当前任务 | 视频、直播、直播评论、待命 |
| 心跳状态 | 加大加粗；离线、超时用橙红色；正常用绿色 |
| 最近消息 | 一句话展示最近心跳或任务反馈 |
| 视频进度 | 进度条 + 分钟 |
| 直播进度 | 进度条 + 分钟 |
| 今日数据 | 视频浏览、直播浏览、采集数 |

心跳展示规则：

| 状态 | 文案 | 样式 |
|---|---|---|
| 60 秒内 | `刚刚心跳` | 绿色、加粗 |
| 1-3 分钟 | `X 分钟前` | 绿色或蓝色、加粗 |
| 3-10 分钟 | `心跳超时 X 分钟` | 橙色、加粗 |
| 超过 10 分钟或离线 | `离线 X 分钟/小时` | 红色、加粗 |

### 5.5 设备详情抽屉

点击设备卡片或列表行后，从右侧弹出设备详情抽屉。抽屉宽度建议 420-520px，桌面端不遮挡左侧列表，移动端全屏。

抽屉内容：

| 区块 | 内容 |
|---|---|
| 设备基础信息 | 名称、编号、状态、版本、地区、备注 |
| 当前任务 | 当前任务、最近心跳、最近消息、任务状态 |
| 今日进度 | 视频分钟、直播分钟、采集数、进度条 |
| 最近 7 天 | 每天视频/直播/采集和异常状态 |
| 最近日志 | 最近 5-10 条运行日志摘要 |
| 处理建议 | 离线、权限、风控、目标直播间未找到等建议 |
| 操作按钮 | 启动、暂停、恢复、停止、刷新配置、查看日志、查看采集记录 |

详情抽屉按钮规则：

1. 主操作只保留一个高亮按钮，例如“启动/继续”。
2. 暂停、恢复、刷新配置使用普通按钮。
3. 停止使用红色危险按钮。
4. 查看日志、查看采集记录是跳转类按钮，不和控制按钮混在一组。

## 6. 任务调度中心调整

### 6.1 页面定位

任务调度中心只回答三件事：

1. 每台设备现在被安排做什么。
2. 手机实际有没有按安排执行。
3. 用户能快速切到视频、直播、直播评论或停止。

### 6.2 删除和保留

删除：

| 当前内容 | 处理 |
|---|---|
| 顶部“只读推荐” | 删除 |
| 顶部“手动分配” | 删除 |
| 筛选区“设备分组” | 删除 |
| 筛选区“应用筛选” | 删除，筛选条件变更后自动生效 |
| 文案“期望任务” | 删除或改为“任务安排” |
| 英文状态 | 全部改成中文 |

保留：

| 当前内容 | 处理 |
|---|---|
| 刷新 | 保留在右上角 |
| 设备搜索 | 保留 |
| 任务筛选 | 保留，但改中文 |
| 状态筛选 | 保留，但改中文 |
| 切视频/切直播/切评论/停止 | 保留并重做按钮样式 |

### 6.3 顶部统计

| 当前文案 | 新文案 |
|---|---|
| 在线设备 | 在线设备 |
| 期望运行 | 已安排任务 |
| 任务一致 | 执行一致 |
| 待确认 | 等待确认 |
| 异常 | 异常设备 |

### 6.4 筛选区

筛选区只保留三项：

| 字段 | 控件 | 说明 |
|---|---|---|
| 设备搜索 | 输入框 | 搜设备名称、设备编号 |
| 任务类型 | 下拉 | 全部、视频、直播、直播评论、待命 |
| 调度状态 | 下拉 | 全部、待下发、已下发、等待确认、执行中、已暂停、已停止、失败 |

筛选条件变更后立即生效，不需要“应用筛选”按钮。

### 6.5 主表字段

| 列名 | 内容 |
|---|---|
| 设备 | 设备名称、设备编号、心跳状态 |
| 任务安排 | 后台安排任务 + 手机实际任务 |
| 状态 | 中文调度状态 |
| 最近命令 | 命令类型、时间、回执状态 |
| 操作 | 切视频、切直播、切评论、停止 |

不再展示 `priority manual`、`STOP / PENDING` 这类英文组合。调度原因和优先级放入详情抽屉或小字中文说明。

### 6.6 操作按钮设计

操作按钮采用紧凑按钮组：

```text
[视频] [直播] [评论] [停止]
```

按钮规则：

| 按钮 | 文案 | 样式 |
|---|---|---|
| 切视频 | 视频 | 蓝色描边或浅蓝底 |
| 切直播 | 直播 | 绿色描边或浅绿底 |
| 切评论 | 评论 | 紫色描边或浅紫底 |
| 停止 | 停止 | 红色描边或浅红底 |

点击按钮后直接对当前设备下发对应调度，不再要求先点击顶部“手动分配”。

### 6.7 中文状态映射

| 原状态 | 页面文案 |
|---|---|
| `PENDING` | 待下发 |
| `ISSUED` | 已下发 |
| `ACKED` | 手机已确认 |
| `ACTIVE` | 执行中 |
| `PAUSED` | 已暂停 |
| `STOPPED` | 已停止 |
| `SUPERSEDED` | 已被新任务替换 |
| `EXPIRED` | 已过期 |
| `FAILED` | 失败 |

命令状态映射：

| 原状态 | 页面文案 |
|---|---|
| `PENDING` | 等待领取 |
| `SENT` | 手机已领取 |
| `ACKED` | 手机已回执 |
| `DONE` | 执行完成 |
| `FAILED` | 执行失败 |
| `EXPIRED` | 已过期 |

### 6.8 详情抽屉

点击设备行打开调度详情抽屉，不再让右侧固定详情长期占屏。

抽屉内容：

| 区块 | 内容 |
|---|---|
| 设备概况 | 名称、编号、心跳、当前状态 |
| 任务安排 | 后台安排、手机实际、目标上下文 |
| 调度原因 | 为什么切换、来源、最近命令 |
| 中文时间线 | 创建任务、下发命令、手机确认、执行完成 |
| 技术详情 | assignmentId、commandId、payload，默认折叠 |

时间线中文化：

| 当前文案 | 新文案 |
|---|---|
| `PLANNED` | 创建任务 |
| `DISPATCHED` | 下发命令 |
| `ACK / RUNNING` | 手机确认 / 执行中 |
| `COMPLETED` | 执行完成 |

## 7. 直播评论页面调整

### 7.1 页面定位

直播评论页面只做两类事情：

1. 修改每台设备的直播评论参数。
2. 对每台设备的直播评论任务进行启动、暂停、恢复、停止、刷新配置等操作。

该页面不承担全局任务调度，不展示过多日志明细。

### 7.2 删除和保留

删除：

| 当前内容 | 处理 |
|---|---|
| `15秒刷新` 下拉 | 删除 |
| 自动刷新说明 | 删除 |
| 与参数配置无关的复杂筛选 | 收敛或删除 |

保留：

| 内容 | 处理 |
|---|---|
| 手动刷新 | 保留一个普通按钮 |
| 批量操作 | 可保留，但默认不突出 |
| 设备列表 | 保留 |
| 设备直播评论参数 | 强化为核心区域 |
| 启动、暂停、恢复、停止、刷新配置 | 保留 |

### 7.3 页面结构

推荐结构：

```text
顶部统计
设备直播评论列表
点击设备 -> 右侧参数抽屉
```

如果不使用抽屉，也可以用左右布局：

```text
左侧：设备列表
右侧：参数配置 + 操作按钮
```

考虑当前页面宽度和信息密度，推荐使用右侧抽屉，主页面保持列表清爽。

### 7.4 顶部统计

| 指标 | 说明 |
|---|---|
| 总设备 | 可配置直播评论的设备数 |
| 已计划 | 已生成评论计划数 |
| 已发送 | 手机已执行发送数 |
| 跳过 | 规则判断不适合发送 |
| 失败 | 需要排查账号或直播间的问题 |

### 7.5 设备直播评论列表

列表字段：

| 列名 | 内容 |
|---|---|
| 设备 | 名称、编号、心跳 |
| 评论模式 | 关闭、指定直播间、账号机器人 |
| 配置来源 | 公共模板、设备单独配置 |
| 执行状态 | 计划、发送、跳过、失败 |
| 最近执行 | 时间 + 简短结果 |
| 操作 | 参数、启动、停止 |

### 7.6 参数抽屉

点击“参数”或设备行打开抽屉。抽屉分为 5 个区块：

| 区块 | 字段 |
|---|---|
| 评论模式 | 关闭、指定直播间、账号机器人 |
| 指定直播间 | 直播间名称、主播名、搜索关键词、别名 |
| 评论策略 | 话术、发送间隔、最大发送数、评论上限 |
| 风控限制 | 是否允许真实发送、失败后是否停止、冷却时间 |
| 账号画像 | 地区、身份、农产品、备注 |

按钮：

| 按钮 | 说明 |
|---|---|
| 保存参数 | 保存当前设备直播评论配置 |
| 启动评论 | 下发启动或切评论任务 |
| 暂停 | 暂停当前评论任务 |
| 恢复 | 恢复暂停任务 |
| 停止 | 停止当前评论任务 |
| 刷新配置 | 让手机重新拉取最新配置 |

### 7.7 操作边界

1. 保存参数只修改设备直播评论配置，不自动启动任务。
2. 启动评论才触发设备执行。
3. 停止必须是危险按钮。
4. 批量操作必须有明确选中设备，不允许默认全选执行。
5. 真实发送相关开关必须在参数区明确展示。

## 8. 路由和导航建议

推荐导航：

```text
工作台
任务调度
直播评论
采集记录
日志中心
配置
```

可选过渡导航：

```text
工作台
设备运行
任务调度
直播评论
采集记录
日志中心
配置
```

过渡情况下，`设备运行` 与 `工作台` 指向同一个设备总览组件。

| 组件 | 用途 |
|---|---|
| `DeviceOverviewPage` | 工作台和设备运行合并后的主页面 |
| `DeviceRunCard` | 单设备运行卡片 |

## 10. 接口影响

第一版优先复用现有接口。

| 页面 | 现有接口 |
|---|---|
| 工作台/设备总览 | `/admin/overview`、`/admin/devices`、设备进度接口、日志摘要接口 |
| 任务调度 | `/admin/task-assignments`、`POST /admin/task-assignments`、`/admin/devices` |
| 直播评论 | `/admin/live-comment-device-summary`、`/admin/live-comment-actions`、`/admin/devices/:deviceCode/task-config`、`POST /admin/mobile-commands` |

如果实现设备详情抽屉时发现需要一次性聚合设备详情，可以后续新增只读聚合接口，但不作为本轮必要条件。

## 11. 实施顺序

1. 工作台和设备运行合并，先完成设备卡片、心跳醒目展示和右侧详情抽屉。
2. 任务调度中心中文化，删除多余按钮和筛选，重做操作按钮。
3. 直播评论页面删除自动刷新下拉，改成设备参数配置和设备操作为主。
4. 对桌面端和移动端截图验收，确认文字不挤压、按钮不换行错乱。
5. 线上部署后逐页确认原有控制功能仍可用。

## 12. 验收标准

### 12.1 工作台/设备运行

1. 心跳状态醒目，离线和超时一眼可见。
2. 设备卡片能展示状态、任务、进度、今日数据和最近消息。
3. 点击设备后右侧弹出详情抽屉。
4. 抽屉里能看到最近 7 天、最近日志和常用操作。
5. 设备运行不再和工作台重复展示两套相似页面。

### 12.2 任务调度

1. 页面主文案全部中文。
2. 不出现 `PENDING`、`STOPPED`、`PLANNED`、`DISPATCHED` 等英文状态。
3. 顶部只保留刷新，不再出现只读推荐和手动分配。
4. 筛选区无设备分组、无应用筛选按钮。
5. 操作区只保留视频、直播、评论、停止这类用户能理解的按钮。

### 12.3 直播评论

1. 页面不再出现 15 秒刷新下拉。
2. 页面核心是设备直播评论参数配置。
3. 每台设备能保存参数，并能启动、暂停、恢复、停止、刷新配置。
4. 真实发送和风控限制在参数区明确展示。
5. 批量操作不会误操作未选设备。

## 13. 暂不处理内容

1. 不重做采集记录和日志中心的三层查看路径。
2. 不新增复杂调度策略。
3. 不改手机端任务执行状态机。
4. 不做设计稿切图或营销式页面。
5. 不把临时截图作为正式证据提交。
