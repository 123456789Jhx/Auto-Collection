## 2. 结论

会议里的“直播视频脚本”不是单一脚本，至少应拆成三条线：

1. 视频浏览采集脚本：当前项目已有主线，手机自动浏览公开视频/直播，识别农业内容，采集 OCR、截图、评论、指标文本并上传后台。
2. 短视频发布脚本：会议新增方向，用手机账号发布 AI 混剪后的短视频，不优先走电脑端或官方 API。
3. 直播辅助脚本：会议新增方向，先做直播观察、数据记录、话术/场控提示，不默认自动评论、点赞、关注或私信。

当前代码和当前有效需求主要覆盖第 1 条。第 2、第 3 条是新增业务方向，需要作为后续模块单独立项，不能直接塞进现有采集脚本里。

## 3. 视频浏览采集脚本

### 3.1 当前定位

手机端是采集执行器，负责在抖音等短视频平台浏览公开可见农业内容，提取候选视频/直播信息，并把证据上传到轻量后台。

第一阶段不做官方 API、AI 审核入库、完整素材库、知识库，也不做自动点赞、评论、关注、私信。

### 3.2 核心流程

1. 启动脚本。
2. 检查无障碍、悬浮窗、截图、网络权限。
3. 优先从后台拉取任务配置，失败时读取本地 `config.js`。
4. 打开抖音，进入推荐流或搜索结果流。
5. 停留当前视频，截图并 OCR。
6. 合并 OCR 文本和可见控件文本。
7. 用农业关键词判断是否命中。
8. 命中后采集标题、字幕、作者、可见互动指标、热门评论、截图证据。
9. 写入本地 JSON 缓存。
10. 按配置上传采集记录、心跳和运行日志。
11. 到达上限或人工停止后结束任务。

### 3.3 任务配置字段

当前方案中脚本需要支持这些配置：

| 字段 | 含义 |
|---|---|
| `taskId` | 任务 ID |
| `platform` | 平台，第一阶段为 `douyin` |
| `mode` | `search` 或 `feed` |
| `keywords` / `searchKeywords` | 搜索词 |
| `matchKeywords` | 农业命中关键词 |
| `maxVideos` | 单次最多浏览视频数 |
| `maxCaptures` | 单次最多采集候选数 |
| `staySecondsMin` | 每条视频最短停留秒数 |
| `staySecondsMax` | 每条视频最长停留秒数 |
| `collectComments` | 是否采集热门评论 |
| `commentLimit` | 单条视频最多评论数 |
| `uploadEnabled` | 是否上传后台 |
| `uploadUrl` | 采集记录上传接口 |
| `heartbeatUrl` | 心跳上传接口 |
| `logUrl` | 日志上传接口 |
| `cacheDir` | 本地缓存目录 |

### 3.4 采集记录字段

| 字段 | 含义 |
|---|---|
| `taskId` | 任务 ID |
| `deviceId` | 手机设备 ID |
| `platform` | 平台 |
| `sceneType` | `video` 或 `live` |
| `keyword` | 当前搜索词 |
| `matchedKeywords` | 命中的农业关键词 |
| `screenText` | 当前屏幕 OCR 全文 |
| `titleText` | 标题或画面主文案 |
| `subtitleText` | 字幕文本 |
| `authorName` | 作者名称 |
| `metricsText` | 点赞、评论、收藏、分享等可见文本 |
| `hotComments` | 热门评论列表 |
| `screenshotFiles` / `screenshotFileIds` | 视频页、评论页证据截图 |
| `capturedAt` | 手机端采集时间 |
| `rawPayload` | 完整原始上报内容 |

### 3.5 运行状态

当前文档中出现的状态可以统一收敛为：

`INIT` -> `PERMISSION_CHECK` -> `LOAD_TASK` -> `OPEN_PLATFORM` -> `ENTER_FLOW` -> `WATCHING` -> `OCR_READING` -> `EVALUATING` -> `CAPTURING` -> `SAVING` -> `UPLOADING` -> `NEXT` -> `STOPPED`

异常恢复使用 `RECOVERING`，遇到验证码、登录异常、风控、权限缺失时停止自动化并上报。

## 4. 短视频发布脚本

### 4.1 会议新增目标

短视频业务目标是把真实农业素材通过 AI 混剪生成短视频，再由手机端账号发布，用发布后的数据验证流量提升。

会议中明确的信息：

1. 第一阶段使用现有 5 台已绑定手机和账号。
2. 每台手机每天先发 5 条视频，总量约 25 条/天。
3. 单账号每天发布上限建议控制在 5-10 条，避免超过后不推荐。
4. 单条视频长度优先 15-30 秒。
5. 发布方式优先使用手机脚本，不优先使用电脑端或官方 API，因为手机发布更接近真实用户行为。
6. 先跑通从素材采集、AI 生成、手机发布、数据回收到复盘的闭环。

### 4.2 上游素材要求

1. 村民只拍真实田间、劳动、农货、农场景素材。
2. 不要求村民拍剧情，不要求村民口播。
3. 素材可以通过企业微信群进入素材池。
4. 后台需要对素材自动抓取、分类和管理。
5. AI 负责生成解说、混剪、字幕或成片。

### 4.3 发布任务建议字段

后续新增短视频发布脚本时，建议任务字段独立于当前采集任务：

| 字段 | 含义 |
|---|---|
| `publishTaskId` | 发布任务 ID |
| `deviceId` | 指定发布手机 |
| `accountId` | 发布账号 |
| `platform` | 平台，第一阶段为 `douyin` |
| `videoFile` | 待发布视频文件 |
| `coverFile` | 封面文件，可选 |
| `caption` | 发布文案 |
| `hashtags` | 话题标签 |
| `scheduledAt` | 计划发布时间 |
| `publishMode` | 手动确认、半自动或自动 |
| `status` | `pending`、`publishing`、`published`、`failed`、`cancelled` |
| `failureReason` | 失败原因 |
| `evidenceScreenshots` | 发布过程证据截图 |
| `publishedAt` | 实际发布时间 |
| `platformPostId` | 平台侧作品标识，能识别则记录 |

### 4.4 发布脚本验收建议

1. 单台手机可以领取一个待发布视频任务。
2. 脚本能把视频、文案、话题带到发布流程。
3. 发布成功后能回传状态、时间、截图证据。
4. 发布失败时能记录失败页 OCR、截图和原因。
5. 遇到登录、验证码、风控、权限弹窗时停止自动化并等待人工处理。
6. 5 台手机能完成每天 25 条的低频发布测试。

## 5. 发布后数据采集

会议要求发布后看效果，不只看是否发布成功。

需要采集的数据包括：

1. 播放量。
2. 3 秒跳出或 3 秒留存相关指标。
3. 点赞数。
4. 收藏数。
5. 评论数。
6. 观众标签或用户画像。
7. 咨询线索或转化线索，若平台页面可见。

这部分应作为“创作者中心/后台数据采集”单独设计。它不是当前视频浏览采集脚本的同一件事，也不应混用 `collection_record` 作为唯一数据表。

建议新增对象：

| 对象 | 用途 |
|---|---|
| `published_video` | 记录已发布作品 |
| `creator_metric_snapshot` | 定时记录作品数据快照 |
| `publish_account` | 记录账号、设备、平台和运行状态 |
| `publish_task` | 记录待发布和已发布任务 |

## 6. 直播辅助脚本

### 6.1 会议新增目标

直播方向不是先做全自动直播运营，而是先观察现有直播过程，找单点优化，再用工具辅助中控和主播。

会议中明确的信息：

1. 直播比短视频更复杂，因为主播动作不可控。
2. 先参考成熟直播间，例如“明明在助农”。
3. 先观察现有直播流程，再做单点优化。
4. 可优化方向包括挂人提升在线人数、背景、灯光、场控、话术提示。
5. AI 可以辅助场控和话术，但仍保留人工中控。
6. 对直播效果的目标是提升在线、互动和成交，但具体结果由运营执行共同决定。
7. 技术团队当前不承诺完整代运营，只提供工具和可执行优化方向。

### 6.2 当前可落地范围

P0 只做只读观察：

1. 进入公开直播间。
2. 读取直播间状态、在线人数等可见指标。
3. 采样公开可见评论。
4. 记录主播、商品、话题、用户反馈等可见文本。
5. 上传直播观察记录、截图、心跳和日志。

P1 做辅助提示：

1. 对评论做分类和去重。
2. 提取高频问题。
3. 生成场控待处理问题列表。
4. 生成话术建议或提醒。
5. 记录人工是否采纳。

P2 才考虑有限动作：

1. 任何真实评论发送、点赞、关注、挂人、互动动作都必须单独评审。
2. 必须有冷却、频控、人工确认、审计记录和一键停止。
3. 默认不自动执行。

### 6.3 直播观察记录建议字段

| 字段 | 含义 |
|---|---|
| `liveSessionId` | 直播观察会话 ID |
| `deviceId` | 观察手机 |
| `accountId` | 账号 |
| `platform` | 平台 |
| `anchorName` | 主播或账号名称 |
| `roomTitle` | 直播间标题 |
| `onlineCountText` | 可见在线人数文本 |
| `metricsText` | 点赞、互动、成交等可见指标文本 |
| `commentSamples` | 评论采样 |
| `highFrequencyQuestions` | 高频问题 |
| `suggestedTalkingPoints` | 建议话术 |
| `operatorAction` | 人工中控处理记录 |
| `screenshotFiles` | 证据截图 |
| `observedAt` | 观察时间 |
| `rawPayload` | 原始上报 |

## 7. 明确不做

1. 不绕过验证码、登录校验、平台风控。
2. 不采集非公开内容。
3. 不承诺平台账号标签、推荐标签或官方流量结果。
4. 当前采集脚本不自动点赞、评论、关注、私信。
5. 当前采集脚本不承担短视频发布功能。
6. 当前直播辅助不默认执行真实互动。
7. 不把直播代运营结果承诺写成技术验收。

## 8. 建议实施顺序

1. 保持当前视频浏览采集脚本主线稳定，完成任务配置、OCR、截图、评论采集、心跳、日志、后台上报。
2. 单独设计短视频发布任务模型，不复用采集任务模型硬塞发布字段。
3. 先做人工确认版发布脚本，跑通单台手机单条视频发布。
4. 扩展到 5 台手机、每天 25 条视频的低频发布测试。
5. 单独设计发布后数据采集，采集创作者中心可见指标并形成数据快照。
6. 直播先做只读观察和评论采样，再做场控提示。
7. 涉及直播真实互动、自动评论、点赞、关注时另开评审和验收。

## 9. 待确认问题

1. “直播视频脚本”最终是指手机自动化脚本，还是指直播间主播话术脚本，或两者都要。
2. 短视频发布是否允许全自动点击发布，还是必须保留人工确认。
3. 发布内容的文案、话题、封面由哪个模块生成，手机端是否只消费最终结果。
4. 创作者中心数据是否通过手机端读取，还是由人工导出或后台脚本采集。
5. 直播辅助是否只做提示，是否允许任何形式的自动互动。
6. 5 台手机对应账号、平台、素材来源、每日发布时间段是否已固定。
