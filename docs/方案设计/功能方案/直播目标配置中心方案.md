# 直播目标配置中心方案

## 1. 方案目标

本方案用于把“搜索直播评论”和“商品卡直播评论”的目标配置从分散 JSON 升级为独立配置中心。

目标是让后台可以按功能维护搜索词、目标直播间、直播间名称映射、商品卡关键词、执行参数和真实评论开关；手机端只消费后端整理后的结构化配置，不再要求运营手填 JSON。

用户已确认采用方案 B：新增数据库表和接口管理配置，不继续只依赖 `liveCommentBotConfig.targetRoom` 和 `p3ExtensionsConfig.commerceCardLiveComment`。

## 2. 当前现状

| 模块 | 当前配置位置 | 当前问题 |
|---|---|---|
| 搜索直播评论 | `liveCommentBotConfig.targetRoom.searchKeywords/matchKeywords` | 能区分搜索词和匹配词，但只有简化弹窗，不能管理多个目标直播间和相似度规则 |
| 商品卡直播评论 | `p3ExtensionsConfig.commerceCardLiveComment` | 主要藏在高级 JSON 中，运营不可视化配置成本高 |
| 手机端搜索直播间 | `openTargetLiveRoomFromSearch` | 已能按搜索词搜索并校验目标词，但目标名称映射不够结构化 |
| 手机端商品卡 | `openMatchingCommerceLiveFromCards` | 已能按商品关键词和直播信号进入直播，但缺少目标直播间映射和相似度准入 |

## 3. 设计原则

1. 搜索词和目标直播间名称必须分离。
2. 后台配置的目标直播间名称是业务标准名，不要求直接作为抖音搜索词。
3. 直播间卡片名称与后台目标名称或别名相似度达到 `0.90` 及以上即可进入，不要求 100% 一致。
4. 商品卡直播评论和搜索直播评论共用目标直播间配置，但执行参数分开。
5. 真实评论必须继续保留 `executeEnabled` 和 `manualExecutionApproved` 双开关。
6. 旧 JSON 配置在过渡期只做兼容读取，不作为主要配置入口。

## 4. 核心对象

### 4.1 直播目标组

直播目标组用于表示一组业务目标，例如“秭归夏橙直播间”。

| 字段 | 说明 |
|---|---|
| `targetCode` | 稳定编码，例如 `zigui_xiacheng` |
| `targetName` | 后台展示标准名，例如 `秭归夏橙直播间` |
| `platform` | 当前为 `douyin` |
| `enabled` | 是否启用 |
| `similarityThreshold` | 默认 `0.90` |
| `remark` | 运营备注 |

### 4.2 目标名称别名

别名用于适配抖音卡片、直播间标题、主播名和商品卡上的不同展示。

| 字段 | 说明 |
|---|---|
| `targetId` | 所属直播目标 |
| `aliasText` | 直播间名称、主播名、卡片标题片段 |
| `aliasType` | `room_name`、`anchor_name`、`card_title`、`product_text` |
| `weight` | 命中权重，第一版只用于排序 |
| `enabled` | 是否启用 |

### 4.3 功能搜索配置

功能搜索配置用于区分不同任务入口。

| 字段 | 说明 |
|---|---|
| `featureType` | `live_comment` 或 `commerce_card_live_comment` |
| `targetId` | 关联直播目标 |
| `searchKeywords` | 抖音搜索词或商城搜索词 |
| `requiredKeywords` | 可选强制关键词，第一版默认不强制 |
| `forbiddenKeywords` | 禁入词，例如 `回放`、`录播`、`已结束` |
| `enabled` | 是否启用 |

### 4.4 商品卡执行配置

商品卡执行配置只服务 `commerce_card_live_comment`。

| 字段 | 说明 |
|---|---|
| `targetId` | 关联直播目标 |
| `productKeywords` | 商品卡匹配词，例如 `夏橙`、`秭归` |
| `liveSignals` | 直播信号，例如 `直播中`、`讲解中`、`进入直播间` |
| `scanMinutesPerRound` | 每轮刷商品卡分钟数，默认 15 |
| `watchMinutesPerLive` | 命中后观看分钟数，默认 15 |
| `maxRounds` | 最大循环次数，默认 3 |
| `maxCommentsPerRoom` | 每个直播间评论上限，默认 1 |
| `commentPool` | 随机评论池 |
| `executeEnabled` | 是否允许真实发送 |
| `manualExecutionApproved` | 是否人工确认真实发送 |

### 4.5 设备绑定

设备绑定用于决定某台设备使用哪些目标规则。

| 字段 | 说明 |
|---|---|
| `deviceId` | 可为空；为空表示任务级默认配置 |
| `targetId` | 绑定直播目标 |
| `featureType` | `live_comment` 或 `commerce_card_live_comment` |
| `priority` | 多目标时的顺序 |
| `enabled` | 是否启用 |

## 5. 数据库设计

第一版新增四张表：

1. `live_targets`
2. `live_target_aliases`
3. `live_target_feature_configs`
4. `live_target_device_bindings`

如果商品卡字段过多，可以在 `live_target_feature_configs` 中使用少量 JSON 字段保存数组类配置，例如 `search_keywords`、`product_keywords`、`live_signals`、`comment_pool`。但目标、别名、设备绑定必须是独立表，避免继续把核心关系藏在 JSON 中。

建议字段：

| 表 | 关键字段 |
|---|---|
| `live_targets` | `id`、`tenant_id`、`target_code`、`target_name`、`platform`、`similarity_threshold`、`enabled`、审计字段 |
| `live_target_aliases` | `id`、`target_id`、`alias_text`、`alias_type`、`weight`、`enabled`、审计字段 |
| `live_target_feature_configs` | `id`、`target_id`、`feature_type`、`search_keywords`、`required_keywords`、`forbidden_keywords`、`product_keywords`、`live_signals`、`runtime_config_json`、`enabled`、审计字段 |
| `live_target_device_bindings` | `id`、`device_id`、`target_id`、`feature_type`、`priority`、`enabled`、审计字段 |

唯一约束：

1. `live_targets(tenant_id, platform, target_code)` 唯一。
2. `live_target_aliases(tenant_id, target_id, alias_text, alias_type)` 唯一。
3. `live_target_feature_configs(tenant_id, target_id, feature_type)` 唯一。
4. `live_target_device_bindings(tenant_id, device_id, target_id, feature_type)` 唯一；任务默认配置可用 `device_id is null` 的部分唯一索引。

## 6. 后端接口设计

### 6.1 后台管理接口

新增管理接口，挂在现有 `/api/v1/admin` 下：

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/live-targets` | 查询直播目标列表 |
| `POST` | `/live-targets` | 新增直播目标 |
| `PATCH` | `/live-targets/:id` | 修改直播目标 |
| `DELETE` | `/live-targets/:id` | 软删除直播目标 |
| `GET` | `/live-targets/:id/aliases` | 查询别名 |
| `POST` | `/live-targets/:id/aliases` | 新增别名 |
| `PATCH` | `/live-target-aliases/:id` | 修改别名 |
| `DELETE` | `/live-target-aliases/:id` | 软删除别名 |
| `GET` | `/live-targets/:id/feature-configs` | 查询功能配置 |
| `PATCH` | `/live-targets/:id/feature-configs/:featureType` | 保存功能配置 |
| `GET` | `/devices/:deviceCode/live-target-bindings` | 查询设备绑定 |
| `PATCH` | `/devices/:deviceCode/live-target-bindings` | 保存设备绑定 |

### 6.2 手机端配置接口

现有 `getCurrentTask` 返回值增加标准化字段：

```ts
liveTargets: Array<{
  targetCode: string;
  targetName: string;
  similarityThreshold: number;
  aliases: Array<{ aliasText: string; aliasType: string; weight: number }>;
  featureType: "live_comment" | "commerce_card_live_comment";
  searchKeywords: string[];
  requiredKeywords: string[];
  forbiddenKeywords: string[];
  productKeywords?: string[];
  liveSignals?: string[];
  runtimeConfig?: Record<string, unknown>;
}>;
```

兼容期内仍返回旧字段：

1. `liveCommentBotConfig.targetRoom`
2. `commerceCardLiveComment`
3. `p3ExtensionsConfig`

手机端优先使用 `liveTargets`，不存在时回退旧 JSON。

## 7. 匹配规则

### 7.1 文本标准化

进入相似度计算前先标准化：

1. 转小写。
2. 全角转半角。
3. 去除空格、换行、常见标点和括号。
4. 去除低价值后缀：`直播间`、`直播`、`官方`、`旗舰店` 可作为可配置停用词。
5. 保留中文、英文、数字和核心商品词。

### 7.2 相似度算法

第一版使用标准化 Levenshtein 相似度：

```text
similarity = 1 - editDistance(a, b) / max(length(a), length(b))
```

命中条件：

1. 从抖音直播卡片、用户块、商品卡、商品详情或进房后页面提取候选名称。
2. 候选名称分别与 `targetName` 和所有 `aliasText` 计算相似度。
3. 任一相似度 `>= similarityThreshold`，默认 `0.90`，视为目标直播间名称命中。
4. 如果命中 `forbiddenKeywords`，即使相似度达标也不进入或进房后退出。
5. `requiredKeywords` 第一版为可选增强，不强制；用户已确认“直播间名字匹配度高就可以进入”。

日志必须记录：

| 字段 | 说明 |
|---|---|
| `targetName` | 后台标准目标名 |
| `candidateName` | 抖音页面候选名称 |
| `matchedAlias` | 命中的别名或标准名 |
| `similarity` | 相似度 |
| `threshold` | 阈值 |
| `source` | `search_card`、`user_block`、`commerce_card`、`live_room_verify` |

## 8. 执行流程

### 8.1 搜索直播评论

```text
读取 liveTargets 中 featureType=live_comment 的启用配置
-> 按 priority 取目标
-> 按 searchKeywords 逐个搜索
-> 扫描直播卡片和用户块
-> 提取候选直播间名称
-> 与 targetName/aliases 做相似度匹配
-> 相似度 >= 0.90 且未命中禁入词
-> 点击进入直播间
-> 进房后二次提取直播间文本并复核相似度
-> 通过后进入采样和评论流程
```

### 8.2 商品卡直播评论

```text
读取 liveTargets 中 featureType=commerce_card_live_comment 的启用配置
-> 按 searchKeywords 进入商城搜索
-> 每轮最多刷商品卡 scanMinutesPerRound 分钟
-> 商品卡命中 productKeywords 和 liveSignals
-> 提取商品卡或直播入口候选名称
-> 与 targetName/aliases 做相似度匹配
-> 相似度 >= 0.90 后进入直播间
-> 进房后二次复核相似度
-> 评论和观看 watchMinutesPerLive 分钟
-> 最多 maxRounds 轮
-> 任意一轮没刷到则正常结束
```

## 9. 后台页面设计

新增或改造为“直播目标配置”页面，保留任务调度页作为启动入口。

页面结构：

1. 目标直播间列表：目标名、平台、启用状态、阈值、绑定设备数、最近命中时间。
2. 目标详情抽屉：标准名、别名、搜索直播评论配置、商品卡直播配置、设备绑定。
3. 搜索直播评论配置区：搜索词、禁入词、阈值、评论模式、发送开关。
4. 商品卡直播配置区：商城搜索词、商品匹配词、直播信号、扫描分钟、观看分钟、轮次、评论池、发送开关。
5. 设备绑定区：选择设备、功能类型、优先级、启用状态。
6. 命中日志区：展示候选名称、相似度、命中别名和进入结果。

不再把配置主要暴露为 JSON 文本框。高级 JSON 可以保留为只读诊断或折叠调试区。

## 10. 兼容与迁移

第一阶段迁移：

1. 从现有 `liveCommentBotConfig.targetRoom` 生成一个默认 `live_targets` 记录。
2. 从 `targetRoom.searchKeywords` 迁移到 `live_target_feature_configs.search_keywords`。
3. 从 `targetRoom.matchKeywords` 迁移为 `live_target_aliases` 和可选 `required_keywords`。
4. 从 `p3ExtensionsConfig.commerceCardLiveComment` 生成商品卡功能配置。
5. 未迁移前手机端继续兼容旧 JSON。

第二阶段收敛：

1. 后台页面保存时只写新表。
2. `getCurrentTask` 从新表聚合 `liveTargets`。
3. 旧 JSON 只读显示，不再作为主配置保存。

第三阶段清理：

1. 真机回归稳定后，逐步删除页面上的旧 JSON 编辑入口。
2. 保留旧字段读取兜底至少一个 APK 版本周期。

## 11. 风险与处理

| 风险 | 处理 |
|---|---|
| 相似度 0.90 对短名称过于宽松 | 短文本低于 4 个有效字符时不走相似度，只允许别名精确或包含命中 |
| 抖音页面无法稳定提取直播间名称 | 同时从卡片文本、用户块、desc、OCR 和进房文本提取候选，并记录样本 |
| 多个目标同时命中 | 按相似度、别名权重、设备绑定优先级排序，只取最高分 |
| 商品卡命中商品词但不是目标直播间 | 必须再通过目标名相似度或别名匹配，不能只凭商品词进入 |
| 旧设备未安装新 APK | 后端保留旧 JSON 返回，旧 APK 仍按旧逻辑运行 |
| 真实评论误触发 | 继续要求 `executeEnabled=true` 且 `manualExecutionApproved=true` |

## 12. 验收口径

1. 后台能新增、编辑、停用直播目标。
2. 后台能给同一直播目标配置多个别名。
3. 后台能分别配置搜索直播评论和商品卡直播评论。
4. 后台能把直播目标绑定到指定设备或作为任务默认目标。
5. 手机端配置接口返回 `liveTargets`。
6. 搜索直播评论按搜索词搜索，不直接强制搜目标直播间标准名。
7. 抖音直播卡片名称与目标名或别名相似度 `>= 0.90` 时可以进入。
8. 进入直播间后必须二次复核目标名称或别名相似度。
9. 商品卡直播评论保持 15 分钟扫描、命中观看 15 分钟、最多 3 轮、任意一轮没命中就结束。
10. 所有命中、跳过和失败原因写入 runtime log 或 live comment action 审计。

## 13. 暂不处理

1. 不做 AI 语义匹配。
2. 不接入外部 OCR 服务。
3. 不做自动购买、加购、关注、私信。
4. 不删除旧 JSON 字段。
5. 不改任务调度的 START、PAUSE、RESUME、STOP 基本协议。

## 14. 落地顺序

1. 新增数据库表和 migration。
2. 新增 repository、service、admin API 和类型定义。
3. 改造 `getCurrentTask` 聚合 `liveTargets`。
4. 新增后台“直播目标配置”页面。
5. 手机端新增 `liveTargets` 解析和相似度匹配工具。
6. 搜索直播评论 runner 接入新配置。
7. 商品卡直播评论 runner 接入新配置。
8. 增加回归测试：配置聚合、相似度、搜索词重试、商品卡轮次、真实发送开关。
9. 更新项目记录、卡点记录和代码审查风险记录。
