# 抖音账号名同步风险修复方案

## 1. 文档目标

本方案用于修复“抖音账号名同步”引入的稳定性风险。目标是让后台能清楚展示每台手机登录的抖音账号，同时不影响一键启动、任务调度、直播评论、视频采集和日志上报。

结论先行：

1. 抖音账号名只是设备展示信息，不属于任务主流程。
2. 手机端不允许在空闲循环里自动操作抖音页面读取账号名。
3. `deviceName` 保留为设备管理名称，抖音账号名单独存储和展示。
4. 任何会点击抖音 UI 的动作都必须有明确触发来源、互斥锁和日志。

## 2. 背景与现状

当前实现为了让后台设备名称显示为抖音账号名，在手机心跳里增加了 `douyinAccountName`，并在后端心跳保存时把该值写入 `deviceName`。

相关现状：

| 模块 | 当前位置 | 现状 |
|---|---|---|
| 手机端空闲循环 | `mobile-agent/autojs/app/collector-app.js` | `idle_loop` 会调用 `maybeSyncDouyinAccountName` |
| 抖音账号读取 | `mobile-agent/autojs/platforms/douyin.js` | 通过进入“我”页面读取可见文本，再恢复首页 |
| 心跳上报 | `mobile-agent/autojs/app/heartbeat.js` | 心跳 payload 携带 `douyinAccountName` |
| 后端保存 | `account-data-platform/apps/api/src/services/mobile.service.ts` | 使用 `douyinAccountName` 更新设备 `deviceName` |
| 数据表 | `collector_devices.device_name` | 同时承担设备名和账号显示名 |

这套实现能把账号名带到后台，但边界不够清晰：它把“读取账号名”变成了手机端常驻行为，和任务调度抢同一个抖音 UI。

## 3. 风险清单

| 风险 | 触发原因 | 影响 | 修复方向 |
|---|---|---|---|
| 一键启动被账号同步打断 | 空闲循环在轮询命令后继续启动账号同步，账号同步也会点击抖音 UI | 用户点击启动后，手机可能先进入抖音个人页或首页恢复流程 | 去掉空闲循环自动同步，只保留显式命令或人工配置 |
| 与任务线程竞争 | 账号同步通过后台线程执行，任务启动也可能同时开始 | 直播评论、视频采集、直播采集可能互相抢页面 | 建立统一 UI 自动化互斥锁，所有点击抖音的动作串行执行 |
| 同步锁可能悬挂 | `running=true` 后如果后台线程启动失败，锁无法释放 | 后续账号同步一直被跳过，状态不可解释 | 账号同步不再放后台线程；如保留线程，必须启动失败回滚和超时释放 |
| 设备名被错误覆盖 | OCR 或文本筛选误判账号名，后端直接覆盖 `deviceName` | 后台设备身份混乱，历史记录难追踪 | 抖音账号名单独字段存储，不再覆盖设备管理名 |
| 无审计来源 | 后台只看到设备名变化，看不到是手机自动读到、人工改的还是误识别 | 出问题后难判断责任和原因 | 保存来源、更新时间、运行日志和命令回执 |
| 隐式打开抖音 | 账号读取逻辑如果允许拉起抖音，会和启动任务行为混淆 | 用户以为启动任务，实际先执行账号同步 | 默认不允许自动打开抖音；只有显式命令可选择是否允许 |

## 4. 不变范围

1. 不改变设备注册、`deviceToken`、`deviceCode` 绑定逻辑。
2. 不改变现有 START、PAUSE、RESUME、STOP、REFRESH_CONFIG 命令语义。
3. 不改变视频采集、直播采集、直播评论的主流程。
4. 不删除心跳中的 `douyinAccountName` 字段兼容能力。
5. 不改变日志中心、采集记录的三层查看路径。

## 5. 变更范围

| 范围 | 需要变更 |
|---|---|
| 手机端 | 关闭空闲自动同步；账号读取只允许显式触发；增加 UI 互斥和日志 |
| 后端 API | 心跳不再用 `douyinAccountName` 覆盖 `deviceName`；增加账号名单独保存和返回 |
| 数据库 | 增加抖音账号名字段，保留设备管理名 |
| 后台 UI | 列表主标题显示抖音账号名，副标题显示设备码和设备管理名；提供手动编辑和可控同步入口 |
| 验证 | 增加一键启动、任务切换、账号同步互斥验证 |

## 6. 修复设计

### 6.1 第一阶段：立即止血

目标是先消除“启动任务时手机自己点抖音页面”的风险。

1. 手机端默认关闭自动账号名同步：
   - `config.runtime.syncDouyinAccountName = false`。
   - 删除或禁用 `idle_loop` 中的 `maybeSyncDouyinAccountName("idle_loop", false)`。
   - `readCurrentAccountName` 保留为工具函数，但不再由空闲循环调用。

2. 后端停止覆盖设备名：
   - 心跳仍接收 `douyinAccountName`。
   - 不再把 `douyinAccountName` 传给 `resolveMobileDevice(... deviceName)`。
   - 旧的 `deviceName` 保持不变，避免错误账号名污染设备身份。

3. 版本与发布：
   - 手机端版本升级，例如 `1.0.16`。
   - API 做一次小版本部署。
   - 这一阶段不要求马上完成账号名自动读取，只保证任务调度稳定。

验收标准：

1. 点击一键启动时，不出现“抖音账号名同步”日志。
2. 点击一键启动时，手机不会因为账号名同步进入“我”页面。
3. 任务启动后只执行用户选择的任务类型。
4. 心跳上报不会覆盖后台设备管理名。

### 6.2 第二阶段：账号名独立建模

账号名不能继续借用 `deviceName`。建议在 `collector_devices` 增加独立字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `douyin_account_name` | `varchar(100)` | 当前识别或人工维护的抖音账号名称 |
| `douyin_account_name_source` | `varchar(32)` | 来源：`manual`、`mobile`、`import` |
| `douyin_account_name_updated_at` | `timestamp with time zone` | 最近更新时间 |
| `douyin_account_name_verified` | `boolean` | 是否人工确认过 |

展示规则：

```text
主标题：douyinAccountName || deviceName || deviceCode
副标题：设备码 deviceCode
辅助信息：设备管理名 deviceName
```

写入规则：

1. 人工在后台编辑账号名时，来源写 `manual`，并标记为已确认。
2. 手机心跳携带账号名时，只更新 `douyin_account_name`，来源写 `mobile`，不覆盖 `device_name`。
3. 手机识别到空值、异常值、明显 UI 文案时，不更新账号名。
4. 如果账号名已人工确认，手机自动识别结果不能直接覆盖，只能进入“待确认”提示或日志。

### 6.3 第三阶段：显式同步能力

如果仍需要从手机自动读取抖音账号名，必须改成显式操作，不能常驻自动执行。

后台交互建议：

1. 设备详情抽屉增加“同步抖音账号名”按钮。
2. 点击后下发独立命令，例如 `SYNC_DOUYIN_ACCOUNT_NAME`。
3. 后台提示该操作会短暂操作手机抖音页面。
4. 手机端收到命令后先检查是否有任务正在运行。
5. 只有设备空闲、没有暂停恢复动作、没有任务线程持有 UI 锁时，才允许执行。

手机端执行规则：

1. 不默认打开抖音；如果当前不在抖音，返回“当前未在抖音，未同步”。
2. 如果确实需要允许打开抖音，必须由命令 payload 明确传入 `allowOpenApp: true`。
3. 执行前获取统一 UI 锁，执行后释放。
4. 成功、跳过、失败都要上报命令回执和运行日志。
5. 读取后尽量恢复原页面，但恢复失败不能继续盲点。

建议命令 payload：

```json
{
  "commandType": "SYNC_DOUYIN_ACCOUNT_NAME",
  "allowOpenApp": false,
  "reason": "manual_admin_sync"
}
```

建议回执：

| 字段 | 含义 |
|---|---|
| `success` | 是否成功读取并上报 |
| `skipped` | 是否因状态不满足而跳过 |
| `accountName` | 识别到的账号名 |
| `failureReason` | 失败原因 |
| `stateBefore` | 执行前抖音状态 |
| `stateAfter` | 执行后抖音状态 |

### 6.4 第四阶段：统一 UI 自动化互斥

当前手机端有多个动作会操作抖音 UI：任务启动、任务恢复、视频采集、直播采集、直播评论、账号读取。它们必须共用同一个互斥入口。

建议增加统一锁：

```text
uiAutomationLock = {
  owner: "task | command | account_sync",
  reason: string,
  startedAt: number,
  timeoutMs: number
}
```

规则：

1. 所有会点击抖音 UI 的流程必须先获取锁。
2. 任务运行优先级高于账号同步。
3. 后台 STOP 命令可以打断任务，但不能被账号同步拦截。
4. 锁超时必须自动释放并写 WARN 日志。
5. 获取锁失败时返回明确原因，不进入等待死循环。

## 7. 后台 UI 调整

设备列表、工作台、任务调度、直播评论、采集记录和日志中心都统一使用以下设备标题规则：

| UI 位置 | 展示 |
|---|---|
| 卡片标题 | 抖音账号名；没有账号名时显示设备管理名 |
| 卡片副标题 | 设备码 |
| 详情抽屉 | 抖音账号名、设备管理名、设备码、最后同步时间、来源 |
| 筛选搜索 | 支持按抖音账号名、设备管理名、设备码搜索 |

设备详情抽屉增加两个操作：

1. “编辑账号名”：人工维护，不操作手机。
2. “同步账号名”：下发显式命令，执行手机端读取。

不建议再把账号名直接写到 `deviceName`，否则设备身份和账号身份会混在一起。

## 8. 落地顺序

| 阶段 | 内容 | 产出物 | 风险 |
|---|---|---|---|
| 1 | 关闭空闲自动同步，停止覆盖 `deviceName` | 手机端补丁、API 补丁、新 APK | 账号名不会自动更新，但任务稳定 |
| 2 | 增加账号名独立字段和接口返回 | migration、schema、admin API | 需要部署数据库 migration |
| 3 | 后台统一展示账号名 | Web 页面调整 | UI 搜索和旧数据兼容 |
| 4 | 增加手动编辑账号名 | 后台表单、API patch | 需要防止误填空值 |
| 5 | 增加显式同步命令 | 后台按钮、mobile command、手机执行器 | 需要 UI 锁和真机验证 |
| 6 | 建立 UI 自动化互斥 | 手机端公共锁工具 | 涉及多个任务入口，需分批接入 |

建议先做阶段 1 和阶段 2。阶段 5、6 是增强项，不应该阻塞止血发布。

## 9. 验收口径

### 9.1 一键启动

1. 后台点击视频、直播、直播评论启动后，手机只进入对应任务流程。
2. 启动过程中不出现账号名同步日志。
3. 手机不会因为账号名同步跳到“我”页面。
4. 命令状态能从待下发、已拉取、执行中到已确认或失败闭环。

### 9.2 账号名展示

1. 设备卡片优先显示抖音账号名。
2. 没有账号名时，仍能显示设备管理名或设备码。
3. 设备详情能看到账号名来源和更新时间。
4. 修改账号名不影响 `deviceCode` 和设备绑定。

### 9.3 任务稳定性

1. 视频采集、直播采集、直播评论互相切换时，账号同步不参与页面操作。
2. STOP、PAUSE、RESUME 不被账号同步线程阻塞。
3. 手机端日志能区分任务动作、配置动作、账号同步动作。

### 9.4 回归验证命令

本地代码检查：

```powershell

```

```text

设备列表能正常展示账号名或设备码
```

## 10. 回滚方案

如果阶段 1 发布后出现问题：

1. 手机端回滚到上一版 APK，但需要确认上一版是否包含自动账号同步。
2. API 可临时忽略 `douyinAccountName`，只保留心跳基本字段。
3. 后台 UI 使用 `deviceName || deviceCode` 展示，不展示账号名。
4. 数据库新增字段如已部署，不需要回滚，可保留为空。

如果显式同步命令出现问题：

1. 后台隐藏“同步账号名”按钮。
2. 手机端关闭 `runtime.syncDouyinAccountName`。
3. 保留人工编辑账号名能力。

## 11. 暂不处理内容

1. 不做账号自动登录或账号切换。
2. 不读取粉丝数、获赞数、抖音号等扩展画像。
3. 不在任务运行中自动识别账号名。
4. 不把账号名识别作为任务启动前置条件。
5. 不用 OCR 结果直接覆盖人工确认过的账号名。
