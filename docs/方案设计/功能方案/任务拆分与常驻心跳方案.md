# 任务拆分与常驻心跳方案

## 1. 文档目标

本方案定义手机 Agent 的执行边界：常驻心跳、刷视频、刷直播、直播评论四类能力分开实现，统一由调度器路由。

## 2. 设计原则

1. 心跳与任务执行解耦。
2. 单机同一时刻只允许一个前台任务执行。
3. 任务模块只处理自己的业务，不直接依赖其他任务的状态机。
4. 后台命令按 `taskType` 路由，不使用一套共享流程串行覆盖所有能力。

## 3. 模块划分

### 3.1 常驻心跳模块

- 负责设备在线、版本、运行状态、最近任务状态上报。
- app 启动后立即启动。
- app 在后台时继续运行。
- 只有脚本真正退出时停止。

### 3.2 刷视频模块

- 负责推荐流浏览、识别、候选记录和翻页。
- 自己维护视频阶段状态和恢复逻辑。
- 不直接触发直播评论发送。

### 3.3 刷直播模块

- 负责进入直播、停留、识别和恢复。
- 自己维护直播阶段状态。
- 不直接执行评论发送。

### 3.4 直播评论模块

- 负责直播评论任务本身的执行边界。
- 只允许在评论任务被调度时进入执行。
- 不和刷视频、刷直播共用同一组前台任务状态。
- 不直接继承其他任务的恢复逻辑、翻页逻辑和计数逻辑。
- 具体评论链路细节单独放在 `直播评论自动化方案.md`。

### 3.5 任务调度器

- 负责接收后台命令和本地任务请求。
- 路由到对应模块。
- 做互斥和优先级控制。
- 评论任务可高于普通浏览任务优先执行。

#### 3.5.1 调度职责

1. 识别当前命令属于哪个任务域。
2. 判断当前是否已有活动任务。
3. 若当前任务和新任务冲突，先进入切换流程。
4. 若当前任务可暂停，则暂停后切换。
5. 若当前任务必须停止，则先停止再启动新任务。
6. 统一维护当前激活任务标识，不让各模块自己抢状态。

#### 3.5.2 调度优先级

| 优先级 | 任务 | 说明 |
|---|---|---|
| 1 | 常驻心跳 | 永远保持，不参与竞争 |
| 2 | 直播评论 | 进入指定直播间和发送动作优先 |
| 3 | 刷直播 | 直播场景优先于普通浏览恢复 |
| 4 | 刷视频 | 默认浏览任务，优先级最低 |

#### 3.5.3 调度切换规则

1. 新任务启动前，先检查是否已有前台任务。
2. 若已有任务且类型相同，只做 resume，不重复初始化。
3. 若已有任务且类型不同，先发 stop/pause，再清理上下文，再启动新任务。
4. 任务切换期间禁止共享 OCR 结果、临时输入、页面缓存。
5. 切换失败时必须回到“无前台任务但心跳继续”的状态。
6. 任意任务失败都只能影响自己，不应把调度器带崩。

#### 3.5.4 调度输入输出

| 输入 | 输出 |
|---|---|
| `taskType` | 当前应执行的模块 |
| `commandType` | 启动、暂停、停止、恢复 |
| `taskId` | 当前任务标识 |
| `deviceId` | 当前设备标识 |
| `forceSwitch` | 是否允许抢占当前任务 |
| `currentTask` | 当前激活任务 |
| `nextTask` | 切换后的目标任务 |
| `dispatchResult` | 成功、失败、忽略、切换中 |

## 4. 状态边界

| 状态 | 归属 | 说明 |
|---|---|---|
| 心跳状态 | 常驻心跳模块 | 只表达 app/设备在线，不绑定某个任务 |
| 视频状态 | 刷视频模块 | 只记录视频阶段进度 |
| 直播状态 | 刷直播模块 | 只记录直播阶段进度 |
| 评论状态 | 直播评论模块 | 只记录评论任务执行状态 |
| 调度状态 | 任务调度器 | 只负责哪个任务当前被允许运行 |

## 4.1 冲突规避规则

1. 常驻心跳与任务执行分离，心跳不参与任务互斥。
2. 刷视频、刷直播、直播评论三类前台任务互斥，同一时刻只允许一个激活。
3. 任务切换必须先释放当前任务状态，再进入新任务状态。
4. 任务之间不共享翻页、恢复、OCR 结果缓存和临时输入状态。
5. 任何任务失败只回退自己的状态，不回滚其他任务。
6. 任何任务暂停或停止，不影响心跳和后台命令轮询。

## 5. 关键接口

1. `heartbeat.start()`：启动常驻心跳。
2. `heartbeat.stop()`：停止心跳。
3. `taskManager.run(taskType)`：按类型启动任务。
4. `taskManager.stop(taskType)`：按类型停止任务。
5. `taskManager.getCurrentTask()`：获取当前前台任务。

## 6. 后台命令约定

| 命令 | 行为 |
|---|---|
| `START` | 启动对应任务 |
| `STOP` | 停止对应任务 |
| `PAUSE` | 暂停对应任务 |
| `RESUME` | 恢复对应任务 |
| `REFRESH_CONFIG` | 刷新后台配置 |

## 7. 验收口径

1. app 打开后心跳自动上报。
2. app 切后台后心跳继续。
3. 刷视频、刷直播、直播评论可分别启动。
4. 同一台手机不会同时跑两个前台任务。
5. 指定直播间评论链路可以单独验证。

## 8. 关联方案

1. `直播评论自动化方案.md` 负责直播评论的具体执行细节。
2. 本文负责把直播评论从总流程里拆成独立任务边界。
3. 两份文档一起使用，前者讲做法，后者讲边界和调度。
