# 任务拆分与常驻心跳方案

## 1. 文档目标

本方案定义手机 Agent 的执行边界：常驻心跳、刷视频、刷直播、直播评论四类能力分开实现，统一由调度器路由。

## 2. 设计原则

1. 心跳与任务执行解耦。
2. 单机同一时刻只允许一个前台任务执行。
3. 任务模块只处理自己的业务，不直接依赖其他任务的状态机。
4. 后台命令按 `taskType` 路由，不使用一套共享流程串行覆盖所有能力。

## 3. 模块划分

### 3.1 常驻心跳模块

- 负责设备在线、版本、运行状态、最近任务状态上报。
- app 启动后立即启动。
- app 在后台时继续运行。
- 只有脚本真正退出时停止。

### 3.2 刷视频模块

- 负责推荐流浏览、识别、候选记录和翻页。
- 自己维护视频阶段状态和恢复逻辑。
- 不直接触发直播评论发送。

### 3.3 刷直播模块

- 负责进入直播、停留、识别和恢复。
- 自己维护直播阶段状态。
- 不直接执行评论发送。

### 3.4 直播评论模块

- 负责指定直播间进入、识别、发送、失败回传和审计。
- 支持目标直播间校验。
- 支持独立限流、重试和状态回执。

### 3.5 任务调度器

- 负责接收后台命令和本地任务请求。
- 路由到对应模块。
- 做互斥和优先级控制。
- 评论任务可高于普通浏览任务优先执行。

## 4. 状态边界

| 状态 | 归属 | 说明 |
|---|---|---|
| 心跳状态 | 常驻心跳模块 | 只表达 app/设备在线，不绑定某个任务 |
| 视频状态 | 刷视频模块 | 只记录视频阶段进度 |
| 直播状态 | 刷直播模块 | 只记录直播阶段进度 |
| 评论状态 | 直播评论模块 | 只记录评论任务执行状态 |
| 调度状态 | 任务调度器 | 只负责哪个任务当前被允许运行 |

## 5. 关键接口

1. `heartbeat.start()`：启动常驻心跳。
2. `heartbeat.stop()`：停止心跳。
3. `taskManager.run(taskType)`：按类型启动任务。
4. `taskManager.stop(taskType)`：按类型停止任务。
5. `taskManager.getCurrentTask()`：获取当前前台任务。

## 6. 后台命令约定

| 命令 | 行为 |
|---|---|
| `START` | 启动对应任务 |
| `STOP` | 停止对应任务 |
| `PAUSE` | 暂停对应任务 |
| `RESUME` | 恢复对应任务 |
| `REFRESH_CONFIG` | 刷新后台配置 |

## 7. 验收口径

1. app 打开后心跳自动上报。
2. app 切后台后心跳继续。
3. 刷视频、刷直播、直播评论可分别启动。
4. 同一台手机不会同时跑两个前台任务。
5. 指定直播间评论链路可以单独验证。
