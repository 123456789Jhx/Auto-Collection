# 手机端任务调度与状态恢复方案

本文记录手机端任务切换和页面状态恢复的当前方向，合并原任务拆分、常驻心跳和状态驱动任务切换方案中的有效结论。

## 1. 功能定位

手机 Agent 不是一次性脚本，而是常驻进程。它需要持续轮询后台配置和命令，并在视频、直播、直播评论任务之间切换。

后续重点不是推倒重写，而是在现有可运行版本基础上增强三件事：

1. 能识别当前抖音页面状态。
2. 能从不同页面恢复到目标任务需要的上下文。
3. 能在后台切换任务时安全中断旧任务并启动新任务。

## 2. 任务类型

| 任务 | 含义 | 标准上下文 |
|---|---|---|
| `video` | 刷视频和视频采集 | `video_playback_context` |
| `live` | 普通直播发现和直播采集 | `feed_context` 或直播发现上下文 |
| `live_comment` | 指定直播间评论 | `target_live_room_context` |

同一台手机同一时间只允许一个主任务活跃。

任务状态隔离不等于执行流程可以复用。`live_comment` 必须有独立 runner，只允许搜索目标直播间、校验目标、评论和退出；不能复用普通 `live` runner，也不能用推荐直播流兜底。

## 3. 常驻层

常驻层必须独立于具体任务：

1. 注册设备并保存设备 token。
2. 拉取任务配置和设备覆盖配置。
3. 轮询后台命令。
4. 上传心跳。
5. 上传结构化日志和完整日志。
6. 上报命令回执。
7. 在任务结束、暂停或失败后回到待命，不退出 Agent。

常驻层不能被直播评论 STOP 直接杀掉，否则后台后续命令无法执行。

## 4. 调度层

手机端调度器维护当前 active task：

```text
后台命令 START/RESUME/REFRESH_CONFIG
-> 更新 activeTaskType
-> 当前任务检查到切换
-> 安全中断当前动作
-> 新任务通过恢复层接管
```

需要检查任务切换的节点：

1. 视频滑动前后。
2. 视频评论采集前后。
3. 直播间停留间隔。
4. 直播评论计划发送前等待。
5. 搜索重试循环。
6. 长时间 sleep。
7. 网络异常重试循环。

## 5. 页面状态模型

页面识别统一由 `detectDouyinState()` 负责，避免每个任务各自猜页面。

| 状态 | 含义 | 典型处理 |
|---|---|---|
| `not_douyin` | 当前不在抖音 | 拉起抖音 |
| `douyin_feed` | 首页或推荐流 | 可进入搜索或继续视频 |
| `video_playing` | 视频播放页 | 视频任务可继续，直播评论需进搜索 |
| `search_input` | 搜索输入页 | 清空旧词，输入新关键词 |
| `search_result` | 搜索结果页 | 校验关键词是否正确 |
| `search_empty` | 搜索无结果或空白 | 点击重试、刷新或重新搜索 |
| `network_error` | 网络异常 | 点击重试，失败后重建上下文 |
| `live_room` | 直播间 | 校验是否目标直播间 |
| `wrong_live_room` | 错误直播间 | 退出并重新搜索目标 |
| `profile_page` | 用户主页 | 找直播入口或返回搜索页 |
| `comment_panel` | 评论面板打开 | 关闭或复用评论上下文 |
| `permission_prompt` | 系统权限弹窗 | 按策略授权或暂停 |
| `douyin_popup` | 抖音内部弹窗 | 关闭后继续 |
| `unknown_overlay` | 未知浮层 | 截图/日志，保守关闭 |
| `unknown` | 无法判断 | 尝试返回、重启抖音或暂停 |

每次识别结果需要记录状态、置信度、可见文本样本、activity、package、阻断原因。

## 6. 恢复层

恢复层根据目标任务决定要恢复到哪里，而不是每次都强制回首页。

| 目标 | 恢复动作 |
|---|---|
| 视频任务 | 回到视频播放上下文，可播放、滑动和采集 |
| 普通直播 | 回到可发现直播入口的上下文 |
| 直播评论 | 搜索并进入已确认的目标直播间 |

恢复顺序必须保守：

```text
1. 关闭已知弹窗
2. 处理权限弹窗
3. 处理键盘和输入框
4. 处理网络异常
5. 返回上一层
6. 重新进入目标上下文
7. 最后才重启抖音
```

未知状态不能无限重试。达到上限后暂停任务，上报失败原因和页面样本，等待后台或人工处理。

## 7. 视频切直播评论

目标：后台从视频任务切到直播评论后，脚本不需要重启，也能从当前页面接管。

流程：

```text
后台启动 live_comment
-> 手机端 activeTaskType 变为 live_comment
-> 视频任务检测到 task_switched
-> 视频任务停止当前动作并返回
-> live_comment 任务启动
-> detectDouyinState()
-> recoverToTargetLiveRoom(targetRoom)
-> 进入目标直播间
-> 执行评论计划
```

如果当前页面已经是目标直播间，不重复搜索；如果是错误直播间，退出后重新搜索。

## 8. 直播评论搜索规则

指定直播间链路固定为：

```text
读取 targetRoom 配置
-> 搜索 anchorName 或目标关键词
-> 停留综合页
-> 在综合页识别用户头像的“直播中”入口和直播卡片
-> 点击进入
-> 校验目标直播间
-> 执行评论计划
```

执行入口必须直接进入直播评论独立 runner。禁止用 `phaseRunner.runPhase("live", ..., { taskType: "live_comment" })` 承载直播评论任务。

明确不做：

1. 不主动切到“视频”tab。
2. 不主动切到“直播”tab。
3. 不假设抖音刚打开就是首页。
4. 不假设搜索框一定可输入。
5. 不在未确认目标直播间时发送真实评论。

常见页面处理：

| 当前状态 | 处理 |
|---|---|
| 搜索输入页 | 清空旧词后输入目标关键词 |
| 搜索结果页关键词正确 | 复用结果 |
| 搜索结果页关键词不正确 | 点搜索框重新搜索 |
| “猜你想看”或建议页 | 输入后优先点顶部搜索按钮 |
| 结果空白 | 先点重试，再下拉刷新，最后重新搜索 |
| 网络异常 | 点击重试，失败后重新进入搜索 |

## 9. 后台命令语义

命令需要区分常驻 Agent 和具体任务：

| 命令 | 语义 |
|---|---|
| `START` | 启动或切换到目标任务 |
| `RESUME` | 恢复目标任务 |
| `PAUSE` | 暂停目标任务，Agent 保持常驻 |
| `STOP` | 停止目标任务，Agent 回到待命 |
| `REFRESH_CONFIG` | 重新拉取后台配置 |

payload 应携带：

```json
{
  "taskType": "live_comment",
  "targetContext": "target_live_room_context",
  "assignmentId": "optional",
  "reason": "manual_or_scheduler"
}
```

兼容历史命令时，`live_comment_control`、`liveComment`、`live-comment` 应规范化为 `live_comment`。

## 10. 日志要求

关键日志字段：

| 字段 | 含义 |
|---|---|
| `taskType` | 当前任务 |
| `stateBefore` | 恢复前页面状态 |
| `targetContext` | 目标上下文 |
| `actionName` | 执行动作 |
| `attempt` | 第几次尝试 |
| `stateAfter` | 恢复后页面状态 |
| `success` | 是否成功 |
| `failureReason` | 失败原因 |
| `commandId` | 后台命令 |
| `activeTaskType` | 当前活跃任务 |

常见失败原因：

| 原因 | 含义 |
|---|---|
| `search_keyword_reset_failed` | 搜索页旧关键词无法清空或新词未生效 |
| `search_network_retry_failed` | 网络异常多次重试失败 |
| `target_live_card_not_found` | 综合页未找到目标直播入口 |
| `target_live_room_not_matched` | 进入直播间后不是目标 |
| `comment_input_not_found` | 找不到评论输入框 |
| `task_switched` | 当前任务被后台切走 |
| `unknown_overlay_blocked` | 未知浮层阻断 |

## 11. 落地顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| 一 | 增加页面识别和日志，不改主流程 | 后台能看到页面状态识别结果 |
| 二 | 直播评论接入恢复层 | 从视频页、搜索页、直播间能进入目标直播间或明确失败 |
| 三 | 任务切换中断 | video 切 live_comment 不需要重启脚本 |
| 四 | 视频和直播任务接入恢复层 | live_comment 切回 video 能恢复视频上下文 |
| 五 | 清理旧线性流程 | 页面恢复逻辑集中管理 |

## 12. 回退措施

当前可回退基线继续保留：

| 项目 | 内容 |
|---|---|
| 基线标签 | `baseline-live-comment-1.0.9` |
| 基线提交 | `9444593 feat: stabilize live comment control flow` |
| 适用范围 | 已能执行直播评论、刷视频、刷直播的前后台和手机脚本版本 |

后续重构建议使用独立分支和功能开关：

```text
runtime.stateDrivenRecoveryEnabled
runtime.taskSwitchInterruptEnabled
runtime.targetLiveRoomRecoveryEnabled
```

如果新恢复逻辑出问题，可以关闭开关或安装旧 APK 回退。

## 13. 验收场景

1. 视频任务运行中切到直播评论。
2. 搜索页已有旧关键词时重新搜索目标账号。
3. 停在“猜你想看”页面时能提交新搜索。
4. 当前在错误直播间时退出并重新搜索。
5. 当前在目标直播间时直接执行评论计划。
6. 搜索结果网络异常时点击重试，失败后明确上报。
7. 出现权限弹窗或未知弹窗时不无限滑动。
8. 直播评论切回视频时恢复视频播放上下文。
