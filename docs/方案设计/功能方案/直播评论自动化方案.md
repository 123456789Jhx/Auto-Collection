# 直播评论自动化方案

本文是直播评论功能的当前唯一方案入口，记录后台配置、远程控制、手机执行、话术生成、真实发送和审计口径。

当前实现修复以 `直播评论独立任务闭环修复方案.md` 为准。本文保留业务功能边界和验收口径，执行层必须按修复方案把 `live_comment` 从普通 `live` 任务里彻底拆开。

## 1. 功能定位

直播评论用于在后台指定设备、账号画像和目标直播间后，由手机 Agent 搜索并进入目标直播间，读取公开可见内容，生成评论计划，并在明确允许真实发送时执行评论发送。

直播评论是独立任务，不能和普通视频采集、普通直播采集并发执行。

执行层也必须独立：`live_comment` 不允许调用普通直播 runner，不允许通过普通直播流兜底进房，不允许在未确认目标账号的直播间发送评论。

## 2. 当前目标

1. 后台为单台设备维护账号画像、直播评论模式和指定直播间配置。
2. 后台保存配置后，手机端能刷新配置或接收远程命令。
3. 后台能下发直播评论启动、暂停、恢复、停止命令。
4. 手机端进入抖音后，不要求一定从首页开始，而是先识别当前页面并恢复到目标直播间。
5. 手机端在综合搜索结果里识别用户头像“直播中”入口和直播卡片，不主动切换到视频或直播 tab。
6. 进入直播间后必须校验目标主播、标题关键词或画面关键词。
7. 未确认目标直播间时不真实发送评论。
8. 计划、跳过、失败和发送结果都写入后台审计。

## 2.1 执行隔离要求

1. `video`、`live`、`live_comment`、`commerce_card_live_comment` 可以共用调度、心跳、日志、风控基础设施。
2. `live_comment` 不能复用普通 `live` 的刷流、切换直播间、推荐直播入口逻辑。
3. `live_comment` 必须独立完成搜索、关键词校验、入口识别、进房校验、评论和退出。
4. 搜索关键词与任务目标不一致时，必须停止并上报明确原因。
5. 命中风控、登录异常、验证码或访问拒绝时，必须停止并退出抖音。
6. 任务完成或失败后，必须回到脚本等待态，不能继续滑动或乱点。

## 3. 后台配置

直播评论配置由三层合并：

| 层级 | 字段 |
|---|---|
| 任务模板 | `collection_tasks.live_comment_config`、`collection_tasks.live_comment_bot_config` |
| 设备覆盖 | `device_task_configs.live_comment_role`、`live_comment_group`、`live_comment_mode`、`live_comment_config`、`live_comment_bot_config` |
| 设备画像 | `collector_devices.account_profile` |

设备级配置优先级高于任务模板。设备画像独立保存，不放在公共模板里。

## 4. 指定直播间

指定直播间配置保存到设备级 `liveCommentBotConfig.targetRoom`。

| 字段 | 说明 |
|---|---|
| `enabled` | 是否启用指定直播间模式 |
| `anchorName` | 主播账号名 |
| `titleKeywords` | 直播标题关键词 |
| `roomKeywords` | 画面或直播间关键词 |
| `allowRealSend` | 是否允许真实发送 |
| `maxSendCount` | 本轮最多真实发送条数 |
| `minSendIntervalSeconds` | 真实发送最小间隔 |

启用指定直播间时，搜索关键词优先使用 `anchorName`，必要时使用标题或房间关键词补充。

## 5. 命令语义

直播评论控制命令统一使用标准任务类型 `live_comment`。历史兼容值 `live_comment_control` 只能作为别名规范化，不能再作为新方案主语义。

| 命令 | 语义 |
|---|---|
| `START` | 启动直播评论任务，恢复到目标直播间并执行 |
| `RESUME` | 从暂停状态恢复直播评论 |
| `PAUSE` | 暂停直播评论，Agent 保持常驻 |
| `STOP` | 停止直播评论子任务，Agent 回到待命 |
| `REFRESH_CONFIG` | 重新拉取直播评论配置 |

payload 示例：

```json
{
  "taskType": "live_comment",
  "targetContext": "target_live_room_context",
  "reason": "manual_live_comment_start",
  "targetRoom": {
    "enabled": true,
    "anchorName": "目标主播"
  }
}
```

STOP 只停止当前直播评论任务，不应让 Agent 杀进程，也不应继续在搜索页无限滑动。

## 6. 手机端流程

```text
Agent 常驻
-> 拉取配置和命令
-> 收到 live_comment START/RESUME
-> 更新 activeTaskType
-> 识别当前抖音页面
-> 恢复到 target_live_room_context
-> 搜索 anchorName 或关键词
-> 停留综合页识别直播入口
-> 进入并校验目标直播间
-> 采样公开文本和评论
-> 生成评论计划
-> 安全网关判断是否允许真实发送
-> 发送或跳过
-> 上报 live_comment_actions
```

如果当前已经在目标直播间，可以跳过搜索；如果在错误直播间，应退出并重新搜索。

## 7. 搜索和进入规则

搜索链路固定为：

```text
读取 targetRoom
-> 打开或恢复搜索输入
-> 清空旧关键词
-> 输入 anchorName 或目标关键词
-> 点击搜索
-> 停留综合页
-> 识别用户头像“直播中”和直播卡片
-> 点击进入
-> 校验目标直播间
```

明确不做：

1. 不主动切换到“视频”tab。
2. 不主动切换到“直播”tab。
3. 不根据非目标直播间的热闹程度发送评论。
4. 不在网络空白页无限等待或无限下滑。

网络异常或空白页处理：

1. 优先点击“重试”。
2. 失败后下拉刷新。
3. 再失败则重新进入搜索。
4. 多次失败后上报 `search_network_retry_failed` 并暂停任务。

## 8. 目标直播间校验

进入直播间后必须校验：

| 来源 | 作用 |
|---|---|
| 主播名 | 优先确认是否目标主播 |
| 标题关键词 | 辅助确认直播主题 |
| 画面关键词 | 辅助确认直播内容 |
| 最近点击入口 | 防止进入错卡片 |
| 页面状态 | 确认当前确实是直播间 |

校验失败处理：

1. 不发送评论。
2. 上报 `target_live_room_not_matched`。
3. 退出直播间并重试搜索，达到上限后暂停。

## 9. 话术生成逻辑

评论话术由账号画像、直播间上下文和话术配置共同决定。

输入信息：

| 输入 | 来源 |
|---|---|
| 账号身份 | `collector_devices.account_profile` |
| 评论模式 | `live_comment_mode` |
| 话术池和机器人配置 | `liveCommentBotConfig` |
| 直播间标题和画面文本 | 手机端采样 |
| 公开评论区文本 | 手机端采样 |
| 目标直播间配置 | `targetRoom` |

生成顺序：

```text
读取账号画像
-> 采样直播间公开文本
-> 判断农业相关性和目标直播间匹配
-> 按模式选择话术类型
-> 从话术池中挑选或组合一句评论
-> 检查敏感词、重复、长度和发送间隔
-> 生成 planned 动作
```

当前话术原则：

1. 优先使用自然、短句、低风险话术。
2. 不承诺疗效、夸大收益或诱导交易。
3. 不重复连续发送相同话术。
4. 不在低置信或不匹配直播间真实发送。
5. 真实发送前必须通过安全网关。

## 10. 真实发送安全网关

只有同时满足以下条件才允许真实发送：

1. `targetRoom.enabled = true`。
2. 已确认当前直播间为目标直播间。
3. `targetRoom.allowRealSend = true`。
4. 未超过 `targetRoom.maxSendCount`。
5. 距离上次发送超过 `targetRoom.minSendIntervalSeconds`。
6. 评论内容通过敏感词、长度、重复和风险检查。
7. 当前没有验证码、登录异常、风控提示或未知阻断弹窗。

不满足时写入 `skipped` 或 `failed`，并记录原因。

## 11. 执行记录

结果写入 `live_comment_actions`。

| 状态 | 含义 |
|---|---|
| `planned` | 已生成计划，未真实发送 |
| `sent` | 已真实发送 |
| `skipped` | 因配置、冷却、相关度、目标不匹配等跳过 |
| `failed` | 执行失败 |

常见原因：

| 原因 | 含义 |
|---|---|
| `allow_real_send_disabled` | 未打开真实发送 |
| `target_live_card_not_found` | 搜索结果未找到目标直播入口 |
| `target_live_room_not_matched` | 进入后不是目标直播间 |
| `comment_input_not_found` | 找不到评论输入框 |
| `send_limit_reached` | 达到本轮发送上限 |
| `send_interval_not_reached` | 发送间隔不足 |
| `risk_control` | 疑似风控 |
| `task_switched` | 任务被后台切换 |

## 12. 后台页面要求

直播评论页需要支持：

1. 按设备查看配置和动作记录。
2. 保存账号画像、评论模式、指定直播间配置。
3. 点击启动、暂停、恢复、停止。
4. 保存指定直播间后触发配置刷新或远程命令下发。
5. 展示最近命令状态、手机实际任务和最近失败原因。
6. 执行记录原因码显示中文解释。

## 13. 验收口径

1. 后台单设备保存账号画像和指定直播间配置。
2. 保存配置后，手机端能拿到最新 targetRoom。
3. 后台启动直播评论后，手机端从当前抖音页面恢复到目标直播间。
4. 搜索结果停留综合页识别直播中入口和直播卡片。
5. 进入直播间后完成目标校验。
6. 未开启 `allowRealSend` 时只计划或跳过，不真实发送。
7. 开启真实发送后仍受次数、间隔和安全网关限制。
8. 暂停和停止命令能停止直播评论任务，Agent 保持常驻。
9. 失败时后台能看到具体原因，而不是只看到离线或空白状态。
