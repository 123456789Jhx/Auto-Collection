# 直播评论自动化方案

## 1. 文档定位

本文是直播评论相关功能的当前唯一需求入口，合并原来的页面调整、任务模板、列表状态、设备画像和指定直播间测试口径。

原拆分文档已被本文吸收，不再作为当前实现依据。

## 2. 当前目标

当前直播评论功能要打通后台配置到手机 Agent 执行的完整链路：

1. 后台为单台设备维护账号画像、直播评论模式和指定直播间配置。
2. 后台通过远程命令下发直播评论控制动作。
3. 手机 Agent 常驻轮询后台配置和命令。
4. 手机 Agent 收到直播评论启动命令后打开抖音，搜索并进入指定直播间。
5. 手机 Agent 读取直播间画面、主播名、评论区和公开可见文本。
6. 命中目标直播间后生成评论计划。
7. 在显式允许真实发送时执行评论发送，并把计划、跳过、失败或发送结果回传后台。

## 3. 当前边界

| 项 | 当前口径 |
|---|---|
| 默认真实发送 | 关闭 |
| 指定直播间 | 支持，通过 `targetRoom` 配置 |
| 发送开关 | 仅 `targetRoom.allowRealSend = true` 时允许 |
| 发送上限 | 受 `targetRoom.maxSendCount` 限制 |
| 发送间隔 | 受 `targetRoom.minSendIntervalSeconds` 限制 |
| 点赞、关注、私信 | 默认不做，不能和评论发送混用 |
| 风控、验证码、登录异常 | 停止自动动作，等待人工处理 |

## 4. 后台页面

### 4.1 直播评论首页

直播评论首页只展示设备卡片列表，支持按设备名称、设备码和状态筛选。

设备卡片展示：

1. 设备名称和设备码。
2. 在线或运行状态。
3. 评论动作总数、计划数、发送数、失败数、跳过数。
4. 最近一次执行时间。

点击设备卡片进入单设备详情页。

### 4.2 单设备详情页

单设备详情页只展示当前设备的数据：

1. 当前设备配置摘要。
2. 账号画像摘要和编辑入口。
3. 指定直播间测试配置入口。
4. 当前设备直播评论执行记录。
5. 只作用于当前设备的控制按钮。

详情页不展示 `agri_chatbot`、`target_follow`、`task`、`device` 等原始技术值，页面显示应转换为业务文案。

### 4.3 公共模板

任务配置页维护所有设备可继承的公共直播评论模板：

1. 是否启用。
2. 机器人名称。
3. 相关度阈值。
4. 每直播间上限。
5. 每小时上限。
6. 最小发送间隔。
7. 发送延迟范围。
8. 低置信处理方式。
9. 话术类型和话术池。

设备级配置可以覆盖公共模板。设备画像不放在任务模板里。

## 5. 后端数据和接口

当前实现按三层配置合并：

| 层级 | 字段 |
|---|---|
| 任务模板 | `collection_tasks.live_comment_config`、`collection_tasks.live_comment_bot_config` |
| 设备覆盖 | `device_task_configs.live_comment_role`、`live_comment_group`、`live_comment_mode`、`live_comment_config`、`live_comment_bot_config` |
| 设备画像 | `collector_devices.account_profile` |

直播评论执行结果写入 `live_comment_actions`，状态包括：

| 状态 | 含义 |
|---|---|
| `planned` | 已生成计划，未真实发送 |
| `sent` | 已执行真实发送 |
| `failed` | 执行失败 |
| `skipped` | 因开关、相关度、冷却、目标直播间不匹配等原因跳过 |

手机端拉取任务配置时，后端需要返回合并后的 `liveCommentConfig`、`liveCommentBotConfig`、`liveCommentRole`、`liveCommentGroup`、`liveCommentMode` 和 `accountProfile`。

## 6. 远程控制协议

直播评论控制必须和完整采集任务控制区分。

1. 后台直播评论页面下发命令必须携带 `payload.taskType = "live_comment_control"`。
2. 手机 Agent 收到该任务类型时，只更新直播评论子任务状态。
3. `START` 表示进入直播评论优先执行状态。
4. `PAUSE` 表示暂停直播评论执行，不退出 Agent。
5. `STOP` 表示停止当前直播评论子任务，不应让 Agent 继续在直播搜索页刷流程。
6. 普通采集命令不得误触发直播评论真实发送。

## 7. 指定直播间配置

指定直播间配置保存到设备级 `liveCommentBotConfig.targetRoom`。

| 字段 | 说明 |
|---|---|
| `enabled` | 是否启用指定直播间模式 |
| `anchorName` | 主播账号名 |
| `titleKeywords` | 直播间标题关键词 |
| `roomKeywords` | 直播间画面关键词 |
| `allowRealSend` | 是否允许真实发送 |
| `maxSendCount` | 本轮最多真实发送条数 |
| `minSendIntervalSeconds` | 真实发送最小间隔 |

启用指定直播间时，手机端必须先确认当前画面命中主播名、标题关键词或画面关键词。未命中时只记录跳过或失败原因，不生成真实发送动作。

## 8. 手机端执行流程

1. Agent 启动后注册设备、拉取任务配置并进入常驻轮询。
2. 收到 `live_comment_control` 的 `START` 命令后设置直播评论优先执行状态。
3. 打开抖音。
4. 使用主播名或目标关键词进入搜索页。
5. 在综合页或直播页查找目标直播间入口。
6. 进入直播间后读取当前页面文本。
7. 通过目标直播间规则校验主播名、标题或画面关键词。
8. 采样公开可见评论和直播间文本。
9. 使用账号画像和话术配置生成评论计划。
10. 通过安全网关判断是否允许真实发送。
11. 发送或跳过后上报 `live_comment_actions`。

## 9. 屏幕识别要求

屏幕识别不能只依赖单一按钮或固定坐标。

当前策略：

1. 优先读取无障碍控件文本、`text`、`desc` 和页面树。
2. 结合 OCR 或截图文本作为补充。
3. 搜索页、综合页、直播页分别识别，避免把任意直播间误判为目标直播间。
4. 目标直播间确认必须同时参考主播名、标题关键词、画面关键词和最近一次进入目标入口的上下文。
5. 控件点击失败时允许坐标兜底，但必须记录日志。
6. 每次进入目标直播间、跳过、失败、发送，都必须回传原因，便于后台复查。

## 11. 验收口径

最小验收链路：

1. 后台单设备保存账号画像和指定直播间配置。
2. 后台下发 `live_comment_control` 启动命令。
3. 手机 Agent 收到命令并回执。
4. 手机自动打开抖音并搜索指定主播或关键词。
5. 手机自动进入指定直播间。
6. 后台能看到计划、跳过、失败或发送记录。
7. 打开 `allowRealSend` 后，真实评论发送仍受条数和间隔限制。
8. 停止命令能让直播评论子任务停止，Agent 保持常驻可继续接收后续命令。
