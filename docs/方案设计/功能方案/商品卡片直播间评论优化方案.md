# 商品卡片直播间评论优化方案

> 状态：基于《商品卡片直播间评论.md》手写原稿整理，尚未实现。本文是新的可落地方案，原稿继续保留用于追溯业务口径。

## 1. 文档目标

本文把原稿中的“商品卡养号、直播间回复、直播养号2”整理为 `commerce_card_live_comment` 的可配置三阶段任务方案。

目标是保留原始业务逻辑：

1. 先从商城按商品关键词搜索和浏览商品卡。
2. 商品卡养号后进入直播板块识别目标直播间。
3. 目标直播间识别成功后执行评论。
4. 目标养号成功后，再进入普通直播流做关键词匹配观看。

本文不修改现有代码，只定义后续后台和手机端实现口径。

## 2. 核心业务结论

1. `夏橙` 只是默认商城搜索词，必须作为后台配置项，不允许写死。
2. 商品卡阶段的关键词用于找商品卡，不等同于目标直播间名称。
3. 目标直播间必须通过后台目标名称、别名、主播名或直播间标题相似度识别，不能只凭商品词进入。
4. 原稿里的“一直刷，不停止”在实现上必须解释为“在任务总时长、风控、STOP/PAUSE 和刷新阈值内持续查找”，不能形成无限循环。
5. 三个阶段属于同一个 `commerce_card_live_comment` 组合任务，但后台应允许按阶段开关控制只跑商品卡养号、只跑目标回复或跑完整链路。

## 3. 当前差异

当前商品卡直播评论第一版已经具备独立任务类型、商城搜索、商品卡匹配、真实评论双开关和审计记录，但与原稿业务仍有差异：

1. 当前实现偏向“刷商品卡后搜索目标直播间”，原稿要求商品卡养号结束后进入抖音直播板块识别目标直播间。
2. 当前商品卡浏览停留时间较短，缺少“单商品约 2 分钟”和“你可能还会喜欢”推荐商品循环。
3. 当前只有商品卡直播评论一段，没有把后续普通直播流养号整理成独立阶段。
4. 当前后台配置没有完整暴露商品卡养号、目标直播间回复和直播养号2的阶段参数。

## 4. 任务模式

后台配置新增 `mode` 或 `enabledStages`，用于决定执行范围。

| 模式 | 阶段 | 说明 |
|---|---|---|
| `product_nurture_only` | 阶段一 | 只做商品卡养号，目标直播间识别成功后结束 |
| `target_comment` | 阶段一、阶段二 | 商品卡养号成功后进入目标直播间并评论 |
| `full_nurture_comment` | 阶段一、阶段二、阶段三 | 完整执行商品卡养号、目标回复和直播养号2 |

默认建议使用 `target_comment`，阶段三需要单独开启，避免单次任务时间过长。

## 5. 总体流程

```text
配置预检
-> 阶段一：商品卡养号
-> 直播板块识别目标直播间
-> 阶段二：目标直播间回复
-> 阶段三：直播养号2
-> 完成并上报
```

任务运行中任何阶段收到 STOP、PAUSE、任务切换、风控、验证码、登录异常或总超时，必须停止当前点击、滑动、输入和等待，并上报明确原因。

## 6. 阶段一：商品卡养号

### 6.1 入口

1. 启动抖音。
2. 进入商城。
3. 点击搜索框。
4. 使用后台 `searchKeywords` 的首个有效词搜索，默认 `夏橙`。

### 6.2 商品卡浏览

1. 在商城搜索结果中识别商品卡。
2. 商品卡文本命中 `productKeywords` 后进入详情页。
3. 单商品详情页浏览约 `productCardDwellSeconds` 秒，默认 120 秒。
4. 浏览期间向下滑动，识别 `recommendationSignals`，默认 `你可能还会喜欢`。
5. 在推荐商品中继续匹配 `productKeywords`，命中后进入下一张商品卡。
6. 推荐区无命中时返回搜索结果继续找商品卡。

### 6.3 阶段结束

1. 单轮商品卡养号默认运行 `productNurtureMinutes=15` 分钟。
2. 结束后返回桌面或抖音首页，不强制停止应用、不清理应用数据。
3. 重新进入抖音直播板块，扫描目标直播间。
4. 识别到目标直播间，阶段一成功。
5. 未识别到目标直播间，按配置重新执行商品卡养号，但受 `productNurtureMaxRounds` 和 `taskMaxMinutes` 控制。

## 7. 阶段二：目标直播间回复

### 7.1 目标识别

1. 进入抖音直播板块。
2. 逐个读取直播间标题、主播名、直播间卡片文本和可见页面文本。
3. 与后台 `targetRoom.targetName`、`aliases`、`matchKeywords` 做标准化匹配。
4. 相似度达到 `similarityThreshold`，默认 0.90，且未命中 `forbiddenKeywords`，才允许进入。
5. 进入直播间后再次读取页面文本进行二次校验。

### 7.2 刷新规则

1. 每次进入直播板块后最多滑动 `targetLiveMaxSwipesPerRefresh` 个直播间。
2. 默认值为 25，后台允许配置范围为 20 到 30。
3. 超过阈值仍未命中目标，点击抖音左下角“首页”刷新，再重新进入直播板块扫描。
4. “持续查找”只在 `targetLiveStageMaxMinutes` 和 `taskMaxMinutes` 内生效。

### 7.3 评论规则

1. 目标直播间二次校验通过后，从 `commentPool` 取评论内容。
2. 每个直播间评论次数受 `maxCommentsPerRoom` 控制，默认 1。
3. 只有 `executeEnabled=true` 且 `manualExecutionApproved=true` 时才真实发送。
4. 未开启真实执行、未审批、重复直播间、发送失败都必须写入审计日志。
5. 阶段二不购买、不加购物车、不关注、不私信。

## 8. 阶段三：直播养号2

### 8.1 前提

阶段三只有在阶段一成功识别过目标直播间后才允许执行。阶段二评论可以成功，也可以因未审批而跳过，但目标直播间必须已经识别成功。

### 8.2 执行规则

1. 进入抖音直播板块。
2. 下滑直播间，读取直播间标题和页面可见文本。
3. 标题或可见文本命中 `liveNurtureKeywords` 后进入直播间。
4. 单房观看 `liveNurtureWatchMinMinutes` 到 `liveNurtureWatchMaxMinutes` 之间的随机时长，默认 10 到 20 分钟。
5. 阶段三不发送评论。
6. 退出当前直播间后继续寻找下一个匹配直播间。

### 8.3 刷新规则

1. 连续上滑或下滑 `liveNurtureRefreshAfterSwipes=10` 个直播间仍未命中关键词时，点击左下角“首页”刷新。
2. 刷新后重新进入直播板块继续识别。
3. 本阶段累计观看目标在任务启动时生成，默认 70 到 100 分钟。
4. 达到累计观看目标后正常完成任务。

## 9. 配置字段

配置优先进入直播目标配置中心；兼容期可继续写入 `p3ExtensionsConfig.commerceCardLiveComment`。

| 字段 | 默认值 | 说明 |
|---|---:|---|
| `enabled` | `false` | 是否启用商品卡片直播间评论任务 |
| `mode` | `target_comment` | 执行模式 |
| `searchKeywords` | `["夏橙"]` | 商城搜索词 |
| `productKeywords` | `["夏橙"]` | 商品卡和推荐商品匹配词 |
| `recommendationSignals` | `["你可能还会喜欢"]` | 推荐商品区域识别文本 |
| `productCardDwellSeconds` | `120` | 单商品详情页浏览时长 |
| `productNurtureMinutes` | `15` | 单轮商品卡养号时长 |
| `productNurtureMaxRounds` | `3` | 商品卡养号失败后的最大重试轮数 |
| `targetRoom` | 必填 | 目标直播间标准名、别名、主播名、禁入词和阈值 |
| `targetLiveMaxSwipesPerRefresh` | `25` | 每次刷新最多扫描直播间数，范围 20 到 30 |
| `targetLiveStageMaxMinutes` | `45` | 阶段二最大查找和评论时长 |
| `commentPool` | 现有配置 | 阶段二评论内容池 |
| `maxCommentsPerRoom` | `1` | 单直播间评论上限 |
| `executeEnabled` | `false` | 是否允许真实发送 |
| `manualExecutionApproved` | `false` | 是否人工批准真实发送 |
| `liveNurtureKeywords` | `[]` | 阶段三直播标题匹配词 |
| `liveNurtureRefreshAfterSwipes` | `10` | 阶段三未命中刷新阈值 |
| `liveNurtureWatchMinMinutes` | `10` | 阶段三单房最短观看时间 |
| `liveNurtureWatchMaxMinutes` | `20` | 阶段三单房最长观看时间 |
| `liveNurtureTotalMinMinutes` | `70` | 阶段三累计观看目标下限 |
| `liveNurtureTotalMaxMinutes` | `100` | 阶段三累计观看目标上限 |
| `taskMaxMinutes` | `180` | 整个任务最大运行时长 |

保存配置时必须校验：

1. 所有最小值不大于最大值。
2. `searchKeywords`、`productKeywords` 非空。
3. 开启阶段二时 `targetRoom` 必填。
4. 开启阶段三时 `liveNurtureKeywords` 必填。
5. `targetLiveMaxSwipesPerRefresh` 必须在 20 到 30 之间。
6. `executeEnabled` 和 `manualExecutionApproved` 都为真时，后台必须展示真实评论风险提示。

## 10. 后台影响

### 10.1 配置页面

后台需要把商品卡片直播间评论从高级 JSON 中拆出来，至少提供以下配置区：

1. 基础开关：启用状态、执行模式、任务总时长。
2. 商品卡养号：商城搜索词、商品匹配词、单卡浏览秒数、单轮养号分钟、推荐区信号、失败重试轮数。
3. 目标直播间：目标名称、别名、主播名、禁入词、相似度阈值、单次刷新扫描直播间数。
4. 评论配置：评论池、单房评论上限、真实发送开关、人工审批开关。
5. 直播养号2：标题关键词、单房观看区间、累计观看区间、未命中刷新阈值。

### 10.2 API 和配置下发

1. 任务类型继续使用 `commerce_card_live_comment`。
2. 手机端配置接口继续返回 `commerceCardLiveComment`，同时在 `liveTargets` 中返回标准化目标配置。
3. 新字段优先放入 `runtimeConfig`，避免破坏现有任务调度协议。
4. 旧字段 `scanMinutesPerRound`、`watchMinutesPerLive`、`maxRounds` 在兼容期映射到阶段一和阶段二字段。

### 10.3 日志展示

日志中心需要展示：

1. 当前阶段。
2. 当前轮次。
3. 商品卡浏览数量。
4. 直播间滑动数量。
5. 刷新次数。
6. 目标直播间匹配结果。
7. 评论发送或跳过原因。
8. 阶段三累计观看分钟数。

## 11. 手机端影响

`commerce-card-live-runner.js` 需要从当前单段循环改为三阶段状态机：

```text
product_nurture
-> target_live_comment
-> live_nurture
```

`douyin.js` 需要补齐或收敛以下能力：

1. 进入商城并搜索商品关键词。
2. 浏览商品详情页并在长等待中响应 STOP/PAUSE。
3. 识别“你可能还会喜欢”推荐区域并继续匹配商品卡。
4. 进入抖音直播板块。
5. 在直播板块按目标直播间规则扫描和刷新。
6. 在直播板块按标题关键词扫描普通直播间。
7. 点击左下角“首页”刷新后重新进入直播板块。

当前不应继续在商品卡阶段结束后调用普通搜索入口寻找目标直播间；目标识别应发生在直播板块扫描链路里。

## 12. 状态与检查点

检查点至少保存：

1. `phase`：`product_nurture`、`target_live_comment`、`live_nurture`。
2. `taskStartedAt`、`phaseStartedAt`、`phaseDeadlineAt`。
3. 当前商品搜索词、商品卡浏览数量、推荐商品跳转次数。
4. 目标直播间扫描次数、刷新次数、候选名称和匹配分数。
5. 已评论直播间集合和评论动作审计编号。
6. 阶段三本次随机出的单房观看时长、累计观看目标和已观看分钟数。
7. 最近页面文本摘要和停止原因。

PAUSE 后保留检查点，RESUME 从当前阶段恢复；STOP 清理当前任务状态并返回待命。

## 13. 日志事件

| 事件 | 含义 |
|---|---|
| `commerce_card_task_start` | 商品卡片直播间评论任务启动 |
| `product_nurture_start` | 商品卡养号开始 |
| `product_card_opened` | 进入匹配商品卡 |
| `product_recommendation_scan` | 扫描推荐商品 |
| `product_nurture_finished` | 单轮商品卡养号结束 |
| `target_live_scan_start` | 直播板块目标直播间扫描开始 |
| `target_live_refresh` | 超过扫描阈值后刷新 |
| `target_live_matched` | 目标直播间匹配成功 |
| `target_live_comment_result` | 目标直播间评论发送、跳过或失败 |
| `live_nurture_start` | 直播养号2开始 |
| `live_nurture_room_watch` | 进入匹配直播间观看 |
| `commerce_card_task_finish` | 任务完成 |

常见结束原因：

| 原因 | 含义 |
|---|---|
| `product_nurture_target_found` | 商品卡养号后识别到目标直播间 |
| `product_nurture_target_not_found` | 商品卡养号后未识别到目标直播间 |
| `target_live_not_found` | 阶段二在限制内未找到目标直播间 |
| `target_live_comment_skipped` | 未审批或开关关闭，跳过真实评论 |
| `live_nurture_completed` | 阶段三累计观看完成 |
| `task_timeout` | 任务总时长超限 |
| `manual_pause` | 后台或本地暂停 |
| `manual_stop` | 后台或本地停止 |
| `risk_control` | 风控、验证码或账号异常 |

## 14. 安全边界

1. 不购买。
2. 不加购物车。
3. 不关注。
4. 不私信。
5. 不绕过验证码、登录校验或平台风控。
6. 不在未命中目标直播间时发送评论。
7. 不在未开启真实发送和人工审批时发送评论。
8. 不允许无限滑动、无限刷新或无法中断的长等待。

## 15. 验收标准

1. 保留原稿文件，优化方案作为新文档存在。
2. 后台能配置商城搜索词，`夏橙` 只是默认值。
3. 商品卡养号能进入商城搜索、打开匹配商品卡、单卡浏览约 120 秒、识别推荐商品并继续循环。
4. 单轮商品卡养号默认约 15 分钟。
5. 商品卡养号结束后从直播板块识别目标直播间，不跳到普通搜索目标直播间链路。
6. 目标直播间每次刷新最多扫描 20 到 30 个直播间，默认 25 个。
7. 超过扫描阈值后点击首页刷新，再重新进入直播板块扫描。
8. 目标直播间必须二次校验后才能评论。
9. 未审批、未开启真实发送、重复直播间和发送失败均有审计记录。
10. 阶段三能按标题关键词进入普通直播间，单房观看 10 到 20 分钟，累计观看 70 到 100 分钟后结束。
11. STOP、PAUSE、RESUME、任务切换、风控和总超时在三个阶段都能生效。
12. 普通 `live` 和旧 `live_comment` 不会进入本任务的任一阶段。

## 16. 实施顺序

1. 确认本文字段和默认值。
2. 更新共享类型、API schema、后台配置表单和配置下发。
3. 手机端实现商品卡养号阶段，包括推荐商品循环和 120 秒可中断浏览。
4. 手机端实现直播板块目标直播间扫描和首页刷新。
5. 手机端实现目标直播间二次校验、评论审计和重复直播间控制。
6. 手机端实现直播养号2的标题关键词匹配、单房随机观看和累计目标。
7. 补充定向测试和静态语法检查。
8. 打包 APK 并做真机回归，重点验证 STOP/PAUSE、目标匹配、刷新阈值和真实评论开关。
