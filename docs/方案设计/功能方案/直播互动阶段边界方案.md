# 直播互动阶段边界方案

## 1. 背景与来源

本文件归并直播互动方向的阶段方案，包括 M3/P0-P3、评论分类、风控开关、角色编组、账号机器人、直播聊天机器人 P0、设备画像和库表设计。

被吸收的阶段旧稿不再作为当前阅读入口。当前以本文件说明直播互动方向的业务边界、对象、配置、状态、验收和不做事项。

## 2. 核心结论

1. 当前默认主线不是“目标账号触发、跟随账号同步评论”，而是“每台设备或每个账号绑定一个直播聊天机器人画像”。
2. 机器人只在三农相关直播间生成自然聊天评论计划，默认状态是 `planned` 或 `skipped`。
3. 真实评论发送必须同时满足后台开关、本地悬浮窗确认、频控、风控、审计和人工停止能力。
4. P0/P1 仍以只读采样、评论分类、计划记录为主；P2 才评估受控发送；P3 的点赞、关注、挂人等动作默认关闭。
5. 后台不能直接打开真实发送能力；任何真实互动都必须单独审批和验收。

## 3. 阶段边界

| 阶段 | 目标 | 允许能力 | 禁止/限制 |
|---|---|---|---|
| P0 | 只读观察和评论计划 | 进入直播间、读取可见评论、判断三农相关性、生成 `planned/skipped` 计划、上传证据 | 不自动发送评论，不点赞，不关注 |
| P1 | 评论分类与稳定性 | 评论去重、分类、触发事件识别、机器人模板推荐、人工待办 | 不做自动执行 |
| P2 | 受控评论执行评估 | 评论动作队列、冷却限频、黑名单、审计、人工停止 | 必须默认关闭真实发送 |
| P3 | 点赞/关注等扩展评估 | 仅做配置、风险和验收方案评估 | 未审批不得执行 |

## 4. 业务对象

| 对象 | 说明 |
|---|---|
| `accountProfile` | 设备或账号的长期画像，描述地区、身份、作物、经验、口吻和禁用话题 |
| `liveCommentMode` | 直播评论模式：`off`、`target_follow`、`agri_chatbot` |
| `liveCommentBotConfig` | 机器人策略配置，包含模板池、频控、阈值、评论类型和安全策略 |
| `live_observation_record` | 直播间只读观察记录，保存房间、评论样本和截图证据 |
| `live_trigger_event` | 目标账号发言、关键词命中、高频问题等触发事件 |
| `live_comment_action` | 评论计划或执行记录，必须有状态、来源、原因和审计 |
| `live_risk_policy` | 冷却、限频、黑名单、人工确认、异常停止策略 |

## 5. 数据分层

| 层级 | 表/字段 | 含义 |
|---|---|---|
| 设备身份层 | `collector_devices.account_profile` | 该设备登录账号的画像 |
| 任务行为层 | `device_task_configs.live_comment_mode` | 当前任务的直播评论模式 |
| 任务行为层 | `device_task_configs.live_comment_bot_config` | 当前任务的机器人策略、频控和话术 |
| 审计记录层 | `live_comment_actions.raw_payload` | 记录画像、相关性、生成原因和安全过滤结果 |

设计原因：

1. 账号画像跟设备长期绑定，不随任务频繁变化。
2. 直播评论策略跟任务绑定，可以按任务调整。
3. 审计记录保留当时使用的画像快照，方便追查。

## 7. 主流程

```text
进入直播间
  -> 读取直播间标题、屏幕文字、评论样本
  -> 判断是否三农相关
  -> 判断是否适合评论
  -> 根据账号画像和机器人配置生成候选评论
  -> 安全过滤和频控检查
  -> 生成 planned/skipped 计划并上报后台
  -> 如果真实发送开关和本地确认全部满足，再进入受控发送
  -> 上报 sent/failed/skipped 和证据
```

## 8. 三农相关性判断

第一阶段不用自由生成模型，先用本地规则和关键词判断。

| 信号 | 示例 | 权重 |
|---|---|---|
| 作物词 | 水稻、玉米、小麦、蔬菜、大豆、果树 | 高 |
| 农事词 | 种植、施肥、除草、病虫害、防治、收割 | 高 |
| 农资词 | 农药、肥料、种子、农机、育苗 | 中 |
| 场景词 | 大棚、农田、合作社、基地、养殖 | 中 |
| 排除词 | 娱乐、游戏、八卦、招商、卖课、私信 | 负向 |

规则：

1. 三农分数达到 `roomRelevanceThreshold` 才进入评论规划。
2. 只有“直播”“主播”等泛词时不允许发言。
3. 营销、私信、卖课、招商等风险词过高时跳过。

## 9. 评论计划

P0 只使用模板池，不接入 AI 自由生成。

| 类型 | 用途 |
|---|---|
| `question` | 向主播或评论区自然提问 |
| `agree` | 简短赞同已有观点 |
| `experience_share` | 结合画像分享轻量经验 |
| `knowledge_tip` | 给出低风险常识提醒 |

评论必须满足：

1. 长度控制在 4 到 40 个中文字符。
2. 不包含联系方式、私信、加微信、卖课、代理、招商。
3. 不承诺保证效果，不夸大收益。
4. 同一直播间不重复同一句话。
5. 同一设备满足最小间隔、每直播间上限和每小时上限。

不满足则生成 `skipped` 并记录原因。

## 10. 上报字段

复用或扩展 `live_comment_actions.raw_payload`：

```json
{
  "mode": "agri_chatbot",
  "botName": "水稻交流号A",
  "profileName": "桂北水稻种植户",
  "commentType": "question",
  "replyText": "高温天这个管理要注意啥",
  "status": "planned",
  "roomRelevance": {
    "score": 78,
    "matchedKeywords": ["水稻", "病虫害"]
  },
  "safety": {
    "passed": true,
    "reason": ""
  }
}
```

主字段映射：

| 字段 | 值 |
|---|---|
| `leaderAccountName` | 空或机器人名 |
| `triggerText` | 当前直播间摘要或触发语境 |
| `matchedKeywords` | 三农相关性命中的关键词 |
| `replyText` | 计划评论 |
| `status` | `planned/skipped/sent/failed` |
| `skipReason` | 跳过原因 |

## 11. 后台页面影响

如果恢复直播互动方向，后台至少需要：

1. 直播观察记录页。
2. 评论计划/动作记录页。
3. 账号画像配置入口。
4. 机器人策略配置入口。
5. 风控策略页。
6. 审计日志页。

当前主后台仍以设备、任务、采集记录、心跳、运行日志和远程命令为主。

## 12. 手机端影响

建议模块：

| 模块 | 职责 |
|---|---|
| `live-room-relevance-detector` | 判断直播间是否三农相关 |
| `agri-comment-bot-planner` | 根据语境和机器人配置生成评论计划 |
| `comment-safety-filter` | 过滤营销、引流、重复、过频评论 |
| `live-room-sampler` | 采样直播间文本和评论，按模式分支处理 |

`live-room-sampler` 模式：

1. `off`：只记录，不规划评论。
2. `target_follow`：保留旧目标跟随逻辑，作为实验模式。
3. `agri_chatbot`：走账号机器人逻辑，作为当前建议主线。

## 13. 验收标准

1. `liveCommentMode=off` 时不生成评论计划。
2. `liveCommentMode=target_follow` 时仍走旧目标跟随逻辑。
3. `liveCommentMode=agri_chatbot` 时不要求目标账号触发。
4. 非三农直播间只上报 `skipped` 或不规划。
5. 三农直播间可以生成 `planned`。
6. 计划里包含机器人名、画像名、相关性分数、评论类型和跳过原因。
7. 重复评论、低相关、风险词、频控超限会跳过。
8. 默认不真实发送。
9. 真实发送必须受本地确认、后台开关、频控和审计约束。

## 14. 当前不做

1. 不绕过验证码、登录校验或平台风控。
2. 不采集非公开内容。
3. 不默认自动发送评论。
4. 不默认点赞、关注、私信、挂人。
5. 不承诺平台标签、推荐权重或直播间流量结果。
6. 不把直播代运营结果写成技术验收。
7. 不使用虚假身份做平台认证或身份声明。

## 15. 后续落地顺序

1. 固化 `accountProfile`、`liveCommentMode`、`liveCommentBotConfig` 配置返回。
2. 手机端新增三农相关性判断。
3. 手机端新增模板式评论计划器。
4. 手机端新增安全过滤和频控。
5. 后台展示 `planned/skipped` 记录和跳过原因。
6. 真机验证只生成计划，不发送。
7. 如需真实发送，再单独进入 P2 受控发送评审。
