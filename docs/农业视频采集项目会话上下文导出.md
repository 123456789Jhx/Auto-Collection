## 3. 已分析 APK 项目结论

该 APK 是一个 Auto.js Pro 打包项目，功能名为“番茄广告助理”。

它的核心结构是：

```text
Android APK 壳
  -> 内嵌 Auto.js 运行时
  -> 启动 assets/project/main.js
  -> main.js 从腾讯云 COS 拉取远程 JS
  -> engines.execScript() 执行远程脚本
  -> 远程脚本通过无障碍、悬浮窗、截图 OCR 操作手机 App
```

### 3.1 APK 启动链

1. `AndroidManifest.xml` 注册启动 Activity：`com.fqggzl.cn.SplashActivity`。
2. `App.java` 初始化 Auto.js runtime、项目配置、脚本加密环境。
3. `SplashActivity.java` 处理权限和 `runScript()`。
4. `project.json` 指定入口为 `main.js`。

### 3.2 本地入口脚本

`decrypted/main.js` 的核心逻辑：

```js
let res = http.get(url)
let str = res.body.string()
engines.execScript('adsad', str)
```

结论：

1. APK 本地脚本不包含主要业务。
2. 真正业务由远程 JS 决定。
3. 远程脚本可以在不更新 APK 的情况下改变行为。

### 3.3 远程主脚本功能

`decrypted/remote_adsad.js` 是主逻辑，主要功能：

1. 显示 Auto.js UI 配置页。
2. 引导开启无障碍服务。
3. 引导开启悬浮窗权限。
4. 请求截图权限。
5. 显示悬浮窗开始/停止按钮。
6. 打开“番茄免费小说”。
7. 使用 OCR 和无障碍控件识别页面文字。
8. 自动点击签到、领取奖励、看视频赚金币等入口。
9. 自动滑动视频。
10. 检测卡住后返回、重启目标 App 或关闭弹窗。

## 4. 用户最终业务方向

用户不是要继续研究“番茄广告助理”，而是希望建设一个农业视频知识采集系统。

核心目标：

```text
手机自动打开抖音等平台
  -> 自动刷短视频或长视频
  -> 发现农业相关知识视频
  -> 获取视频信息、文案、字幕、热门评论
  -> 发送到后台
  -> 后台做农业知识分析和素材沉淀
```

用户强调：

1. 手机里面肯定要装自动化脚本。
2. 不希望一开始做太重的平台。
3. 后台是后台的事，手机端先跑通自动化采集。
4. 企业级方向可以后续扩展，但当前重点是手机端自动化脚本和后台接入设计。

## 5. 关于“爬数据”和“手机自动化”的结论

讨论过两种数据来源：

1. 直接爬抖音数据。
2. 手机自动化脚本刷视频采集。

结论：

```text
不要二选一。
推荐官方 API + 手机自动化脚本双数据源。
```

### 5.1 官方 API 适合做

1. 按关键词获取合规搜索入口。
2. 获取公开视频基础信息。
3. 获取授权账号自己的视频数据。
4. 获取部分互动指标。
5. 作为稳定、可追踪的数据来源。

### 5.2 手机自动化脚本适合做

1. 推荐流采样。
2. 搜索结果页现场采集。
3. OCR 画面文案。
4. OCR 字幕。
5. 读取热门评论。
6. 截图留证。
7. 补充官方 API 拿不到的现场信息。

### 5.3 最终推荐架构

```text
官方 API 数据源
  -> 后台定时拉取/搜索农业视频
  -> 入候选库

手机自动化数据源
  -> 手机刷推荐流/搜索流
  -> OCR/评论/字幕/截图
  -> 上传后台
  -> 入候选库

后台统一去重、解析、审核、入知识库/素材库
```

## 8. 新项目第一阶段建议目标

第一阶段目标不要过重，只跑通手机端采集闭环：

```text
Auto.js/AutoX.js 手机脚本
  -> 打开抖音
  -> 进入搜索或推荐流
  -> OCR 识别当前视频
  -> 命中农业关键词
  -> 采集截图、OCR 文本、热门评论
  -> POST 到后台接口
```

最小后台接口：

```http
POST /api/mobile/video-captures
```

最小上传字段：

```json
{
  "taskId": "task_001",
  "deviceId": "android_001",
  "platform": "douyin",
  "keyword": "水稻病虫害",
  "screenText": "OCR 识别全文",
  "titleText": "视频标题或主文案",
  "subtitleText": "字幕文本",
  "authorName": "作者昵称",
  "metricsText": "点赞评论等文本",
  "hotComments": ["评论1", "评论2"],
  "capturedAt": "2026-05-28T10:00:00+08:00"
}
```

## 9. 需要继续展开的问题

新项目中可以继续展开以下问题：

1. Auto.js 还是 AutoX.js 作为第一阶段运行环境。
2. 手机脚本是否打包 APK，还是先直接在脚本 App 中运行。
3. 抖音搜索页、推荐流、话题页优先适配哪一个入口。
4. OCR 方案使用 Auto.js 内置 OCR 还是外接手机端 OCR 插件。
5. 评论采集深度，第一阶段建议只采集可见热门评论。
6. 图片上传方式，第一阶段 Base64，后续对象存储预签名。
7. 官方 API 的权限申请和额度评估。
8. 候选视频去重键设计。
9. 后台是否先用 Java Spring Boot 实现最小接口。
10. 后续是否引入 Python 服务处理 ASR、OCR、LLM。

## 11. 边界约束

后续实现时保持以下边界：

1. 不做自动点赞、评论、关注、私信。
2. 不绕过验证码、登录校验或平台风控。
3. 不批量下载完整视频。
4. 不抓取非公开内容。
5. 手机端只做候选采集和证据上传。
6. 最终知识分析、审核、入库在后台完成。
7. 外部采集进入素材获取环节，不替代原视频生产生命周期。
