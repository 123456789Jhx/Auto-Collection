## 目标和范围

本期目标是在一周内完成“后台控制手机脚本自动发布视频”的最小可验收闭环：

1. 后台可以创建、审核、分配和重试视频发布任务。
2. 手机脚本可以从后台领取发布任务，执行发布流程，并回传状态、日志、截图和失败原因。
3. 后台可以查看发布任务状态、设备执行进度、异常原因和执行证据。
4. 视频源接口未到位时，先支持后台手动录入或 Mock 视频源数据；接口文档到位后再替换为正式视频源适配器。

本期包含：

1. 发布任务数据结构和后台 API。
2. 发布任务管理页面。
3. 平台账号和设备绑定。
4. 手机端发布任务领取、执行、回传。
5. 发布异常状态、日志和截图证据。
6. 视频源接口预留字段和 Mock 接入。

本期不包含：

1. 多平台完整适配。
2. AI 自动生成标题、文案和话题。
3. 复杂自动排期算法。
4. 发布后数据采集和效果分析。
5. 绕过验证码、登录校验或平台风控。
6. 自动点赞、评论、关注、私信等互动行为。

## 风险和需要确认

- 风险：视频源接口文档未到，正式字段和回写方式无法最终确认。
- 处理：本周先用手动创建和 Mock 视频源完成发布闭环，接口文档到位后补视频源适配器。
- 风险：平台 App 发布页面 UI 变化会导致脚本定位失败。
- 处理：每个关键步骤回传截图和页面文本，失败时进入人工处理，不继续盲点。
- 风险：账号未登录、验证码、风控、权限弹窗会阻断发布。
- 处理：脚本不绕过限制，只上报 `MANUAL_REQUIRED`，后台等待人工处理。
- 风险：压缩到一周后，复杂排期、多平台和发布后数据分析无法同时完成。
- 处理：本期只交付单平台、单账号/少量账号、小范围可验收闭环。
- 需要确认：第一周验收是否以“手动创建发布任务 + 真机发布尝试 + 后台证据回传”为完成标准。
- 需要确认：本期优先适配的平台是否仍为抖音。
- 需要确认：测试账号和测试视频是否由业务方提前准备。

## 一周验收口径

1. 后台可以手动创建一条视频发布任务。
2. 发布任务可以绑定平台账号和执行设备。
3. 手机脚本可以领取任务并进入发布执行流程。
4. 手机脚本可以回传执行步骤、运行日志、截图和最终结果。
5. 发布成功时后台显示 `PUBLISHED` 和发布时间。
6. 发布失败或被平台阻断时后台显示明确异常码和截图证据。
7. 视频源接口未到时，Mock/手动录入数据可以完成同样流程。
8. GitHub 仓库补齐排期、验收口径、截图或录屏证据，满足成果提交规范。

## 压缩交付边界

为了将工期压缩到 2026-06-15 至 2026-06-21 这一周内，本期只做最小闭环：

1. 只保证一个主平台的发布流程。
2. 只做基础账号设备绑定，不做复杂账号池调度。
3. 只做手动/Mock 视频源，不等待正式接口。
4. 只做发布任务状态和证据，不做发布后效果采集。
5. 只做异常停止和上报，不做自动绕过或自动恢复所有异常。
