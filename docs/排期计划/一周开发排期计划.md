## 目标和范围

本周不再把所有能力放在一个顺序流程里，而是按职责拆分为 4 个独立模块：

1. 心跳常驻模块。
2. 刷视频模块。
3. 刷直播模块。
4. 直播评论模块。

本周目标是把这些模块的边界、状态和调度关系明确下来，并完成最小可用拆分。

本周包含：

1. 心跳独立常驻，app 打开即启动，后台继续上报。
2. 刷视频、刷直播、直播评论分开执行。
3. 直播评论支持“进入指定直播间 -> 识别 -> 发送”的完整链路。
4. 后台命令按任务类型路由，互不覆盖。
5. 文档收口到当前有效范围、方案和排期。

本周不包含：

1. 多平台发布完整适配。
2. 发布后数据分析和效果优化。
3. AI 自动生成标题、文案、话题。
4. 绕过验证码、登录校验或平台风控。
5. 未授权的点赞、关注、私信等真实互动能力。

## 拆分方案

### 1. 常驻心跳

- 单独线程维护。
- 只负责上报设备在线、版本、运行状态、最近任务状态。
- 不依赖刷视频、刷直播、直播评论是否正在执行。
- app 真正退出时才停止。

### 2. 刷视频任务

- 独立任务入口。
- 只处理推荐流、识别、命中、翻页和候选记录。
- 不直接调用直播评论逻辑。

### 3. 刷直播任务

- 独立任务入口。
- 只处理直播流进入、停留、识别和上下文恢复。
- 不直接触发评论发送。

### 4. 直播评论任务

- 独立任务入口。
- 只处理指定直播间进入、评论识别、发送、失败回传和审计。
- 需要独立限流、失败重试和目标直播间校验。

### 5. 任务调度器

- 接收后台任务类型。
- 路由到对应模块。
- 同一台手机同一时刻只允许一个前台任务执行。
- 心跳不受任务执行状态影响。

## 风险和需要确认

- 风险：任务拆分后，状态、恢复和互斥逻辑会变复杂。
- 风险：抖音 UI 变化会影响视频、直播和评论识别。
- 风险：无障碍、悬浮窗、权限弹窗会打断前台任务。
- 需要确认：本周是否先做“心跳 + 调度 + 评论任务”。
- 需要确认：刷视频和刷直播是否都要保留当前自动恢复策略。
