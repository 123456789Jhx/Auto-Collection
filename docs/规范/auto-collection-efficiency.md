# 效率改进与执行标准

- 项目：Auto Collection
- 负责人：张润
- 来源日期：2026-06-11

## 建议沉淀方向

- 生产库清理必须先确认容器、库名和表计数。
- GitHub 验收材料统一放在 `docs/`。
- 手机端设备身份必须使用唯一 ID 和 token，不允许多台设备共用默认 ID。

## 标准化方案

### 适用场景

1. 清理手机脚本上报产生的脏数据。
2. 发布新版 API 或 APK 后验证设备注册逻辑。
3. 按 GitHub 成果规范整理项目材料。

### 输入材料

1. 服务器部署目录和 Docker Compose 文件。
2. 后台线上地址和健康检查地址。
3. 数据库表计数 SQL。
4. README、overview、acceptance、deployment、evidence 等文档。

### 操作步骤

1. 先确认线上后台 API 返回的数据是否和目标数据库计数一致。
2. 只进入 `auto-collection-postgres` 容器操作 Auto Collection 生产库。
3. 清理前后分别执行表计数 SQL。
4. 清理后观察旧脚本请求是否被 401 或 409 拒绝。
5. 将验收材料放入 `docs/`，README 只保留入口和核心说明。

### 输出结果

1. 生产库脏数据表计数为 0。
2. 未注册旧脚本不能继续写入后台。
3. README 和 `docs/` 满足 GitHub 成果提交规范。
