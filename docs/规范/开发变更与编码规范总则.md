# 开发变更与编码规范总则

## 1. 目的

本文件是项目统一变更入口。

任何接口、数据库、手机脚本、后台页面、部署脚本或文档变更，都先写方案，再确认，再落地。

## 2. 生效范围

适用于：

1. 后端接口。
2. 数据库表结构。
3. 手机自动化脚本。
4. 后台管理页面。
5. 部署脚本与环境变量。
6. 文档、规范、项目记录。

## 3. 变更流程

1. 先写方案。
2. 方案要说明现状、目标、变更范围、不变范围、风险和落地顺序。
3. 发给我确认后再改代码。
4. 落地后补验证结果。

## 4. 编码要求

1. 先读现有代码和文档，再改。
2. 优先复用现有模型、表、接口和页面。
3. 数据结构变更必须同步 migration。
4. 接口变更必须同步类型定义。
5. 手机脚本改动必须保留可审计日志。

## 5. 文档要求

1. 项目开发放 `docs/项目开发/`。
2. 当前范围放 `docs/当前需求/`。
3. 方案放 `docs/方案设计/`。
4. 过程、会议、联调和历史材料放 `docs/项目开发/`。

## 6. 设备与安全

1. 设备对外统一使用 `deviceCode`。
2. 手机本地 token 统一使用 `deviceToken`。
3. 设备注册必须唯一。
4. 真实互动能力必须有独立开关、范围和审计。

## 7. 部署与清理

1. schema 变更和应用部署分开看。
2. 高风险清理必须明确保留范围。
3. 生产部署脚本和本地脚本都要保留。
