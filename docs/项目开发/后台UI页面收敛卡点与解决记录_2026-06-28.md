# 后台 UI 页面收敛卡点与解决记录

记录日期：2026-06-28

线上地址：http://106.54.41.106:18080

## 1. 本轮目标

本轮按 `docs/方案设计/功能方案/后台UI页面收敛与操作流程方案.md` 落地后台 UI 调整，重点解决三类问题：

1. 工作台和设备运行信息重复，设备详情固定占屏。
2. 任务调度中心按钮和筛选过多，页面出现英文状态和技术字段。
3. 直播评论页需要聚焦设备直播评论参数调整和设备操作，不再保留自动刷新下拉。

## 2. 已完成调整

| 页面 | 处理结果 |
|---|---|
| 工作台 | 合并设备运行能力，设备卡片改为横向卡片列表，心跳状态加大加粗，点击卡片从右侧打开设备详情抽屉 |
| 设备运行 | 从左侧导航移除，不再保留重复入口 |
| 任务调度 | 去掉只读推荐、手动分配、设备分组、应用筛选；任务、状态、来源和命令展示改为中文 |
| 直播评论 | 去掉 5/15/30 秒刷新下拉，保留手动刷新；点击设备从右侧打开评论参数和操作抽屉 |
| 执行记录 | 直播评论跳过/失败原因增加常见原因码中文映射，减少运营页面直接暴露技术字段 |

## 3. 保留的原有逻辑

1. 工作台设备卡片点击仍然用于查看该设备详情，只是详情从固定右栏改为右侧抽屉。
2. 任务调度仍通过原有 `createTaskAssignment` 下发视频、直播、直播评论和停止操作。
3. 直播评论仍通过原有设备任务配置接口保存指定直播间、账号画像和评论模式。
4. 采集记录和日志中心的“手机卡片 -> 日期卡片 -> 明细”路径本轮未修改。
5. 手机 Agent、数据库 schema 和 API 业务逻辑本轮未变更。

## 4. 卡点与解决

| 卡点 | 原因 | 解决方式 |
|---|---|---|
| 工作台卡片点击后没有按原流程打开详情 | 上版 UI 把详情固定在右侧区域，点击反馈不明显 | 新增 `detailOpen` 状态，设备卡片点击后打开 `.ops-detail-drawer`，每日进度和最近心跳只在抽屉打开时拉取 |
| 设备运行和工作台重复 | 两个页面都在表达设备状态、心跳和采集进度 | 将设备运行能力收敛到工作台，移除 `设备运行` 导航入口，减少重复页面 |
| 任务调度出现英文状态和技术字段 | 表格和详情直接展示 assignment status、source、targetContext、commandStatus | 增加中文映射函数，详情中展示“手动调整、指定直播间、待下发、已停止”等运营可读文案，并移除 JSON 技术块 |
| 任务调度操作入口不直观 | 用户需要理解顶部手动分配和表格状态 | 表格操作统一为 `[视频] [直播] [评论] [停止]`，直接对当前行设备下发任务 |
| 直播评论页承担内容过多 | 固定右侧详情和自动刷新下拉压缩了主表空间 | 主区只保留设备评论状态和执行记录，详情改右侧抽屉，自动刷新下拉删除，保留手动刷新 |
| 本地浏览器直接访问远端 API 失败 | Dev 环境直接跨域访问 `106.54.41.106:18080/api/v1` 会被浏览器限制 | 本地验证时临时将 `VITE_API_BASE_URL_DEV=/api/v1` 并通过 Vite proxy 转发到 `http://106.54.41.106:18080` |
| 直播评论执行记录显示原因码 | 后端和手机端存储的是稳定英文原因码 | 前端新增常见原因码中文映射，不改变历史数据结构 |
