# 业务脚本更新与加载修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans when independently executing this plan. The current coordinator implements the tightly coupled runtime changes locally with TDD and delegates only isolated build tooling work and review.

**Goal:** 防止旧业务包覆盖新 APK，并证明视频/评论词实际加载来源。

**Architecture:** APK 生成 schemaVersion 2 基线 manifest；下载、激活、启动共享验证逻辑。可信业务包进入固定运行视图，基座相对依赖通过本地代理复用 APK 模块。

**Tech Stack:** AutoJS CommonJS、Node test、PowerShell、Bun TypeScript。

**Spec:** `docs/方案设计/功能方案/远程脚本功能模块方案.md` 第 6.5 节。

## Global Constraints

- 在用户指定的共享工作区保留已有未提交修改；不切分或还原其他对话的文件。
- 本轮不构建 APK/业务 ZIP、不改写共享 AutoJs6 暂存区、不安装或发布、不提交 Git。
- 修改/新增 JS/TS 不超过 600 行，优先保持 450 行以内；存量超限另记问题，不因本任务全量重构。
- schemaVersion 为 2，channel 为 biz-scripts；业务版本独立于 APK versionName。
- 不改变视频矩形坐标、方向、520ms 时长和评论词抓取规则。

## Task 2: 构建时基线与业务包契约

文件：`scripts` 下新增独立 manifest helper 和 fixture 测试；修改 `package-autojs-apk.ps1`、`bundle-autojs.ps1`、API `biz-script-release.service.ts` 及对应注入测试。

接口：基线字段 `schemaVersion,channel,version,apkBuildId,files,baseFiles,sourceSha256,baseCompatibilityId`；版本默认 UTC `yyyyMMdd.HHmmssfff`。指纹为排序后的 `path:sha256` LF 连接 UTF-8 SHA256。

- [x] 临时 fixture 测试先失败：业务变化只改业务指纹，基座变化改兼容标识；输出逐文件 SHA 对应实际内容。
- [x] helper 只操作显式 SourceRoot/OutputPath；打包入口在暂存最终配置后生成内置基线，最终 APK 内容核验成功后导出基线 sidecar。
- [x] bundle 接收 `BaselineManifestPath` 并校验基座匹配；manifest 内外同步协议字段；增量校验兼容。
- [x] API 从显式基线文件分配高于 max(远端最新,APK基线) 的版本并向 bundle 传参；缺基线明确失败。
- [x] 只运行 fixture/helper 和注入式 API 测试，不调用真实 packager 或 ZIP 构建入口。
