- 日期：2026-07-28
- 状态：设计定稿（待实施）
- 依据文档：《外部发布任务接口说明.md》、《发布视频.md》（业务需求）、2026-07-28 项目代码勘察

## 0. 现状诊断：旧业务"覆盖"新业务的真相

**先说结论：不是旧配置覆盖了新配置，而是命令路由的默认值把你带进了旧业务。**

实际链路（已用代码和数据库记录双向核实）：

```
设备页点"启动"
  → DevicesPage.tsx:220 sendCommand(deviceCode, "START")   ← 不携带 taskType
  → POST /admin/mobile-commands {commandType:"START", payload:{}}
  → 手机 control-loop.js:156  normalizeCommandTaskType(payload.taskType, "video")
  → 缺省默认 = video（旧视频采集）
  → 用 config.js:27 的旧关键词"大棚蔬菜"开始采集
```

而发布视频走的是**完全独立的另一扇门**：`control-loop.js:623` 首先判断 `commandType === "PUBLISH_VIDEO_TASK"`，走热更新目录里的 `features/publish-video/发布视频-入口.js`。配置存储也是隔离的（采集参数在 `config.js`，publish_video 配置在手机 storages 独立命名空间），**不存在互相覆盖的代码路径**。

### 三个真实缺口（这才是要修的东西）

| # | 缺口 | 位置 |
| --- | --- | --- |
| 1 | 后端 `POST /admin/publish-tasks/dispatch-now`、`POST /claim-once` 早已就绪，但**前端没有任何按钮调用它们**——所以你在页面上怎么点都发不出 PUBLISH_VIDEO_TASK | `apps/api/src/routes/publish-tasks.ts:23,60`（孤儿接口） |
| 2 | 设备页"启动/暂停/关闭"按钮语义模糊：字面像"启动这台设备"，实际是"启动**采集**"，且不带 taskType 永远默认视频采集 | `apps/web/src/routes/DevicesPage.tsx:191-222,475` |
| 3 | 没有"手动测试发布"入口：想不依赖外部接口、直接发一条测试视频到手机，目前做不到 | 需新增一个小接口 + 弹窗 |

## A. 接口数据结构与抖音号字段（对接依据）

### A.1 外部接口（wecom-console 侧）八个业务字段

| 字段 | 类型 | 本项目落库字段 | 说明 |
| --- | --- | --- | --- |
| `taskId` | string | `publish_tasks.taskId` | 剪映草稿 ID；`platform + taskId` 共同唯一 |
| `platform` | string | `publish_tasks.platform` | `抖音`→DOUYIN / `视频号`→WECHAT_CHANNELS |
| `accountName` | string\|null | `publish_tasks.accountName` | **路由键**：发布账号（抖音号名称） |
| `title` | string | `publish_tasks.title` | 视频标题 |
| `description` | string | `publish_tasks.description` | 描述 + `#话题`（固定 5 个，校验缺失走 TOPIC_PENDING） |
| `coverUrl` | string\|null | `publish_tasks.coverUrl` | 封面图链接 |
| `videoUrl` | string | `publish_tasks.videoUrl` | 成片 mp4 链接 |
| `status` | string | 接口侧状态 | `未发布`→PENDING / `已发布`→PUBLISHED |

两个端点：
- 领取：`POST /api/v1/external/publish-tasks/claim`，body `{platform, accountName?}`；**accountName 可选，不传则领该平台下一条可执行任务**——这是 D 节"不绑定开关"的接口依据。
- 回填：`PATCH /api/v1/external/publish-tasks/{taskId}/status`，body `{platform, status, publishedUrl?, platformContentId?, error?}`。

### A.2 抖音号绑定字段（本项目侧）

绑定信息挂在 `collector_devices.accountProfile`（jsonb），字段已存在：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `douyinAccountId` | 抖音号（数字 ID） | 辅助校验、展示 |
| `douyinAccountName` | 抖音账号名称 | **匹配键**：与接口 `accountName` 精确比对（trim 后相等） |
| `wechatChannelsName` | 微信视频号名称 | 仅记录与回传展示，不参与匹配 |

**关键设计决定（与业务文档对齐）**：接口对抖音、视频号任务都**只给抖音号**（accountName）。视频号任务的路由同样用 accountName 匹配设备——因为业务约定"每个设备都有固定的抖音号和视频号"，命中抖音号即确定了设备，该设备的视频号随之确定。`wechatChannelsName` 只用于结果记录。

### A.3 上线注意（对方系统侧）

外部接口文档第 8 节：我们接管发布后，需提醒对方把 wecom-console 的 `DOUYIN_PUBLISH_ENABLED=false` 并重启其 worker，避免双边同时消费同一任务。

## B. 后台页面布局与控件职责边界

总原则：**一个按钮只做它字面上说的事；发布业务的所有动作只在"发布任务"和"远程脚本"两个页面发生；设备页不再藏业务动作。**

| 页面 | 职责（字面含义） | 打开后看到 | 允许的操作 | 明确禁止 |
| --- | --- | --- | --- | --- |
| 工作台 | 全局概览 | 在线设备数、今日发布成功/失败/未命中、今日采集量、异常告警 | 仅跳转链接，无业务按钮 | 不下发任何命令 |
| 任务调度 | **采集业务**的任务分配 | 设备 × 采集任务类型（视频/直播/搜直播评论/商品卡养号/目标直播评论）分配状态 | 分配/暂停/恢复/停止**采集**任务 | 不出现发布视频入口 |
| 配置 | **采集业务**的参数配置 | 关键词、采集参数等 | 采集配置的增删改 | 不管 publish_video |
| 设备 | 设备台账与连接状态 | 设备列表：在线状态、心跳、**账号绑定状态列**（已绑定抖音号 xxx / 未绑定） | ①账号绑定弹窗（见 D 节）②查看详情 ③~~启动/暂停/关闭~~ | 见下方改动 2 |
| 远程脚本 | 业务脚本配置与热更新 | publish_video 配置：闸口区间、发布时间段、接口地址、revision、绑定设备数 | 编辑配置、绑定设备、启停、**"立即下发"按钮（新增）**、发布热更新版本 | 不展示任务流水 |
| 发布任务 | **发布业务**的唯一任务入口 | 任务看板：待领取/已匹配/未命中/已下发/运行中/成功/失败/待补话题 + 统计汇总（已发 m / 未发 n + 原因） | **"领取一条"（claim-once）、"立即调度"（dispatch-now）、"手动测试发布"（新增）**、补全话题、查看单任务明细 | 不做设备管理 |
| 采集记录 | 采集业务的数据记录 | 采集结果列表 | 查询、导出 | — |
| 日志中心 | 全系统日志 | 命令日志、手机回报日志 | 查询、过滤 | — |

### 改动清单（具体到控件）

1. **发布任务页新增三个按钮**（调用已存在的后端接口，零后端改动）：
   - `领取一条` → `POST /admin/publish-tasks/claim-once`
   - `立即调度` → `POST /admin/publish-tasks/dispatch-now {configId}`（configId 从页面上的 publish_video 配置选择）
   - `手动测试发布` → 弹窗：选设备、选平台、填 videoUrl/coverUrl/title/description（含 5 个 #话题）→ 调新增接口 `POST /admin/publish-tasks/manual-test`（后端小改：复用 `publish-command.service.ts:50 createPublishVideoTaskCommand` 直接生成 PUBLISH_VIDEO_TASK，跳过外部 claim）。**这是联调期的救命入口**。
2. **设备页按钮改名+收窄**：`启动`→`启动采集`、`暂停`→`暂停采集`、`关闭`→`停止采集`。彻底消除"点了启动以为在跑发布"的误解。（可选加固：给 START 强制带上 `taskType:"video"`，手机端缺省值保留但打 warning 日志。）
3. **远程脚本页**：publish_video 配置行操作列加`立即下发`，调 dispatch-now。
4. **设备列表新增"绑定状态"列**：显示 `douyinAccountName` 或"未绑定"，一眼看出哪台设备能接发布任务。

## C. 新旧业务隔离方案（四层）

### C.1 命令层（已完成大半，补一处）

- 发布业务命令字：`PUBLISH_VIDEO_TASK` —— 手机端 `control-loop.js:623` 已优先判断、独立分支，**保持不动**。
- 采集业务命令字：START/PAUSE/STOP + `payload.taskType ∈ {video, live, live_comment, commerce_card_live_comment}`。
- **规则：两个命令字集合永不交叉**。前端 `api-client.ts:522` 的 commandType 类型联合里不混入 PUBLISH_VIDEO_TASK（发布只能由发布任务页/调度器产生）；采集按钮一律显式带 taskType。

### C.2 页面层（本方案 B 节的核心）

- 设备页、任务调度页 = 采集业务；发布任务页、远程脚本页 = 发布业务。工作台只读。

### C.3 配置层（已隔离，保持）

- 采集参数：手机本地 `config.js`（task.keywords 等），后台"配置"页管理。
- publish_video 参数：后台 `remote_script_configs` 表 → 手机 storages 命名空间 `AgriVideoCollectorRemoteScripts` 缓存；**闸口等执行参数以 PUBLISH_VIDEO_TASK 命令 payload 为准**（`publish-command.service.ts:25-39` 已下发），手机缓存只做兜底展示。
- 已确认无任何代码把 publish_video 配置写回 config.js，也无反向污染——**这一层不用改，写进文档防回归**。

### C.4 数据层（已隔离，保持）

- 发布任务流水：`publish_tasks` 表（状态机 CLAIMED→MATCHED/UNMATCHED→DISPATCHED→RUNNING→SUCCEEDED/FAILED→REPORTED，另有 TOPIC_PENDING）。
- 采集数据：原有采集表。命令统一走 `mobile_commands` 表但靠 `command_type` 区分。

## D. 新设备绑定流程（抖音号开关）

### D.1 流程

```
新设备首次注册/心跳
  → collector_devices 新增行，accountProfile 为空
  → 设备页"绑定状态"列显示【未绑定】角标
  → 管理员打开绑定弹窗（DeviceAccountBindingControl 改造）：

    ┌────────────────────────────────────────┐
    │ 绑定发布账号                    [开关] │
    │                                        │
    │ 开关 = 关（默认）：                    │
    │   该设备不绑定抖音号                   │
    │   → 只参与采集业务                     │
    │   → 可承接"接口未指定账号"的发布任务   │
    │                                        │
    │ 开关 = 开：                            │
    │   抖音账号名称*  [____________]        │
    │   抖音号(ID)     [____________]        │
    │   视频号名称     [____________]        │
    │   → 发布任务按接口 accountName 精确    │
    │     匹配到此设备                       │
    └────────────────────────────────────────┘
  → 保存 PATCH /admin/devices/:code（写 accountProfile）
```

### D.2 两种状态的运行语义

| | 开关=开（已绑定） | 开关=关（未绑定） |
| --- | --- | --- |
| 采集业务 | 正常参与 | 正常参与 |
| 发布任务-指定账号（accountName 非空） | **只接匹配自己抖音号名称的任务** | 不接 |
| 发布任务-未指定账号（accountName=null） | 不接 | 可接（多台未绑定设备按在线+空闲择一） |

### D.3 匹配与串行规则（对齐业务文档）

1. 调度器拿到任务后按 `accountName` trim 精确匹配 `accountProfile.douyinAccountName` 的在线设备：
   - 命中 → `MATCHED`，到发布时间段（publishTimeSlots）→ `DISPATCHED` 生成 PUBLISH_VIDEO_TASK；
   - 未命中 → `UNMATCHED`，`matchNote = "无绑定该抖音号的设备：{accountName}"`，跳过继续比对下一条（业务文档要求的串行语义，已实现的状态机直接承载）。
2. 同一设备同一时间段只执行一条发布任务（串行）；同一抖音号不同时间段的多个任务排队到各自时间段。
3. 汇总：发布任务页统计条 `已发布 m 个 / 未发 n 个 + 每条原因`（SUCCEEDED/FAILED.resultError/UNMATCHED.matchNote）。
4. 视频号任务：用同一个 accountName（抖音号名称）匹配同一台设备；手机上先跑抖音流程、再跑视频号流程（或按平台各自任务分别下发，取决于调度器现有实现，**真机联调时验证这一行为**）。
5. 视频号验证弹窗：只标记上报，不绕过（执行器已有 `视频号验证弹窗标记.js`）。
