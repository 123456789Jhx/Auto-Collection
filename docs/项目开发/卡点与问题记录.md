## 1.0.1 2026-07-07 商品卡直播评论真机回归卡点

现象：

- 产品新增商品卡路径：进入商城搜索“夏橙”，刷商品卡，命中 `秭归/夏橙` 和直播信号后进入直播间评论并观看。
- 该路径依赖抖音商城、商品卡、商品详情和直播入口控件形态，真机 UI 可能与搜索直播间链路不同。

当前实现：

- 新增 `commerce-card-live-runner.js`，作为 `live` 任务下的独立商品卡直播评论 runner。
- 商品卡配置收口到后台高级配置 `p3ExtensionsConfig.commerceCardLiveComment`，手机本地默认关闭；只有后台明确 `enabled=true` 时才会替代普通直播任务。
- 真实评论发送必须同时开启 `executeEnabled` 和 `manualExecutionApproved`，否则只记录 skipped 审计结果，不点击评论输入框。
- 新增商品卡配置：搜索词 `夏橙`，匹配词 `秭归/夏橙`，每轮扫描 15 分钟，命中直播观看 15 分钟，最多 3 轮。
- 新增抖音适配方法：进入商城、商城商品卡搜索、商品卡直播入口识别、进入直播间后二次关键词校验。
- 评论仅从审批后的 `commentPool` 中随机选择，不购买、不加购、不关注、不私信；发送、跳过和失败结果进入统一直播评论审计记录。

待验证：

1. 真机是否能稳定进入商城并搜索“夏橙”。
2. 商品卡列表或详情页是否能稳定识别 `秭归/夏橙` 和直播入口。
3. 进入直播间后二次关键词校验是否足够，是否会因直播间可见文本不足导致误判。
4. 后台未开启或未审批时是否不会触发商品卡任务、不会真实发送。
5. 随机评论是否能在商品直播间成功发送，且执行记录能看到 sent/skipped/failed。
6. 观看 15 分钟期间 STOP/PAUSE 是否能中断。
7. 任意一轮 15 分钟内没刷到匹配直播时，任务是否正常结束而不是无限滑动。
8. 同一任务内重复进入同一直播间时是否按直播间指纹跳过重复评论。

- 第一版商品卡 runner 曾由普通 `live` 任务配置触发，容易抢占普通直播采集并造成后台文案混淆。

- `live_comment` 继续表示搜索直播间评论，执行 `live-comment-runner.js`。
- `commerce_card_live_comment` 执行 `commerce-card-live-runner.js`，日志和 checkpoint 均按商品卡任务类型记录。
- 普通 `live` 只执行普通直播 phase，不再检查 `commerceCardLiveComment.enabled` 来切换 runner。

待验证：

1. 任务调度页两个按钮分别下发 `live_comment` 和 `commerce_card_live_comment`。
2. 下发 `live_comment` 时手机仍走搜索框搜索目标直播间并评论。

4. 下发普通 `live` 时，即使商品卡配置开启，也只执行普通直播采集。
5. 工作台和日志中心能把“搜索直播间评论”和“商品卡直播评论”分开显示。

## 1.0.4 2026-07-08 生产 Web 镜像构建卡点

现象：

- 用户打开生产后台仍看到老版本，当前提交没有在线上生效。
- 部署日志显示自托管 runner 已完成 SSH 连接、源码同步和 compose 构建启动，但 Web 镜像构建失败。
- 失败点为 `nginx:1.27-alpine` 基础镜像元数据请求，服务端 Docker 镜像源返回 `401 Unauthorized`。

根因：

- 生产 `Dockerfile.web` 最终阶段依赖 `nginx:1.27-alpine`。
- 服务端 Docker daemon 使用的镜像源对该 nginx 镜像请求未授权，导致 Web 镜像无法构建，后续 compose 启动和健康检查不会执行。
- API/Web 构建阶段使用的 `oven/bun:1.3.14` 在当前构建链路可用，可以用同一 runtime 承接静态服务和 API 代理，减少生产基础镜像依赖。

处理方案：

1. 新增 Bun Web server，保留原 Nginx 行为：静态资源、SPA 回退、`/downloads` no-store 下载、`/api`、`/health`、`/ready` 代理到 API 容器。
2. `Dockerfile.web` 最终阶段改为 `oven/bun:1.3.14`，不再拉取 nginx 镜像。
3. 生产 compose 下载目录挂载从 `/usr/share/nginx/html/downloads` 调整为 `/app/public/downloads`。
4. 增加专项测试覆盖代理、静态资源、下载目录、SPA 回退和路径穿越防护。

验证结果：

- 已先执行新增测试并确认失败：缺少 `deploy/web-server` 模块。
- 修复后已执行 `bun test deploy/web-server.test.ts`，通过。

剩余风险：

- 用户提供生产 SSH 登录方式后，已直连服务器 `/opt/auto-collection/account-data-platform` 部署当前提交。
- 远端已备份 `.env.production`，补齐强管理员密码和 `MOBILE_REQUEST_SIGNING_REQUIRED=true`，未记录密钥明文。
- 已检查 `http://106.54.41.106:18080/health` 返回 `ok`，`/ready` 返回 `ready`，前端页面静态资源更新为 `/assets/index-BPs2pwE9.js`。

## 1.0.5 2026-07-12 生产 Web 镜像 TypeScript 引用构建卡点

现象：

- 商品卡组合任务全量部署到 `/opt/auto-collection/account-data-platform` 时，远端 Web 镜像构建失败。
- 失败点为 `src/lib/api-client.ts` 和 `LiveTargetsPage.tsx` 引用 `@pkg/types` 时，TypeScript 报 `TS6305`，提示 `packages/types/dist/src/index.d.ts` 未从源文件构建。

根因：

- `apps/web/tsconfig.json` 使用 project references 引用 `packages/types`。
- `Dockerfile.web` 在干净容器里直接执行 `bun --filter @app/web build`，没有先构建 `packages/types` 的声明产物；本地工作区因为已有构建产物和 `tsc -b` 验证，不会暴露该问题。

处理方案：

- `Dockerfile.web` 在 Web build 前新增 `bunx tsc -b packages/types`，保证生产容器内先生成 project reference 需要的声明文件。

验证结果：

- 已重新执行远端 API/Web/db-push 构建、数据库同步和 API/Web 重启。
- 远端 `docker compose` 显示 postgres、redis healthy，API/Web started。
- 公网 `http://106.54.41.106:18080/health` 返回 200，`/ready` 返回 200，首页资产更新为 `/assets/index-BX1GbJtC.js`。

## 1.1 2026-07-01 直播评论执行层未彻底隔离

现象：

- 后台下发直播评论任务后，手机可能停留在上一轮搜索词页面。
- 直播评论任务可能复用普通直播流程，导致进入非目标直播间。
- 搜索阶段出现风控页时，日志可能继续记录为后续点击失败，而不是明确的 `risk_control`。

根因：

- `live_comment` 只有调度状态分离，执行流程仍可能复用普通 `live` runner。
- 搜索关键词设置后缺少二次校验，无法发现旧关键词残留。
- 风控检测没有覆盖搜索、点击、进房、评论前的全部阶段。

处理方案：

- 以 `docs/方案设计/功能方案/直播评论独立任务闭环修复方案.md` 为唯一修复口径。
- 先确认包含任务切换修复的代码基线。
- 新增或整理直播评论独立 runner。
- 禁止直播评论任务调用普通直播 runner。

## 1.2 2026-07-02 AutoJS6 OOM 与线程高频创建

现象：

- 手机出现 `AutoJS6 应用崩溃` 页面。
- 崩溃信息为 `java.lang.OutOfMemoryError: OutOfMemoryError thrown while trying to throw an exception; no stack trace available`。
- 部分手机 APP 页面显示主脚本运行但守护脚本未运行，后台仍可收到心跳。
- 崩溃后再次启动时，可能出现无障碍设置页跳转或无障碍状态误判。

证据：

- ADB 可见手机曾持续出现 `/data/user/0/com.agri.video.collector/files/project/main.js` 的 `ScriptThread ... notifyThreadExit`。
- 频率与主脚本待命循环 `sleep(Math.min(config.runtime.agentIdleLoopMs || 1000, 300))` 对应，接近每 300ms 一次。
- 后台心跳由 `main.js` 的常驻循环上报，不依赖 `watchdog.js`，因此守护脚本未运行时仍可能在线。

当前判断：

- `collector-app.js` 的待命循环高频调用 `controlLoop.pollControlCommandsAsync(false)`。
- `pollControlCommandsAsync(false)` 在创建线程后才进入 `pollControlCommands` 判断是否达到 `commandPollIntervalSeconds`。
- 当未到轮询间隔时，新线程很快退出，但线程已经创建，长期待机会导致 AutoJS6 线程/脚本资源累计，最终触发 OOM。

处理方案：

1. 将后台命令轮询的间隔判断提前到创建线程之前。
2. 保留 `force=true` 的即时轮询能力。
3. 限制后台异步线程启动频率，避免待命循环每 300ms 创建线程。
4. 补充日志或诊断字段，区分主脚本运行、守护脚本运行、无障碍检测来源和后台心跳来源。

解决结果：

- 已在 `mobile-agent/autojs/app/control-loop.js` 增加 `shouldPollControlCommands`，在 `pollControlCommandsAsync(false)` 创建线程前先判断命令轮询间隔，未到间隔直接返回。
- 设备未注册时也会更新 `commandControl.lastPollAt`，避免未注册状态下每 300ms 创建一次后台线程。
- 已新增 `mobile-agent/autojs/tests/control-loop.test.js`，覆盖“未到轮询间隔不创建线程”和“未注册轮询受节流”两个场景。
- 已在 `mobile-agent/autojs/core/permission.js` 增加无障碍检测诊断日志，记录 `enabled`、`source`、`packageName`、`enabledServices`；不改变原有自动跳无障碍设置页行为。
- `mobile-agent/autojs/project.json` 已提升到 `1.0.22/58`，用于区分本次 OOM 修复和无障碍诊断日志版本。
- 1.0.22 已被 1.0.23 打包产物取代；当前应安装 `dist/apk/燎原星火-1.0.23-inrt.apk` 后真机回归，确认 AutoJS6 OOM 不再出现。

验证口径：

### 2.3 2026-07-07 直播评论执行期间后台短暂离线

现象：直播评论执行一段时间后，后台设备先显示离线，过一段时间又恢复在线；手机侧守护脚本和采集脚本仍在运行。

排查证据：

1. 后台 `mapDeviceStatus()` 使用 `lastHeartbeatAt <= 3 分钟` 判在线；超过 3 分钟会强制显示 `offline`。
2. 最近 100 条心跳中，`device_b6f808fa52420e43` 在 `21:10:44 -> 21:18:14` 有约 `7.5` 分钟空窗，`device_9b185a40148fe414` 在 `21:10:47 -> 21:18:02` 有约 `7.24` 分钟空窗。
3. 空窗后的下一条心跳状态为 `idle` 或 `paused`，说明脚本没有退出，后台恢复在线是因为后续心跳重新到达。
4. 当前设备恢复在线后仍可能上报 `paused`，这是任务收尾状态语义问题，不是离线的主因。

根因：直播评论独立执行层拆分时，`live_comment` 从原来带 `writeHeartbeat()` 的 `phaseRunner.runPhase("live", ...)` 路径切到 `liveCommentRunner.runTargetLiveCommentTask()`。新 runner 搜索目标直播间、进房和持续采样时没有独立心跳；持续采样修复后任务链路变长，心跳空窗超过后台 3 分钟阈值。

处理结果：

1. 新增 `mobile-agent/autojs/app/agent-heartbeat-daemon.js`，Agent 启动后创建独立后台线程，按固定间隔上报心跳。
2. 独立心跳只读取 `floatyControl.state` 状态快照，不操作抖音 UI，不依赖视频、直播、直播评论任一业务 runner。
3. `main.module.js` 创建 `agentHeartbeatDaemon`，`collector-app.initializeAgent()` 在悬浮状态就绪后、权限检查前启动守护线程。
4. 新增 `createFinishedTaskStatePatch()`，任务完成或失败后写入 `running=false`、`paused=false`，让状态回到 `idle`，避免在线设备被误显示成暂停或不可用。

### 2.4 2026-07-08 直播评论搜索输入与无障碍误跳修复

现象：

1. 直播评论目标账号搜索阶段可能报 `search_keyword_set_failed`，手机停在搜索页、建议页或后续设置流程，未进入目标直播间。
2. 部分手机在无障碍已开启或刚启动状态不稳定时，会被本 APK 拉起 `android.settings.ACCESSIBILITY_SETTINGS`，阻断直播评论链路。

1. `mobile-agent/autojs/platforms/douyin.js` 增加 `getSearchInputText()`，关键词校验先读取输入框真实文本，再读取整屏可见文本。

3. `mobile-agent/autojs/core/accessibility.js` 区分 `context_unavailable` 和 `settings_unavailable`，不再把系统状态未知包装成普通未开启。
4. `mobile-agent/autojs/core/permission.js` 对未知状态只短暂等待并记录诊断，不自动打开无障碍设置页；确实检测到未开启的原启动授权路径仍保留。
5. `mobile-agent/autojs/project.json` 提升到 `1.0.31/67`，用于区分本次修复版本。
