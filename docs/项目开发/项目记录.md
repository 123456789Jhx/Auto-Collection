## 3. 文档维护规则

1. 根 README 只写项目介绍、当前能力、运行入口和边界，不放临时排查日志。
2. `docs/方案设计/` 只保留 `功能方案/` 和 `架构方案/` 两类。
3. 当前有效架构方案只维护 `系统架构方案.md`。

5. 废弃或明确不使用的方案直接删除，不保留为当前入口。
6. `docs/项目开发/部署说明.md` 单独维护，不和 README 或项目记录合并。
7. 卡点文档统一并入 `卡点与问题记录.md`。
8. `docs/项目开发/error` 是临时日志材料，不删除、不合并、不作为正式证据提交。
9. 所有有效改动必须维护到本文件或 `docs/项目开发/` 下对应专题记录；所有卡点、Bug 和阻断问题必须维护到 `卡点与问题记录.md`，修复后回填同一条目。

### 2026-07-03 直播评论进房后 0 采样与 STOP 优先级修复

- 触发场景：从后台直播评论页保存目标并触发 `REFRESH_CONFIG + reenterTargetRoom=true` 后，手机能进入目标直播间，但马上记录 `直播评论任务完成`、`农业视频手机采集脚本结束`、`任务结束后退出抖音`。
- 日志证据：2026-07-03 10:23-10:24，`勤能致富`、`大道至简2266` 的 `searchResult.source` 为 `target_user_live_entry`，`reason=room_verified`，但完成日志里 `sampleCount=0`、`sentActionCount=0`、`skippedActionCount=0`。

### 2026-07-10 APK 打包瘦身审计与裁剪规则

- 触发场景：用户反馈手机端 App 安装占用达到 270MB 级别，但项目只是 AutoX.js 小脚本，需要审查 APK 和安装占用来源，并尽量缩小正式打包体积。
- 审计结论：`mobile-agent/autojs` 源码约 1.38MB，APK 内 `assets/project` 约 856KB，体积主要来自 AutoJs6 runtime、Dex、native libraries、MLKit/OpenCV/OCR 数据和安装后的 native/oat 编译产物；手机数据目录仅约 2-3MB，不是日志或缓存堆积。
- 根因修复：`project.json` 里原有 `optimization.removeOpenCv=true`，但 `scripts/package-autojs-apk.ps1` 未读取优化配置，导致正式 `1.0.37` 仍注入 `libopencv_java4.so` 等大体积库；本轮打包脚本改为读取 `optimization`，在签名前按规则跳过 native 注入并删除不需要的 APK assets。
- 裁剪范围：默认移除 OpenCV、MediaInfo、条码扫描、pngquant、terminal native、OpenCC、Jieba/Pinyin 数据、Android devices DB 和 `tests` 目录；保留 MLKit OCR 主库、`libc++_shared.so`、`libpng.so` 等运行时依赖。R8/minify 新增配置开关，但默认保持关闭，避免 AutoJs6 宽反射/脚本运行链路被误裁剪。
- 热更新口径：`scripts/package-autojs.ps1` 同步读取 `optimization.excludeTests`，热更新 zip 默认不再包含 `tests` 目录，避免测试代码随线上脚本下发。
- 体积结果：旧 `dist/apk/燎原星火-1.0.37-inrt.apk` 为 63.99MiB；使用同版本和临时 dummy 注册密钥构建的瘦身审计包为 43.67MiB，减少约 20.32MiB。构建日志显示跳过 7 个 native library、约 32.21MiB raw native 输入，并删除 46 个 APK assets、约 7.90MiB compressed。
- 验证结果：已执行 PowerShell 解析检查、`node --check mobile-agent/autojs/main.js`、`project.json` JSON 解析、`scripts/package-autojs-apk.ps1 -SkipBuild` 和完整临时 APK 构建；临时包仅用于体积审计，因使用 dummy `MOBILE_REGISTRATION_SECRET`，不能安装或发布。
- 剩余风险：移除 OpenCV、条码扫描和 MediaInfo 后，必须用真实注册密钥重新打正式包，并至少在一台手机验证启动、悬浮窗、无障碍、截图授权、OCR fallback、商品卡搜索和直播进房评论链路；如 AutoJs6 某些 `images.*` API 运行时强依赖 OpenCV，需要按真机日志恢复对应裁剪项。
