## 3. 文档维护规则

1. 根 README 只写项目介绍、当前能力、运行入口和边界，不放临时排查日志。
2. `docs/方案设计/` 只保留 `功能方案/` 和 `架构方案/` 两类。

5. 废弃或明确不使用的方案直接删除，不保留为当前入口。
6. `docs/项目开发/部署说明.md` 单独维护，不和 README 或项目记录合并。
7. 卡点文档统一并入 `卡点与问题记录.md`。
8. `docs/项目开发/error` 是临时日志材料，不删除、不合并、不作为正式证据提交。
9. 所有有效改动必须维护到本文件或 `docs/项目开发/` 下对应专题记录；所有卡点、Bug 和阻断问题必须维护到 `卡点与问题记录.md`，修复后回填同一条目。

### 2026-07-03 直播评论进房后 0 采样与 STOP 优先级修复

- 触发场景：从后台直播评论页保存目标并触发 `REFRESH_CONFIG + reenterTargetRoom=true` 后，手机能进入目标直播间，但马上记录 `直播评论任务完成`、`农业视频手机采集脚本结束`、`任务结束后退出抖音`。
- 日志证据：2026-07-03 10:23-10:24，`勤能致富`、`大道至简2266` 的 `searchResult.source` 为 `target_user_live_entry`，`reason=room_verified`，但完成日志里 `sampleCount=0`、`sentActionCount=0`、`skippedActionCount=0`。
