# 05-话题校验与断点补全

## 目标

确保话题不足时所有平台都等待补全，并且补全后从原任务继续，不重新 claim 外部任务，不重走已完成的手机端流程。

确认后的业务规则：

- 如果接口任务话题不足，补全前不允许先发布某个平台。
- 两个平台都等补全。
- 后台 claim 后先做话题主校验，不合格不匹配、不下发。
- 手机端收到命令后做防御校验，不合格不下载、不开 app。
- 手机端流程中发现话题未选中时，就地等待后台补全，拿到补全文案后在当前页面继续。

## 当前问题

前序只读核对发现：

- 后端话题校验、`TOPIC_PENDING`、补全后重下发已经有骨架。
- 手机端 `topic-resume.js` 已实现每 20 秒轮询补全文案。
- 但加入 `PUBLISH_BUSY` 后，话题补全重下发容易被当前任务自己的旧命令误判为设备忙。
- 前端话题补全弹窗目前只校验非空，没有复用 5 个话题校验。
- 后端没有发现单独 worker 自动处理 `topicResolveTimeoutMinutes` 超时；目前主要依赖手机端等待超时后上报失败。

## 不要改什么

- 不要补全话题时重新 claim 外部任务。
- 不要把 `TOPIC_PENDING` 直接回写外部最终失败。
- 不要让一个平台先发布，另一个平台等补全。
- 不要在手机端话题待补时清理并重走全流程，除非超时失败。
- 不要让 busy 检查阻断当前任务自己的断点续发。

## 实施步骤

1. 后端 claim 前置校验保持主闸门。
   - 外部任务保存后、设备匹配前，调用 `validatePublishTopics()`。
   - 话题不足：
     - 任务状态 `TOPIC_PENDING`。
     - 不匹配设备。
     - 不创建命令。
     - 不回写外部最终失败。

2. 补全接口保持原任务继续。
   - `completePublishTaskTopics()` 只更新原任务 description。
   - 如果原任务未匹配，补全后重新匹配同一任务。
   - 如果原任务已匹配，补全后复用原设备。
   - 调用 `redispatchPublishVideoTaskCommand()` 复用同一任务幂等键。

3. 与 busy 检查兼容。
   - 补全重下发传入 `excludeTaskId = 当前任务 id`。
   - busy helper 查询 active command/task 时排除当前任务。
   - 不能因为当前任务已有旧命令或 `TOPIC_PENDING` 状态而阻止补全后的重下发。

4. 手机端防御保持。
   - `publish-video-entry.js` 收到命令后先校验 `#` 数量。
   - 不合格：上报 `TOPIC_PENDING`，不下载、不开 app。
   - 流程中 UI 话题未选中：
     - 先上报 `TOPIC_PENDING`。
     - `topic-resume.js` 按 `topicResolveTimeoutMinutes` 等待。
     - 拿到补全文案后覆写 `payload.description`，继续当前流程。

5. 前端补全弹窗复用话题校验。
   - 抽出或复用 `quick-paste-publish.ts` 中的话题校验逻辑。
   - `PublishTopicsModal` 提交前校验：
     - 恰好 5 个 `#话题`，或按任务的 `expectedTopicCount`。
     - 每个 `#` 后必须有文字。
   - 显示当前话题数量。

6. 可选：后端超时兜底。
   - 如果产品要求即使手机端不在线也能超时失败，可新增 worker：
     - 扫描 `TOPIC_PENDING` 且超过 `topicResolveTimeoutMinutes` 的任务。
     - 回写外部未发布，原因 `TOPIC_RESOLVE_TIMEOUT`。
   - 如果暂不做，必须在文档和验收中说明超时主要由手机端执行中等待处理。

## 验收口径

- 话题不足时两个平台都不会发布。
- 话题补全前不会下发手机命令，或执行中会停在当前页面等待。
- 补全后复用原任务，不重新 claim 外部。
- 补全后不会被自身 busy 状态拦截。
- 前端补全弹窗能提前阻断明显不合格文案。

## 风险提醒

- `expectedTopicCount` 默认 5，但任务 payload 中可能带不同值；前端补全弹窗最好使用任务实际值。
- 手机端执行中等待补全会保持亮屏和发布锁，占用设备；这与“不排队”一致，但后端 busy 需识别这种占用。
- 如果后端超时 worker 和手机端超时同时存在，要避免重复回写外部。
