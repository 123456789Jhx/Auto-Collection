# 03-双平台发布顺序编排

## 目标

确保平台处理顺序稳定、可预测、可测试。

确认后的业务规则：

- 外部接口返回的任务会明确告诉要发布的平台。
- 系统不应把无平台字段任务默认为双平台任务。
- 如果同一时间段同时处理抖音和视频号，平台顺序固定为：**抖音 → 视频号**。
- 如果两个平台任务命中同一设备，抖音先创建命令；视频号因设备忙进入后端 `PUBLISH_BUSY` 延迟重试，而不是立刻下发第二条手机命令。

## 当前问题

前序只读核对发现：

- `publish-config.ts` 默认 `platforms = ["抖音", "视频号"]`。
- `dispatchPublishConfigNow()` 当前按配置数组顺序循环。
- 如果配置顺序被改为 `["视频号", "抖音"]`，当前就会先处理视频号。
- 旧测试只覆盖默认顺序，不强制配置反序时仍抖音优先。

## 不要改什么

- 不要在手机端实现“一条命令内部先发抖音再发视频号”。
- 不要把外部平台字段缺失的任务扩展成双平台。
- 不要让前端配置数组顺序决定业务执行顺序。
- 不要取消平台启用配置；配置仍表示启用哪些平台，只是不表示顺序。

## 涉及文件

- `account-data-platform/apps/api/src/services/publish-config.ts`
- `account-data-platform/apps/api/src/services/publish-scheduler.service.ts`
- `account-data-platform/apps/api/src/services/publish-scheduler.service.test.ts`

- `account-data-platform/apps/web/src/routes/RemoteScriptConfigModal.tsx`

## 实施步骤

1. 定义固定平台顺序常量。
   - 建议在 `publish-scheduler.service.ts` 或共享 domain 中定义：
     - `const PUBLISH_PLATFORM_ORDER = ["DOUYIN", "WECHAT_CHANNELS"]`
   - 如果代码使用中文平台值，则统一转换后排序。

2. 调整调度循环。
   - 不要直接 `for (const platform of publishConfig.platforms)`。
   - 改为：
     - 先把配置中的平台标准化为集合。
     - 再按固定顺序过滤启用平台。
   - 伪代码：
     - `orderedPlatforms = PUBLISH_PLATFORM_ORDER.filter(platform => enabledSet.has(platform))`

3. 保留接口明确平台。
   - claim 外部接口时，传入当前平台。
   - 外部返回任务后，保存平台字段。
   - 不要因为配置启用了两个平台，就把一个外部任务复制成两个平台任务，除非外部接口本身返回两条明确平台任务。

4. 与 busy retry 串联。
   - 同 slot 中，抖音先尝试下发。
   - 视频号后尝试。
   - 如果视频号命中同设备且抖音命令仍活跃，视频号应进入 `PUBLISH_BUSY` retry。
   - 后续 retry 时仍只处理该视频号任务，不重新 claim。

5. 更新前端文案。
   - 接口定时配置里的 `platforms` 文案应表达“启用平台”，不要表达“执行顺序”。
   - 如展示平台顺序，应展示固定顺序“抖音 → 视频号”。

## 测试要求

在 `publish-scheduler.service.test.ts` 至少覆盖：

1. 默认配置 `["抖音", "视频号"]` 时，claim 顺序为抖音后视频号。
2. 配置反序 `["视频号", "抖音"]` 时，claim 顺序仍为抖音后视频号。
3. 只启用抖音时，只 claim 抖音。
4. 只启用视频号时，只 claim 视频号。
5. 外部任务平台字段明确为抖音时，只创建抖音命令。
6. 外部任务平台字段明确为视频号时，只创建视频号命令。
7. 同 slot 双平台同设备时，视频号不立即下发，进入 busy retry。

前端测试可覆盖：

- 接口定时页展示“启用平台”而不是“执行顺序”。
- 反序配置保存后，后端仍按固定顺序执行；前端不需要依赖数组顺序表达业务顺序。

## 验收口径

- 平台处理顺序由后端固定常量控制。
- 配置数组顺序变化不影响实际执行顺序。
- 外部任务平台字段是任务真实平台来源。
- 手机端仍只接收单平台单任务命令。
- 双平台同设备时不会形成手机端队列。

## 风险提醒

- 如果直接对中文平台字符串排序，容易受别名影响；建议先标准化平台枚举。
- 如果把配置 `platforms` 理解成“任务平台列表”，可能误把一条外部任务复制成双平台任务，违背“接口明确平台”。
- 如果不与 busy 节点联动，固定顺序只会保证“先创建抖音命令、再创建视频号命令”，仍会形成排队。
