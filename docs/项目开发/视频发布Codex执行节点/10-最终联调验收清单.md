## Mock 全链路验收

建议使用隔离 mock 外部接口、隔离 API 端口、隔离 Web 端口完成。

### 场景 A：抖音正常发布

1. 外部接口返回平台抖音、素材完整、话题完整、抖音账号存在。
2. 后端 claim 后匹配绑定该抖音账号的在线设备。
3. 创建 1 条 `PUBLISH_VIDEO_TASK`。
4. 模拟移动端拉取命令并上报 `SUCCEEDED`。
5. outbox 回写外部 `已发布`。
6. 看板统计成功 +1。

### 场景 B：视频号正常发布

1. 外部接口返回平台视频号、素材完整、话题完整、抖音账号存在。
2. 后端按抖音账号命中同设备。
3. 设备有 `wechatChannelsName`。
4. 创建 1 条视频号 `PUBLISH_VIDEO_TASK`。
5. 模拟移动端上报 `SUCCEEDED`。
6. 外部回写 `已发布`。

### 场景 C：双平台同 slot 同设备

1. 同 slot 外部接口先后返回抖音和视频号任务。
2. 后端固定先处理抖音。
3. 抖音创建命令。
4. 视频号命中同设备后进入 `PUBLISH_BUSY` retry，不立即创建第二条命令。
5. 模拟抖音完成。
6. 到达 retry 时间后，视频号成功创建命令。
7. 看板能看到过程中 busy/retry 状态变化。

### 场景 D：设备忙重试耗尽

1. 设备已有活跃发布命令。
2. 新任务连续 3 次 retry 都发现 busy。
3. 第 3 次后任务最终未发布。
4. 外部回写错误 `PUBLISH_BUSY`。
5. 看板 busy / 未发统计符合口径。

### 场景 E：话题不足

1. 外部接口返回话题不足任务。
2. 后端保存为 `TOPIC_PENDING`。
3. 不匹配设备、不创建命令、不回写最终失败。
4. 前端看板显示补全按钮。
5. 补全后校验通过，复用原任务继续匹配和下发。

### 场景 F：素材无效

1. 外部接口返回缺视频、缺封面或非法 URL。
2. 后端不匹配、不下发。
3. 本地记录素材失败码。
4. 外部回写未发布。
5. 看板显示素材异常。

### 场景 G：视频号验证弹窗

1. 视频号任务已下发。
2. 模拟手机端执行中检测到安全验证/验证码/滑块。
3. 手机上报 `CHANNELS_VERIFY_PENDING` 和 `popupFeature`。
4. 后端保存待人工处理，不回写成普通失败。
5. 看板显示视频号验证待处理。

## 真机验收清单

真机验收需要用户明确授权后执行。

1. 抖音：
   - 素材下载到日期目录。
   - 相册前两项素材选择正确。
   - 封面编辑流程可用。
   - 话题选择成功。
   - 发布成功判定准确。
   - 发布后目录清理。

2. 视频号：
   - 微信启动校正准确。
   - 发现/视频号/我的/发表视频路径正确。
   - 相册素材选择正确。
   - 标题和描述输入正确。
   - 导出等待准确。
   - 发布成功判定准确。
   - 验证弹窗出现时不继续点击。

3. 断点补全：
   - 故意制造话题未选中。
   - 手机端停在当前流程等待。
   - 后台补全文案。
   - 手机端继续当前流程发布。

4. 忙碌：
   - 同设备已有任务执行时，后端不再下发第二条命令。
   - 手机端不会收到队列中的第二条发布任务。

## 风险提醒

- mock 全链路通过不代表真机 UI 发布判定一定准确，抖音/视频号成功特征仍需真机校准。
- busy retry 涉及时间，需要测试中注入 fake clock，避免真实等待 5 分钟。
- 外部接口如果不支持结构化错误码，只能在 `error` 文本中稳定写入失败码；需要和外部系统确认展示方式。
- 如果同一任务既 topic pending 又 busy，状态优先级需要清楚：话题不足优先，不应占用设备；执行中话题待补才占用设备。
