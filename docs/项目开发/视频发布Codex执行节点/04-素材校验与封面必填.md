# 04-素材校验与封面必填

## 目标

把素材有效性前置到后端，明确缺视频、缺封面、URL 无效时的统一处理规则。

确认后的业务规则：

- 同一素材如果缺视频、缺封面或 URL 无效，该素材关联的双平台任务都失败。
- 不允许缺封面时某个平台先发。
- 不允许把素材缺失留到手机端下载阶段才发现。
- 外部接口任务和手动/粘贴发布任务都应在下发前校验必要素材。

## 当前问题

前序只读核对发现：

- 后端类型允许 `coverUrl: null`。
- DB 字段 `cover_url` 可为空。
- `publish-config.ts` 中 `requireCover` 默认 `false`，且没有被外部接口调度严格使用。
- 手动测试发布和粘贴发布中存在允许空封面的旧路径。
- AutoJS 默认下载器中 `material-dir-manager.js` 要求 `coverUrl` 必填；缺封面会在手机下载时报 `MATERIAL_INVALID`。
- 这导致后端语义和手机端语义不一致：后端允许下发，手机端才失败。

## 不要改什么

- 不要只在手机端修；素材校验必须在后端下发前完成。
- 不要让外部接口任务缺封面后仍创建 `PUBLISH_VIDEO_TASK`。
- 不要把 `requireCover: false` 继续作为发布视频业务默认口径。
- 不要在没有确认的情况下直接把历史 DB 字段改成 not null 导致迁移失败；可以先服务层强制，再评估 DB 约束。
- 不要把 URL 可访问性校验做成无限等待或阻塞整轮调度很久。

## 实施步骤

1. 定义素材失败码。
   - 推荐结构化失败码：
     - `MATERIAL_INVALID`
     - `VIDEO_REQUIRED`
     - `COVER_REQUIRED`
     - `VIDEO_URL_INVALID`
     - `COVER_URL_INVALID`
   - 如果当前只支持 `resultError` 字符串，至少保证错误文本稳定、可测试。

2. 外部 claim 后立即校验素材。
   - 在 `publish-match.service.ts` 中，保存/匹配前检查：
     - `videoUrl` 必须存在且是 http/https URL。
     - `coverUrl` 必须存在且是 http/https URL。
   - 缺失或非法时：
     - 本地保存任务。
     - 不匹配设备。
     - 不创建命令。
     - 外部回写“未发布”。
     - 错误原因使用稳定失败码或稳定文案。

3. 手动测试发布强制封面。
   - 修改 `manualPublishTestPayloadSchema`。
   - `coverUrl` 改为必填 URL。
   - `ManualPublishTestModal` 表单必填封面 URL。
   - 缺封面时前端阻断，不发 API。

4. 粘贴发布强制封面。
   - `parseQuickPasteText` 解析结果必须包含视频 URL 和封面 URL。
   - 如果没有显式封面，但可以从 `.mp4` 派生 `.jpg`，需要确认派生封面是否算有效封面。
   - 若业务要求显式封面，则禁用派生；若接受派生，则提交前仍要校验派生 URL。
   - 封面 HEAD 校验 404/410 必须阻断。

5. 配置层收敛。
   - `publish-config.ts` 中 `requireCover` 改为默认 `true`，或移除该开关。
   - `RemoteScriptConfigModal` 中直接素材和接口定时默认值都应体现封面必填。
   - 如果保留 `requireCover` 只作为兼容字段，不允许它关闭发布视频封面必填规则。

6. 命令 payload 收敛。
   - `createPublishVideoTaskCommand()` 生成 payload 前假设 `coverUrl` 一定存在。
   - 类型中 `coverUrl` 尽量从 nullable 改成 string。
   - 对历史任务或旧调用做防御性错误，不要静默下发空封面。

7. DB 约束分阶段处理。
   - 第一阶段：服务层强制，DB 仍允许历史 null。
   - 第二阶段：清理历史数据或确认无需保留后，再加 not null migration。
   - 不要在同一节点里强行改 DB not null 导致测试和本地数据失败。

## 验收口径

- 新任务下发前一定有合法视频 URL 和封面 URL。
- 外部接口缺素材时不会匹配设备，不会创建手机命令。
- 手动测试和粘贴发布缺封面时前端和后端都阻断。
- 手机端仍保留下载阶段防御，异常会回传 `MATERIAL_INVALID`。
- 双平台任务素材无效时，两个平台都不会发布。

## 风险提醒

- 直接把 Zod schema 改成严格必填可能导致外部 claim parse 失败后无法回写外部任务；推荐先能解析，再服务层判定并回写。
- 如果继续允许从 `.mp4` 派生 `.jpg`，要确认派生 URL 一定符合真实素材服务规则。
- 如果前端只做 HEAD 校验，CORS 失败不一定代表 URL 不可用；阻断策略要和现有降级规则保持一致。
