# 08-前端粘贴发布与高级调试修复

## 目标

修复视频发布模块前端中已经核对出的几个明确问题，并让前端与后端新业务规则保持一致。

本节点重点：

1. 修复“高级调试 / 手动测试发布”配置来源被过滤空的问题。
2. 粘贴发布强制素材和话题校验，与后端一致。
3. 接口定时配置的时间窗输入增强。
4. 默认执行配置唯一性或 fallback 策略明确。
5. 设备账号绑定展示与当前“按抖音号路由，视频号字段只做能力检查”的规则一致。

## 当前问题

前序只读核对发现：

- `PublishTaskOperations.tsx` 中 `configsQuery` 请求了 `sourceMode: "external_pull"`，但同组件又从这个结果中过滤 `direct_material` 给手动测试弹窗，导致 `directConfigs` 实际为空。
- 粘贴发布已能解析 mp4/jpg，但封面 URL 校验和“封面必填”要与 04 节点统一。
- 接口定时的 `publishTimeSlots` 前端使用 tags 输入，前端不校验 `HH:mm`，错误延后到后端。
- 多个 `isDefault === true` 的 direct material 配置只 warning，不阻止；粘贴发布直接取第一个默认配置。
- 设备绑定 UI 已有抖音账号和视频号名称，但绑定状态展示仍偏抖音主字段；这与“按抖音号路由、视频号字段只做能力检查”基本一致，但文案需要明确。

## 不要改什么

- 不要把高级调试的接口定时配置和直接素材配置混用。
- 不要在前端绕过后端校验；前端校验只是提前提示。
- 不要让粘贴发布在缺封面、话题不足时继续提交。
- 不要让用户通过拖动平台顺序影响实际后端平台顺序。
- 不要改旧 `/publish-tasks`、`/remote-scripts` 兼容路由的基础可用性。

## 实施步骤

1. 拆分高级调试配置查询。
   - `PublishTaskOperations.tsx` 保留一个 query 取：
     - `scriptKey = publish_video`
     - `sourceMode = external_pull`
     - 用于“拉取一条接口任务”和“立即拉取并下发”。
   - 新增一个 query 取：
     - `scriptKey = publish_video`
     - `sourceMode = direct_material`
     - `status = ENABLED`
     - 用于 `ManualPublishTestModal`。
   - 手动测试按钮在 direct 配置加载中时显示 loading 或禁用。
   - 没有 direct 配置时提示：`请先到发布设置创建直接素材发布配置`。

2. 手动测试弹窗强制素材必填。
   - `ManualPublishTestModal` 中视频 URL、封面 URL 必填。
   - 封面 URL 为空时前端阻断。
   - 描述话题数量不足时前端阻断。
   - 平台字段仍由用户明确选择，不默认双发。

3. 粘贴发布与 04/05 节点对齐。
   - `quick-paste-publish.ts` 抽出可复用的 `validatePublishDescriptionTopics`。
   - 粘贴内容必须包含视频 URL 和封面 URL。
   - 如果保留“从 mp4 派生 jpg”，要明确该派生结果也要经过封面可用性校验。
   - 缺视频、缺封面、多个视频、多个封面、非 http/https 都阻断。
   - 话题必须恰好满足 `expectedTopicCount`，默认 5。

4. 接口定时时间窗输入增强。
   - 对 `publishTimeSlots` 做前端校验：每项必须符合 `HH:mm`。
   - 可在 `StringArrayField` 或 `field-rules.ts` 中识别字段名并加规则。
   - 推荐保存前去重、排序，避免 `11:00` 重复。
   - 错误提示示例：`发布时间窗必须为 HH:mm，例如 11:00`。

5. 默认 direct material 配置策略。
   - 推荐强约束：同一租户、同一脚本、同一 `sourceMode = direct_material` 只能有一个 `isDefault = true`。
   - 前端保存某配置为默认时：
     - 要么提示会替换其他默认，并由后端处理唯一性；
     - 要么保存前阻断多个默认。
   - 如果后端暂不支持唯一默认，前端至少避免静默取第一个，必须提示用户处理。

6. 设备绑定文案对齐。
   - 绑定主字段仍是抖音账号名称/抖音号 ID。
   - 视频号名称文案改成能力字段，例如：`微信视频号名称（用于确认该设备可发视频号）`。
   - 设备列表绑定状态建议同时显示：
     - 抖音账号
     - 视频号能力：已绑定 / 未绑定
   - 不要把视频号名称作为主匹配键传达给用户。

7. 保存慢优化保持。
   - 保持 `RemoteScriptsPage.tsx` 的精确 query invalidation。
   - 不要恢复宽泛 `remoteScriptConfigs` 全量等待。
   - 保存成功后弹窗关闭不应等待所有列表刷新。

## 验收口径

- 高级调试手动测试发布配置下拉不再为空。
- 粘贴发布不会提交缺封面/缺话题/非法 URL 的任务。
- 接口定时时间窗非法值在前端即提示。
- 用户能明确知道视频号名称是设备能力检查字段，不是主路由字段。
- 保存配置体验不退化，不恢复保存慢问题。

## 风险提醒

- 如果前端强制封面，但后端仍允许空封面，会出现口径不一致；本节点应在 04 后执行。
- 如果默认配置唯一性只在前端做，API 直接调用仍可能制造多个默认；最终应由后端兜底。
- 如果 URL HEAD 因 CORS 失败就完全阻断，可能误杀可用素材链接；继续沿用当前 404/410 阻断、CORS warning 的策略更稳。
