# 07-任务看板状态与统计汇总

## 目标

让任务看板完整展示发布任务的新状态和失败分类，尤其是：

- `PUBLISH_BUSY`
- `MATERIAL_INVALID`
- `TOPIC_PENDING`
- `CHANNELS_VERIFY_PENDING`
- 缺封面 / 缺视频 / URL 无效
- 外部回写状态
- 后端 busy retry 的下次重试时间和重试次数

## 当前问题

前序只读核对发现：

- 前端 `PublishTasksPage.tsx` 没有 `PUBLISH_BUSY` label 和颜色。
- 后端 `getPublishTaskDashboard()` 只有基础统计：今日成功、今日未发、今日未命中。
- 没有 busy 专项统计。
- 没有素材无效、话题待补、视频号验证待处理等细分统计。
- 如果后端新增 busy retry 字段，前端目前没有展示入口。

## 不要改什么

- 不要把任务看板改成复杂运维系统；本节点只补发布业务关键状态。
- 不要删除旧状态 label。
- 不要把外部回写失败和发布失败混为一类。
- 不要只在前端写死统计；统计应以后端 dashboard 返回为准。

## 实施步骤

1. 后端 dashboard 增加统计字段。
   - 建议在 `getPublishTaskDashboard()` 返回：
     - `success`
     - `unpublished`
     - `unmatched`
     - `busy`
     - `topicPending`
     - `materialInvalid`
     - `channelsVerifyPending`
     - 可选：`reportFailed`
   - 如果已经有 `summary` 对象，扩展该对象即可。

2. 后端列表返回重试信息。
   - 如果 02 节点新增字段，则列表记录应带：
     - `failureCode`
     - `dispatchRetryCount`
     - `nextDispatchAt`
     - `lastDispatchAttemptAt`
   - 前端可展示“第 n/3 次重试，预计 HH:mm 再试”。

3. 前端状态 label 补齐。
   - 在 `PublishTasksPage.tsx` 的 `statusLabels` 增加：
     - `PUBLISH_BUSY`: `设备忙，等待重试`
   - 如果结构化失败码存在，失败码 label 也要补：
     - `COVER_REQUIRED`: `缺少封面`
     - `VIDEO_REQUIRED`: `缺少视频`
     - `VIDEO_URL_INVALID`: `视频链接无效`
     - `COVER_URL_INVALID`: `封面链接无效`

4. 前端颜色策略。
   - `PUBLISH_BUSY` 建议使用 orange/warning。
   - `TOPIC_PENDING` 使用 warning。
   - `CHANNELS_VERIFY_PENDING` 使用 purple 或 warning。
   - `MATERIAL_INVALID` 使用 red/error。
   - `REPORTED` 成功和失败要根据 `resultError` 或失败码区分展示。

5. 统计卡更新。
   - 当前只有三张统计卡时，可扩展为：
     - 今日成功
     - 今日未发
     - 今日未命中
     - 设备忙
     - 话题待补
     - 素材异常
   - 如果页面空间有限，至少要在“今日未发”下方显示分项说明。

6. 操作入口。
   - `TOPIC_PENDING` 保持“补全话题”按钮。
   - `PUBLISH_BUSY` 不需要人工操作，展示下次重试时间。
   - `CHANNELS_VERIFY_PENDING` 可显示“需人工处理视频号验证”，本节点不一定实现人工恢复动作。

## 测试要求

后端测试：

- `getPublishTaskDashboard()` 统计：
  - busy 任务计入 `busy`。
  - topic pending 任务计入 `topicPending`。
  - material invalid 任务计入 `materialInvalid`。
  - channels verify pending 任务计入 `channelsVerifyPending`。
  - report failed 单独可见。

前端测试：

- `publish-tasks-page.test.js`
  - `PUBLISH_BUSY` 显示中文状态。
  - busy 行显示重试次数和下次重试时间。
  - `TOPIC_PENDING` 仍显示补全按钮。
  - `CHANNELS_VERIFY_PENDING` 显示待人工验证文案。
  - 素材异常显示红色或错误状态文案。
  - 统计卡显示 busy / topic / material 分项。

## 验收口径

- 看板不会再裸显示 `PUBLISH_BUSY`。
- 用户能区分“设备忙等待重试”和“最终未发布”。
- 用户能看到话题待补和视频号验证待处理。
- 后端统计与前端展示字段一致。
- 外部回写失败不会被误判为发布失败。

## 风险提醒

- 如果 `PUBLISH_BUSY` 处于等待重试中，不应计入最终未发，除非产品明确要计入。
- 如果 busy 重试耗尽并最终回写未发布，可以同时计入 busy 和 unpublished，需统计口径明确。
- 旧任务可能没有 `failureCode` 字段，前端要兼容空值。
