# 小米14 换机适配方案（Android 16 存储兼容）

本文件为 2026-09-11 小米14 换机诊断产出的**可执行修复方案**，供联合打包流程直接使用。问题背景与证据链见 `卡点与问题记录.md` 同日条目。

## 1. 背景

原测试机 MI8（Android 10，1080×2248）替换为小米14：

| 项 | 值 |
|---|---|
| 型号 / 代号 | `23127PN0CC` / `houji` |
| 系统 | Android 16（API 36）/ HyperOS OS3.0（V816） |
| 分辨率 / 密度 | 1200×2670 / 480dpi |
| Root | 未 root |
| 序列号 | `d950a769`（连接在 5037 服务，5038 未监听） |

当前阻塞：点击「一键启动」报 `FileNotFoundException ... /storage/emulated/0/燎原星火/datasource/运行日志/2026-09-11.log: open failed: EPERM`，Agent 无法启动。

**已确认与网络无关**：APK 内置生产 API 为公网域名 `https://qk-api.dafengchan.top/api/v1`，基座上报 HTTP 200 正常，更换网络环境不需要重新打包。

## 2. 缺陷说明

### 2.1 环境侧（无需改代码，但决定回退目标）

- APK 为 `versionName=1.0.95`、`versionCode=131`、`minSdk=24`、`targetSdk=29`
- 仅声明旧版 `READ/WRITE_EXTERNAL_STORAGE`，`appops` 显示 `ignore`
- **未声明** `MANAGE_EXTERNAL_STORAGE`
- Android 11+ 分区存储下无法写公共目录；Android 16 已废弃 legacy 存储
- 目标目录 owner 为 `u0_a237`，当前应用 UID 为 `u0_a465`，权限 `drwxrws---`，跨 UID 不可访问

### 2.2 代码侧（本次修复对象）

`files.createWithDirs()` 在失败时**返回 `false` 而不抛异常**，现有实现只捕获异常、不检查返回值，导致可写性判定恒为 `true`，回退分支永不执行。

**同一缺陷存在两份重复实现，必须同时修复：**

| 文件 | 位置 | 函数 |
|---|---|---|
| `mobile-agent/autojs/main.module.js` | 第 100-108 行 | `ensureWritableDir()` |
| `mobile-agent/autojs/main.module.js` | 第 110-130 行 | `resolveOutputBaseDir()` |
| `mobile-agent/autojs/watchdog.js` | 第 102-110 行 | `ensureWritableDir()` |
| `mobile-agent/autojs/watchdog.js` | 第 111-131 行 | `resolveOutputBaseDir()` |

`watchdog.js` 的这两份函数位于 `loadConfig()` 内，每次 `maybeUpdate()` 都会执行，因此同样会踩到该缺陷。

### 2.3 判定证据

将 `datasource` 目录改名后重试，报错由 `EPERM` 变为 `ENOENT`——目录创建实际失败，代码仍判定为可写。实验后目录名已还原。

### 2.4 已排除的绕过路径（不需要再尝试）

| 方案 | 结论 |
|---|---|
| `appops set LEGACY_STORAGE allow` | 无效，Android 16 已废弃 legacy 存储 |
| `appops set MANAGE_EXTERNAL_STORAGE allow` | 无效，APK 未声明该权限 |
| `chmod -R 777` 目录 | 无效，FUSE 权限由 MediaProvider 策略控制，权限位无变化 |
| ADB 代建目录 | 无效，owner 为 shell，FUSE 按 UID 判定 |
| 改 `config.js` 的 `fixedBaseDir` | 不可行，文件在 APK 内，热更新包永不包含 `config.js` |
| 劫持 `SCRIPT_DIR` | 不可行，`getScriptDir()` 优先取 `files.cwd()` 与 `engine.getSource()`，均指向 APK 私有目录 |

## 3. 改造方案

### 3.1 新增公共模块 `mobile-agent/autojs/core/output-dir.js`

消除两份重复实现，并提供可单测的纯逻辑。

```javascript
"use strict";

function createOutputDirResolver(options) {
  options = options || {};
  var files = options.files;
  var scriptDir = options.scriptDir;

  function buildProbePath(dirPath) {
    return files.join(dirPath, ".write-probe-" + new Date().getTime() + "-" + Math.floor(Math.random() * 1000000));
  }

  function isWritableDir(dirPath) {
    if (!dirPath) return false;
    var filePath = buildProbePath(dirPath);
    var payload = "probe-" + new Date().getTime() + "-" + Math.random();
    try {
      // createWithDirs 失败时返回 false 而不抛异常，必须同时判断返回值
      var created = files.createWithDirs(filePath);
      if (created === false) return false;
    } catch (error) {
      return false;
    }
    var ok = false;
    try {
      files.write(filePath, payload);
      ok = String(files.read(filePath)) === String(payload);
    } catch (error2) {
      ok = false;
    }
    try { files.remove(filePath); } catch (removeError) {}
    return ok;
  }

  function resolve(config) {
    var output = config.output || {};
    if (output.fixedBaseDir) {
      return { baseDir: output.fixedBaseDir, source: "fixed", writable: isWritableDir(output.fixedBaseDir) };
    }
    var folderName = output.folderName || "datasource";
    var visibleRoots = [
      "/storage/emulated/0/燎原星火",
      "/sdcard/燎原星火",
      "/storage/emulated/0/Download/燎原星火",
      "/sdcard/Download/燎原星火",
      "/storage/emulated/0/AgriVideoCollector",
      "/sdcard/AgriVideoCollector"
    ];
    for (var i = 0; i < visibleRoots.length; i++) {
      var visibleBaseDir = files.join(visibleRoots[i], folderName);
      if (isWritableDir(visibleBaseDir)) {
        return { baseDir: visibleBaseDir, source: "visible", writable: true };
      }
    }
    var privateBaseDir = files.join(scriptDir, folderName);
    return { baseDir: privateBaseDir, source: "private", writable: isWritableDir(privateBaseDir) };
  }

  return { isWritableDir: isWritableDir, resolve: resolve };
}

module.exports = { createOutputDirResolver: createOutputDirResolver };
```

要点：

1. `createWithDirs` 用 `=== false` 判定，兼容"返回 `undefined` 但实际成功"的实现差异
2. 增加**写入后读回比对**，覆盖"创建成功但写入被拒"的情况
3. 探测文件用随机名，避免与并发实例冲突
4. 无论成败都清理探测文件
5. `resolve()` 返回 `source`，便于日志与排障区分"公共目录/私有目录"
6. 保持 ES5 语法（`var`、无箭头函数、无模板字符串），符合 Acorn 校验

### 3.2 修改 `mobile-agent/autojs/main.module.js`

- 删除第 100-130 行的 `ensureWritableDir()` 与 `resolveOutputBaseDir()`
- 在第 132 行的 `if (config.output.useProjectDir) {` 之前，通过 `localBaselineRequire` 加载新模块：

```javascript
var outputDirResolver = localBaselineRequire("core/output-dir.js").createOutputDirResolver({
  files: files,
  scriptDir: SCRIPT_DIR
});
```

- 将第 132-138 行替换为：

```javascript
if (config.output.useProjectDir) {
  var resolvedOutput = outputDirResolver.resolve(config);
  config.output.baseDir = resolvedOutput.baseDir;
  config.output.baseDirSource = resolvedOutput.source;
  config.output.baseDirWritable = resolvedOutput.writable;
  config.output.cacheDir = files.join(config.output.baseDir, "候选记录");
  config.output.screenshotDir = files.join(config.output.baseDir, "截图");
  config.output.logDir = files.join(config.output.baseDir, "运行日志");
  config.output.xmlDir = files.join(config.output.baseDir, "页面XML");
  console.info("[INFO] output_dir_resolved dir=" + resolvedOutput.baseDir +
    " source=" + resolvedOutput.source + " writable=" + resolvedOutput.writable +
    " scriptDir=" + SCRIPT_DIR);
}
```

注意：该日志必须用 `console.info`，因为此时 `logger`（第 141 行）尚未初始化。

### 3.3 修改 `mobile-agent/autojs/watchdog.js`

`loadConfig()` 内第 102-131 行同样删除两份本地实现，改为 require 同一公共模块：

```javascript
function loadConfig() {
  var config = require(files.join(SCRIPT_DIR, "config.js"));
  config.runtime = config.runtime || {};
  config.runtime.scriptDir = SCRIPT_DIR;
  config.output = config.output || {};
  var outputDirResolver = require(files.join(SCRIPT_DIR, "core/output-dir.js")).createOutputDirResolver({
    files: files,
    scriptDir: SCRIPT_DIR
  });
  if (config.output.useProjectDir) {
    var resolvedOutput = outputDirResolver.resolve(config);
    config.output.baseDir = resolvedOutput.baseDir;
    config.output.baseDirSource = resolvedOutput.source;
    config.output.cacheDir = files.join(config.output.baseDir, "候选记录");
    config.output.screenshotDir = files.join(config.output.baseDir, "截图");
    config.output.logDir = files.join(config.output.baseDir, "运行日志");
    config.output.xmlDir = files.join(config.output.baseDir, "页面XML");
  }
  return config;
}
```

`watchdog.js` 走 `require(绝对路径)`，与它现有加载 `config.js` 的方式一致，不使用 `localBaselineRequire`。

## 6. 风险与边界

1. **改动涉及基座文件**（`main.module.js`、`watchdog.js` 均在 `biz-script-baseline.json` 的 `baseFiles` 中），**不能通过业务脚本热更新下发**，必须重新构建 APK
2. **日志落私有目录后**，普通 ADB 与手机文件管理器无法直接读取（`卡点与问题记录.md` 2026-07-06 有同类记录），排障依赖应用上传到后台
3. 新增 `core/output-dir.js` 会进入 APK 基线，后续业务脚本包需使用匹配的 `baseCompatibilityId`，按现有流程由打包脚本导出配套基线
4. 若希望恢复"日志写公共目录、可直接查看"，需提升 `targetSdk` 至 30+ 并声明 `MANAGE_EXTERNAL_STORAGE`，同时适配分区存储、前台服务类型（Android 14+）、后台启动 Activity 等；**成本高，建议单独立项，不在本批次**
5. 本方案不改变 MI8 等 Android 10 设备的行为，回归风险集中在启动前的目录解析阶段
