# 代码审查风险记录

更新时间：2026-07-12

本文只记录代码审查的简要结论，按日期倒序维护；同一天的记录合并到一个日期块内，并按风险等级分层。详细问题、卡点、修复过程和验证结果维护到 `卡点与问题记录.md`、`项目记录.md` 或对应提交说明中。

## 2026-07-12

| 风险等级 | 审查结果 | 处理结果 |
|---|---|---|
| P1 | 阶段B开始落地 assignment/command 一对多后，如果只改服务逻辑而不补数据库唯一约束、事件表和旧命令兼容，后续 `PAUSE/RESUME/STOP` 仍可能丢失运行归属或被历史 commandId 回写覆盖。 | 已新增 `0021_assignment_command_timeline.sql`、schema 字段和 `device_task_assignment_events`，控制命令追加 `assignmentId + commandSequence + idempotencyKey`；回执优先按 command 归属 assignment 回写，并保留旧 commandId fallback。V2 与真实评论开关继续关闭，手机端 checkpoint v2 和评论幂等尚未实施。 |
| P0 | 第二版要求 PAUSE、RESUME、STOP 复用同一 assignment，但当前 `device_task_assignments` 只关联一个 command，现有编排还会在控制操作前废弃旧 assignment 并新建运行，无法支撑稳定暂停恢复。 | 已在两份方案中把 assignment 定义为唯一运行实例，要求 `mobile_commands` 通过 assignmentId 和 commandSequence 形成一对多历史，并补充 stateVersion、命令幂等、每设备单一非终态运行约束和旧状态迁移；代码尚未实施。 |
| P0 | 真实评论原方案只有配置布尔值和追加式动作上报，缺少可撤销审批、服务端原子预占、动作状态更新、崩溃查询和 unknown 人工处理，无法证明物理发送最多一次。 | 已在方案中拆出运行时急停和独立执行审批，定义 reserve/update/query/resolve 接口、短时发送许可、稳定 roomKey、comment slot、账号校验、跨运行额度和 BLOCKED 人工恢复；真实评论开关在实现与验收前必须保持关闭。 |
| P1 | effectiveWorkflow 示例缺少完整目标门禁字段，配置 hash 未覆盖目标/别名/绑定聚合变化，默认 3600 秒 assignment 有效期也无法覆盖 240 分钟流程；V1/V2 压制条件存在不同表述。 | 已补全 expectedAccount、required/forbidden、相似度、snapshotHash 和聚合 revision/hash 规则，增加显式过期时间校验、capability TTL 和 V1/V2 唯一选择表；V2 在数据库、接口、手机状态机和真机验收完成前保持关闭。 |
| P1 | 阶段 A 已落地后台配置、预览和门禁，但手机端 assignment 快照、checkpoint v2、评论幂等和真机验收尚未实现；如果误开启 V2 或真实评论，会把“配置准备”误当成可执行闭环。 | `feature_rollout_controls` 默认关闭 `commerce_card_workflow_v2` 和 `commerce_card_real_comment`，服务端 `activationReady=false` 阻止开启；移动端 V2 配置下发时标记 `executionEligible=false`，预览页也显示不可执行，后续必须完成运行闭环后再调整门禁。 |

## 2026-07-08

| 风险等级 | 审查结果 | 处理结果 |
|---|---|---|

| P1 | 生产 Web 镜像最终阶段依赖 `nginx:1.27-alpine`，服务端 Docker 镜像源返回 401 时会阻断部署，导致线上后台继续停留在旧版本。 | 已改为 Bun runtime 提供静态资源和 `/api`、`/health`、`/ready` 代理，并更新下载目录挂载；已补 `deploy/web-server.test.ts` 覆盖生产入口行为；已直连部署到生产并通过健康检查与前端资产验证。 |
| P1 | 任务调度页缺少暂停/恢复入口，运营只能停止任务，无法区分“临时暂停”和“结束任务”。 | 已在任务调度列表和详情中新增 `PAUSE`、`RESUME` 控制入口，并用当前安排任务/手机实际任务确定控制目标。 |
| P1 | 手机端如果不认识后台明确下发的任务类型，旧逻辑可能回退到 `video`，造成商品卡任务跑成旧刷视频流程。 | 已增加明确任务类型防回退保护：不支持的显式任务类型回执 `FAILED/unsupported_explicit_task_type`，不启动视频；后台增加任务不一致提示。 |
