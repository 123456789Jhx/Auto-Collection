## 2026-07-07

| 风险等级 | 审查结果 | 处理结果 |
|---|---|---|
| P0 | `840959a` 将直播评论从 `phaseRunner.runPhase("live", ...)` 拆到独立 `live-comment-runner` 后，没有继承原 `phase-runner` 的持续 `writeHeartbeat()` 契约；直播评论搜索、进房、持续采样超过 3 分钟时，后台会按心跳超时临时判离线。 | 已新增 `agent-heartbeat-daemon.js`，Agent 启动后通过独立后台线程持续上报心跳；`main.module.js` 创建守护实例，`collector-app` 在权限检查前启动；已补 `agent-heartbeat-daemon.test.js` 覆盖业务线程不让出时仍持续心跳。 |
| P1 | 任务完成或失败收尾后，`collector-app.finishTask()` 写入 `paused=true`，会让恢复在线后的设备继续显示暂停或不可用，干扰离线问题判断。 | 已新增任务收尾状态补丁，完成或失败后写入 `running=false`、`paused=false` 并回到 `idle`；已补 `collector-app-finish-state.test.js` 覆盖成功和失败收尾；版本提升到 `1.0.28/64`。 |
| P1 | 当前改动尚未打包安装到三台手机，生产仍运行旧包时不会体现本次修复。 | 本轮按要求只改代码；后续通过安全来源注入注册密钥后重新打包、签名校验并做三机直播评论 10 分钟以上回归。 |
| P1 | `7d6d268` 新增商品卡直播评论后，`commerceCardLiveComment.enabled` 在手机本地默认配置中为 `true`，但后台 API 和手机 `refreshRuntimeConfig()` 尚未下发或刷新该配置；普通 `live` 任务会被商品卡 runner 抢占，且线上无法通过后台关闭或调整关键词。 | 已修复：商品卡配置纳入 `p3ExtensionsConfig.commerceCardLiveComment`，后台移动端任务接口单独返回该配置，手机刷新配置时应用；手机本地默认关闭。2026-07-08 进一步拆成独立 `commerce_card_live_comment` 任务，普通 `live` 不再触发商品卡 runner。 |
| P1 | 商品卡直播评论直接调用 `douyin.sendLiveComment()` 并用 `commentMode: "agri_chatbot"` 绕过话术池校验；当前缺少独立的真实发送总开关、人工确认字段和动作记录上传。 | 已修复：新增 `executeEnabled` 和 `manualExecutionApproved` 双开关，未审批时只写 skipped 审计记录不发送；商品卡发送使用 `commentMode: "commerce_card_live"`，发送、跳过、失败统一写入直播评论动作日志并上传。 |
| P2 | 商品卡入口匹配先在整屏文本上判断商品关键词和直播信号，再点击任意直播入口，可能出现关键词和直播入口不属于同一卡片的误点；`maxCommentsPerRoom` 配置也未真正按直播间去重。 | 已部分收口：runner 按任务内直播间文本指纹记录已评论直播间，并按 `maxCommentsPerRoom` 控制发送次数；卡片容器级标题和直播标识聚合仍需真机 UI 树回归后继续加强。 |
