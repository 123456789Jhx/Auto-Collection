# 后台 UI 重构卡点与解决记录

记录日期：2026-06-26
线上地址：http://106.54.41.106:18080

## 1. 背景与来源

本次后台 UI 重构按 `docs/方案设计/后续方案/` 中的 H5 页面方案调整后台视觉，重点覆盖工作台、设备运行、任务调度、直播评论、采集记录、日志中心和配置页面。

用户回归时发现采集记录和日志中心的原有查看路径被压平：页面直接通过下拉框进入明细，缺少原来的“点击手机卡片、再点击日期卡片、再查看当天日志或采集记录”的操作链路。

## 2. 核心结论

1. H5 视觉可以改，但不能替换原有业务路径。
2. 采集记录和日志中心必须保留三层结构：手机卡片、日期卡片、当天明细。
3. 工作台、设备运行、直播评论、任务调度、配置页面继续沿用本次 H5 风格，不额外改动后端接口。
4. 本次修复已部署到生产环境，生产 `/health` 和 `/ready` 均正常。

## 3. 变更范围

| 范围 | 处理结果 |
|---|---|
| 采集记录 | 恢复手机卡片入口、日期卡片入口和当天内容列表；保留筛选、右侧记录详情和自动刷新 |
| 日志中心 | 恢复手机卡片入口、日期卡片入口和当天日志明细；保留运行动态、异常汇总、完整日志、导出和手动同步 |
| 样式 | 新增卡片按钮样式和移动端响应式，保持 H5 风格 |
| 生产部署 | 上传前端文件后重新构建 Web 镜像并重启 `auto-collection-web` |

## 4. 不变范围

1. 不改后台 API 路径和数据结构。
2. 不改手机 Agent 的采集、日志上传、命令轮询逻辑。
3. 不改直播评论真实发送策略和风控边界。
4. 不把未验证的后续方案写成当前现状。

## 5. 功能变更

| 页面 | 原问题 | 修复方式 | 验收口径 |
|---|---|---|---|
| 采集记录 | 设备和日期被改成下拉筛选，用户点击卡片路径丢失 | `RecordsPage` 改为三段视图状态：未选手机、已选手机未选日期、已选日期 | 点击手机卡片进入“采集日期”，点击日期卡片进入“内容列表” |
| 日志中心 | 默认选择第一台设备和第一天，用户看不到手机和日期入口 | `LogsPage` 不再自动选中首项，新增手机卡片和日期卡片层 | 点击手机卡片进入“日志日期”，点击日期卡片进入“运行动态/异常汇总/完整日志” |
| 样式 | 卡片作为按钮后需要保持后台视觉一致 | `styles.css` 增加卡片按钮、统计块、移动端栅格规则 | 桌面端和移动端卡片可点击且不挤压 |

## 6. 业务流程影响

原有流程恢复为：

1. 运营进入采集记录或日志中心。
2. 先按手机判断是哪台设备的数据。
3. 再按日期判断当天数据。
4. 最后查看日志明细、完整日志、采集内容和记录详情。

该流程和用户原有使用习惯一致，减少误点下拉框后直接进入明细导致的定位成本。

## 7. 前端影响

1. `RecordsPage.tsx` 保留原接口，改为状态驱动的三层渲染。
2. `LogsPage.tsx` 保留日志同步、导出、筛选和抽屉详情，只调整入口层级。
3. `styles.css` 新增 `ops-device-card` 按钮行为、`log-center-device-card`、`log-center-card-grid` 等样式。
4. 本地构建命令 `bun --filter @app/web build` 通过。

## 8. 后端影响
