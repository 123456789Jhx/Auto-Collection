## 详细记录

### 2026-06-05 AutoX 自启动守护

#### 结论

小米 MIUI 上看到 AutoX.js 出现在后台，只代表 AutoX.js 应用进程被系统拉起，不代表 `main.js` 已经运行。

本次新增 `watchdog.js` 作为手机端自启动入口：

1. AutoX.js 的定时任务事件负责启动 `watchdog.js`。
2. `watchdog.js` 每 60 秒检查 `main.js` 是否运行。
3. 如果 `main.js` 不在运行，`watchdog.js` 自动执行 `main.js`。
4. `main.js` 和 `watchdog.js` 都做防重复判断，避免多个事件触发后重复启动多个采集实例。

#### 手机端推荐设置

在 AutoX.js 里不要只给 `main.js` 设置开机事件，推荐给 `watchdog.js` 设置事件任务。

优先设置：

1. `Autox.js启动时`
2. `屏幕解锁时`
3. `开机时`

如果 AutoX.js 只能给同一个脚本设置一个事件，先选 `Autox.js启动时`。如果实测重启后仍不触发，再新增一条同样指向 `watchdog.js` 的任务，事件选 `屏幕解锁时`。

#### 小米 MIUI 设置

需要保留以下系统设置：

1. 允许 AutoX.js 自启动。
2. 电池策略设置为不限制。
3. 后台运行允许。
4. 无障碍服务保持开启。
5. 锁定后台任务卡片，避免系统清理。

MIUI 的 `开机时` 广播不一定稳定，尤其是应用还没完成加载、无障碍服务还没恢复时，所以不能把 `开机时` 当成唯一入口。

#### 打包文件

```text
dist/AgriVideoCollector-autojs-0.1.0-20260605-watchdog.zip
```

该包包含：

1. `main.js`
2. `main.module.js`
3. `watchdog.js`
4. 其他手机端模块文件

#### 验收方式

1. 手动运行 `watchdog.js` 一次。
2. 等 10 秒内确认 `main.js` 被拉起。
3. 后台设备页能看到心跳。
4. 停止 `main.js` 后，不停止 `watchdog.js`，等待 60 秒内确认 `main.js` 被重新拉起。
5. 重启手机后，如果只进入 AutoX.js 首页但没有自动运行 `main.js`，解锁屏幕后观察 60 秒内是否由 `watchdog.js` 拉起。

日常运行时不要把 `watchdog.js` 和 `main.js` 都手动循环运行。正常做法是让 `watchdog.js` 常驻，由它负责拉起 `main.js`。

### 2026-06-05 手机 Agent 接入与认证

#### 本次目的

把手机脚本的常驻 Agent、设备 token、心跳、命令拉取和后台设备注册统一起来，避免启动逻辑和采集逻辑混在一起。

#### 核心结论

1. Agent 常驻模块负责心跳、拉配置、拉命令、注册设备 token。
2. 任务执行模块只在后台启动命令或 `autoStart=true` 时执行视频/直播采集。
3. 停止任务只停止采集，不退出 Agent。
4. 设备 token 采用独立绑定，不再依赖 `deviceId` 的弱校验。

#### 启动流程

1. AutoX.js 定时任务启动 `main.js`。
2. 创建悬浮窗。
3. 注册或校验设备 token。
4. 上报 Agent 启动日志。
5. 拉取 `/mobile/tasks/current` 配置。
6. 上报 idle 心跳。
7. 如果 `autoStart=true`，直接进入任务执行。
8. 如果 `autoStart=false`，停留待命。

#### 后台字段语义

| 字段 | 语义 |
|---|---|
| 当前状态 | `idle` / `running` / `offline` |
| 当前任务 | `视频` / `直播` / `未执行任务` |
| 最近心跳 | 只显示时间，不再显示“多少分钟前” |
| 最近 IP | 仅辅助排查来源 |

#### Token 方案

1. 手机首次启动生成 64 位随机 token。
2. token 只存本地，不明文保存到后台可见字段。
3. 后台通过 `deviceId` 反查绑定 token，再校验请求签名。
4. 普通业务请求不再明文携带 token。
5. 后续可加 `timestamp`、`nonce`、HMAC 和 HTTPS。

#### 当前不变范围

1. 不改视频/直播主链路。
2. 不把停止任务等同于退出 Agent。
3. 不做远程脚本替换和热更新。
4. 不把 IP 当作唯一身份。

#### 已调整方向

1. 手机端启动器必须优先读取 `/sdcard/燎原星火/`。
2. 手机端公共更新能力需要负责下载 ZIP、校验 SHA256、解压、覆盖脚本和上报事件。
3. 主流程和守护脚本都应复用同一套更新能力。
4. 更新验收必须看到完整事件链：

```text
CHECKED -> DOWNLOADED -> VERIFIED -> APPLIED
```
