# 验收口径

## 验收目标

当前验收只看代码里真实存在的能力，不把历史方案当成现状。

## 功能验收

| 模块 | 验收口径 |
|---|---|
| 线上后台 | 能打开后台页面 |
| 设备列表 | 能展示设备、在线状态、最近心跳和任务状态 |
| 日志页面 | 能查看结构化日志和日志文件 |
| 采集记录 | 能查看手机脚本上报的记录 |
| 任务配置 | 能保存并下发设备任务配置 |
| 设备认证 | 未注册设备访问普通移动端接口返回 401 |
| 设备注册 | 新设备能按 token 注册 |
| 直播评论 | 能保存画像、配置、命令和动作记录 |
| 版本管理 | 能查询 Agent 版本和更新事件 |
| 数据清理 | 运行数据表清理后可复查为空 |

## 技术验收

1. `bun --filter @app/api typecheck` 通过。
2. `bun --filter @app/api build` 通过。
3. 生产 Docker Compose 中 API、Web、PostgreSQL、Redis 正常运行。
4. `http://106.54.41.106:18080/ready` 返回 ready。

## 证据要求

1. `docs/项目开发/项目说明.md` 说明当前目标和边界。
2. `docs/项目开发/部署说明.md` 说明本地开发、生产部署和清理方式。
3. `docs/方案设计/方案设计索引.md` 只保留当前有效方案和后续方案索引。
4. `docs/项目开发/项目现状.md` 记录当前完成度和边界。
5. `docs/项目开发/卡点与问题记录.md` 记录未闭环问题和风险。

## 不通过条件

1. 旧设备身份继续自动生成脏数据。
2. 运行数据清理后仍有历史残留。
3. docs 里仍把未落地方案写成当前现状。
4. 直播评论真实发送没有明确开关、限制和审计记录。
