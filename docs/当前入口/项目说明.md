## 2. 项目目标

Auto Collection 当前用于小范围 Android 手机运行农业内容采集脚本，并把设备状态、心跳、运行日志、采集记录和控制命令集中到后台监控。

当前阶段重点不是完整内容生产平台，而是先解决三件事：

1. 手机脚本运行状态可见。
2. 采集记录、日志和异常原因可追踪。
3. 分散运行的手机可以通过公网后台拉取配置和命令。

## 3. 当前主链路

1. 手机端 AutoX.js 脚本检查权限并进入待命。
2. 脚本浏览公开可见的农业相关视频和直播内容。
3. 脚本通过屏幕文本、OCR、无障碍控件和关键词判断候选内容。
4. 命中后保存标题、作者、可见指标、评论、屏幕文本和运行上下文。
5. 脚本上报采集记录、心跳、运行日志和停止原因。
6. 后台展示设备、任务、日志、采集记录和配置。
7. 后台下发命令后，由手机 Agent 主动拉取并执行。

## 4. 当前成果

1. 手机端脚本已经模块化，可打包为 APK，提供启动、停止、守护、权限检查等入口。
2. 后台 API 已支持设备注册、心跳、运行日志、完整日志文件、采集记录和命令拉取。
3. 后台 Web 已提供设备、采集记录、日志、任务配置、直播评论等页面。
4. 生产环境已通过 Docker Compose 部署到 `106.54.41.106:18080`。
5. 设备认证已改为令牌注册模式，普通上报接口不再自动创建设备。
6. 直播评论已具备指定直播间配置、手机 Agent 进入目标直播间、计划记录和授权真实发送的代码链路。

## 5. 当前不做

1. 不接入抖音官方 API。
2. 不绕过验证码、登录校验或平台风控。
3. 不采集非公开内容。
4. 不批量下载完整视频。
5. 不承诺平台标签、推荐或账号权重结果，只记录脚本实际运行证据。
6. 直播间评论发送、点赞、关注等真实互动动作不属于默认启用能力，必须单独评审、审批和验收。

## 6. 技术结构

| 模块 | 技术 | 说明 |
|---|---|---|
| 手机端 | AutoX.js / JavaScript | Android 自动化脚本与 APK 包装 |
| 后台 API | Bun + Hono | 接收移动端上报和后台管理请求 |
| 后台 Web | React 19 + Vite + Ant Design | 管理后台页面 |
| 数据库 | PostgreSQL + Drizzle ORM | 设备、任务、日志、心跳、采集记录 |
| 缓存 | Redis | 预留后台运行依赖 |
| 部署 | Docker Compose | 生产环境 API、Web、Postgres、Redis |

## 8. 成功指标

1. 负责人能打开线上后台查看设备、日志和采集记录。
2. 新版 APK 能使用唯一设备 ID 注册，不再共用 `android_001`。
3. 未注册设备访问移动端普通接口时返回 401，不写入脏数据。
4. 默认 `android_001` 旧脚本注册返回 `DEVICE_ID_NOT_UNIQUE`，不写入设备表。
5. 清理生产库后，设备、日志、心跳、采集记录等运行数据表可复查为 0。
